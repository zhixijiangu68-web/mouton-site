CVSS の 10.0 は、悪用されるかどうかを表さない。直す順番は、KEV と「外から届くか」で決める

CVE の番号と記録、CVSS v3.1・v4.0、EPSS、CISA の KEV と BOD 22-01・26-04、JVN と IPA、月例パッチを、公式の文書とカタログのデータで確かめた

約12分更新日 2026年11月13日

脆弱性の情報は、どの弱点か（CVE）、起きたときにどれほど重いか（CVSS）、悪用されそうか（EPSS）、実際に悪用されたか（KEV）の四つに分けて読むと整理できる。直す順番は、CVSS の点数の高さより先に、KEV に載ったかと、その機器がインターネットから届くかで決める。IT のニュースに出る「CISA が KEV に○件追加」「月例パッチ」の読み方として、ファイアウォールの記事のつなぎ目の機器の話から広げた。

CVE は、一つの弱点に付く番号と、その記録

CVE は、公開された脆弱性に一つずつ付く番号で、番号ごとに「CVE レコード」という記録がある。番号の形は「CVE-年-数字」で、数字は4桁から19桁まで、年は見つかった年か公開した年を表す[1]。KEV のカタログ（2026年11月10日版）の1,779件にも、数字が6桁と7桁の番号が33件ある[2]。

番号を割り当てるのは、CNA（CVE Numbering Authority）と呼ばれる組織だ。CNA の欄には、製品・版・問題の種類・説明・参照を入れる決まりになっている。記録の状態は、公開（PUBLISHED）か取り下げ（REJECTED）のどちらかになる[1]。Palo Alto Networks のファイアウォールの OS「PAN-OS」の CVE-2024-3400 は、作った会社自身が CNA として2024年4月5日に番号を予約し、4月12日に公開した[3]。

公式の一覧「CVE List」は、GitHub の cvelistV5 に JSON のファイルとして置かれ、約7分ごとに更新される[4]。記録には CNA の欄のほかに、ほかの組織が情報を足す ADP の欄がある。CISA の ADP は、SSVC の判断材料と KEV に載った日付を足し、CNA が書いていない CVSS や CWE（弱点の種類の番号）を補うことがある。CNA の欄の値は書き換えない[4][5]。

CVSS のベースの値は、深刻さで、悪用の起こりやすさではない

CVSS は、脆弱性の性質を項目ごとに評価し、0.0〜10.0 の点数と項目の並び（ベクトル）で表す決まりで、FIRST が管理している[6]。CVE-2024-3400 の記録には、v3.1 のベクトル CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H と、ベースの値 10.0（CRITICAL）が入っている[3]。ネットワークから届き（AV:N）、条件は難しくなく（AC:L）、権限も利用者の操作も要らず（PR:N・UI:N）、影響が脆弱な部品の外へ及び（S:C）、機密性・完全性・可用性への影響がどれも高い（C:H・I:H・A:H）、という読み方になる。

ベースの値は、時間や使う環境で変わらない、脆弱性そのものの性質を表す。v3.1 の利用者の手引きは「CVSS が測るのは深刻さで、リスクではない」という節を置き、リスクを評価するなら、外から届くかや脅威の状況のような CVSS の外の要素も考えるよう書いている[7]。

2023年11月1日に公開された v4.0 は、項目をベース・脅威・環境・補足の四つのまとまりに分けた[6]。脅威のまとまりの「Exploit Maturity（悪用の成熟度）」は、悪用の情報がないときの既定値を「攻撃されている（Attacked）」と同じに扱い、最悪の場合を前提に点数を出す[6]。v4.0 は、どのまとまりで出した点数かを CVSS-B（ベースだけ）・CVSS-BT・CVSS-BE・CVSS-BTE の名前で示すよう求め、製品の会社や NVD が出すのはふつう CVSS-B だと書いている[6]。脅威と環境の値は、使う側が自分の環境に合わせて足すものとされている。

点数の呼び方は、0.1〜3.9 が Low、4.0〜6.9 が Medium、7.0〜8.9 が High、9.0〜10.0 が Critical だ[6]。

EPSS と SSVC は、悪用の見込みと状況を足す

EPSS は、FIRST が出している、CVE ごとに「これから30日のうちに悪用の動きが観測される確率」を見積もる仕組みだ。値は 0〜1 の確率と、ほかの CVE と比べた順位（パーセンタイル）で表され、毎日更新される[8]。EPSS は、最悪の場合を前提にした CVSS-B に、起こりやすさの見積もりを足す。見積もりなので、値が低いことは、悪用されないことの約束ではない。

CISA が CVE レコードに足す SSVC の判断材料は、三つの値でできている。悪用の状況（Exploitation：none・poc・active）、偵察から悪用までを自動にできるか（Automatable：yes・no）、悪用されたときに攻撃者が得る支配の大きさ（Technical Impact：partial・total）だ[5]。CVE-2024-3400 には active・yes・total が入っている[3]。

KEV は、実際に悪用が確かめられた脆弱性の一覧

KEV（Known Exploited Vulnerabilities）は、CISA が出している、実際に悪用が確かめられた脆弱性のカタログだ。載せる条件は、CVE の番号があること、悪用されている確かな証拠があること、直し方か避け方がはっきりしていることの三つで、悪用には試みも含む。スキャンや研究、PoC（動くことを示すだけのコード）の公開だけでは載らない[9]。

KEV は、2021年11月3日に、米国の連邦の行政機関に向けた拘束力のある指令 BOD 22-01 とともに始まった。BOD 22-01 は、カタログに載った脆弱性を期限までに直すよう機関に求め、最初の期限を、2021年以降の番号は2週間、それより前の番号は6か月とした[10]。カタログでも、2021年11月3日に載った287件の期限は、2021年以降の番号の多くが14日、それより前の番号のほぼすべてが181日だ。2023〜2025年に足された618件では、578件が21日だった[2]。

2026年6月からは、BOD 26-04「Prioritizing Security Updates Based on Risk」が KEV の根拠になっている[11][12]。CISA の資料は、BOD 26-04 を、KEV の上に立って、リスクの高い脆弱性を先に直し、低いものは後に回せるようにする指令と説明し、直す期限は、KEV に載った時と、機関が自分の機器で見つけた時の早いほうから数えるとしている[12]。カタログでは、2026年6月11日から11月10日までに足された162件のうち、126件が3日、36件が14日の期限だった[2]。指令が縛るのは米国の連邦の機関だけで、ほかの組織には、内容を読むことを勧めている[12]。

KEV のカタログは、12の項目で書かれている

KEV は JSON と CSV で配られ、GitHub の cisagov/kev-data に、項目の意味を決めたスキーマと一緒に置かれている[2]。全体には、版（catalogVersion）・出した日時（dateReleased）・件数（count）が付き、2026年11月10日の版（2026.11.10）は1,779件だった。一件ごとの項目は次の12個だ[2]。

  • cveID・vendorProject・product・vulnerabilityName・shortDescription：番号、作った会社、製品、名前、説明
  • dateAdded：カタログに足された日。ニュースの「○件追加」は、この日付が同じ件数にあたる。2026年11月10日は6件、11月9日は4件だった
  • requiredAction・dueDate：求める対応と、連邦の機関の期限。2026年6月11日からの162件にはどれも、機器ごとにインターネットへの出方を評価するよう書かれている
  • knownRansomwareCampaignUse：ランサムウェアの攻撃に使われたと分かっていれば Known、確かめられていなければ Unknown。1,779件のうち361件が Known
  • forensicTriage：BOD 26-04 のもとで、フォレンジックの確認（すでに入られていないかの調べ）を求めるなら Yes。103件が Yes
  • notes・cwes：製品の会社の告知や NVD へのリンクと、弱点の種類（CWE）。CWE-20（入力の確かめの不足）が119件、CWE-78（OS コマンドの注入）が115件と多い

日本では、JVN と IPA の緊急対策情報を見る

日本の製品やサイトの脆弱性は、2004年7月に始まった「情報セキュリティ早期警戒パートナーシップ」の流れで扱われる。IPA が届け出を受け付け、JPCERT/CC が製品の会社との調整をし、修正ができると、脆弱性と対策の情報が JVN（Japan Vulnerability Notes）で公表される[13]。弱点を見つけたときは、公開せずに、作った会社か IPA の窓口に知らせる。KEV の notes に JVN の頁が並ぶ項目もあり、2026年11月10日に足された CVE-2026-111793 には JVNVU93403064 が載っている[2]。

IPA は、早めの対策が要るものを「重要なセキュリティ情報」として出す。2026年10月の「Microsoft 製品の脆弱性対策について」は、10月14日（日本時間）に公表された更新のうち、Windows のシェルの CVE-2026-96951 を、Microsoft が悪用を確認したものとして挙げ、至急の更新を呼びかけている[14]。同じ番号は、米国の10月13日に KEV に足され、期限は3日、forensicTriage は Yes だった[2]。

月例パッチは、決まった日にまとめて出る

Microsoft のセキュリティ更新は、ふつう毎月第2火曜日（米国の日付）に出る。日本の日付では翌日の水曜日になる。Microsoft の手引きは、この日に合わせて本番の前に数日の確かめの期間を置く例を示し、緊急の修正を予定の外で入れる手順も決めておくよう勧めている[15]。

月例パッチの日には、悪用が確かめられたものが KEV に足されることが多い。2026年は、8月11日・9月8日・10月13日・11月10日の第2火曜日に、それぞれ Microsoft の脆弱性が KEV に入った[2]。先に見るのは、月例パッチの件数より、その中で悪用が確かめられたものだ。

直す順番は、悪用の事実と、外から届くかで決める

先に直すのは、KEV に載ったもののうち、インターネットから直接届く機器だ。VPN の入口やファイアウォール、メールの中継の機器は、外と内のつなぎ目に置かれ、インターネットのどこからでも接続を試せる。2026年に KEV に足された項目にも、SonicWall の SSL VPN、Ivanti Connect Secure、Cisco の Secure Firewall ASA と FTD、Palo Alto Networks の PAN-OS、Citrix NetScaler、Check Point の Security Gateway、Barracuda のメールのゲートウェイが並ぶ[2]。

CVE-2024-3400 は、PAN-OS の GlobalProtect（VPN の機能）にあり、認証なしでファイアウォールの上で root の権限のコマンドを動かせる弱点だった。CVE の公開と同じ2024年4月12日に KEV に載り、期限は7日、ランサムウェアへの利用は Known になっている[2][3]。修正はすでに出ている。

管理画面も同じだ。CISA の BOD 23-02 は、連邦の機関に、インターネットから届く管理画面を、見つけてから14日のうちに外から外すか、別の仕組みで接続を制限するよう求めている[12]。

KEV にないものは、CVSS のベースの値に、自分の環境の事情を足して並べる。インターネットから届くか、その機器がどれほど大切か、EPSS の値、SSVC の Automatable と Technical Impact だ[5][6][8]。どの順番でも、自分が何の製品のどの版を使っているかの一覧がなければ、KEV や告知と照らし合わせられない。

直したあとは、直す前に入られていないかを確かめる。KEV の forensicTriage が Yes の項目は、BOD 26-04 がこの確認を求めているものだ[2]。その機器のログを SIEM に集めていれば、告知に書かれた時期までさかのぼって、見慣れない接続や管理者の操作を探せる（道具は SIEM のまわりの記事）。

自分の環境で確かめる

KEV と CVE レコードは公開のデータなので、自分のパソコンで読める。試すのは自分の機械と、許された演習の環境だけにし、脆弱性を他人の機器で試すことはしない。

curl -sO https://raw.githubusercontent.com/cisagov/kev-data/main/known_exploited_vulnerabilities.json でカタログを取り、jq -r '.catalogVersion, .count' known_exploited_vulnerabilities.json を実行すると、版と件数が出る。2026年11月10日の版では 2026.11.10 と 1779 だった[2]。

jq -r '.vulnerabilities[] | select(.dateAdded >= "2026-11-09") | [.dateAdded, .cveID, .product, .dueDate] | @tsv' known_exploited_vulnerabilities.json で、11月9日からの追加が1件1行で並ぶ。select の条件を vendorProject（作った会社）に変えれば、自分の使う製品の項目だけが残る。

CVE レコードは、cvelistV5 の cves/2024/3xxx/CVE-2024-3400.json のように、年と番号の上の桁で分けたフォルダーに置かれている。jq '.containers.cna.metrics' で CNA の CVSS が、jq '.containers.adp[].metrics' で CISA が足した SSVC と KEV の日付が出る[3][5]。
