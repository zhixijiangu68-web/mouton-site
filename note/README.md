# note事業部

ムートンの note を、5 人の AI 社員（Claude Code のサブエージェント）で回すための部署。

## 社員

| 担当 | エージェント | やること | 成果物 |
|---|---|---|---|
| リサーチ | `note-researcher` | 研究・公的機関などの情報を調べ、材料と参考文献をまとめる | `01-research.md` |
| 記事作成 | `note-writer` | ムートンの文体で本文を書く | `02-draft.md` |
| タイトル | `note-titler` | タイトル案・見出し画像の文言・ハッシュタグ | `03-titles.md` |
| 品質チェック | `note-editor` | 事実・出典・文体・ルールを確認し、完成稿を作る | `04-review.md`, `article.md` |
| SNS集客 | `note-sns` | X・Threads・Instagram の告知文と投稿計画 | `05-sns.md` |

定義は `.claude/agents/note-*.md`、全体の進め方は `.claude/skills/note/SKILL.md`。

## 使い方

Claude Code でこのリポジトリを開いて：

```
/note 朝の散歩が気分を変える理由
```

文体や読者を指定したいとき：

```
/note 転職の面接で緊張しない方法（です・ます調、20代の初めての転職）
```

1 人だけ動かすこともできる（例：「note-titler で note/morning-walk/ のタイトルを考え直して」）。

## 流れ

```
テーマ → リサーチ → 記事作成 → タイトル → 品質チェック → SNS集客
                        ↑            │
                        └─ 差し戻し ─┘（最大2回）
```

## サイトの哲学記事を note に載せる分（2026-10-17）

`/note` で新しく書く記事とは別に、サイトの記事を**本文そのまま** note に載せる形にしたものがある。アカウントの設定（名前・ID・自己紹介・ヘッダー・アイコン）と公開の順番は `profile/profile.md`。

| 場所 | 中身 |
|---|---|
| `profile/` | ヘッダー画像（`header.jpg`）・アイコン（`icon.png`）・名前・自己紹介 |
| `start/` | 「はじめての方へ」（ブランドの考え方と、3人の哲学者への入口） |
| `free-kierkegaard/`・`free-nietzsche/`・`free-spinoza/` | 無料の入門記事（`article.md`・`03-titles.md`） |
| `paid-kierkegaard/`・`paid-nietzsche/`・`paid-spinoza/` | 有料記事の出品シート（`listing.md`）と、無料の冒頭（`free-part.md`）。**有料の続きの全文は公開リポジトリに入れない**（オーナーの手元の原稿を貼る）。16 から派生した有料記事 `paid-choice/` は、下の「無料の問いから派生した有料記事」 |
| `free-habit/` | 無料の記事「意志力に頼らない習慣設計」（オーナーの原稿、PDF 24ページ）。`review.md` に、原稿から変えたところとまだ確かめていないこと。全文は公開リポジトリに入れてよい（無料のため） |

- 本文はサイトの記事から写した。サイトの記事を直したら、note の版を直すかどうかを決める（直さないと古くなる）。
- 末尾の `{PAID_URL}` ・ `{URL_FREE_*}` ・ `{URL_PAID_*}` は、公開した note の URL に置き換えてから貼る。
- note で売るかどうか（A／B／C）の整理は `docs/note-monetization-20261017.md`。

オーナーの依頼で、無料で読める記事30本を書いた。設計（不安・導く先・洞察・土台）は `series-30/plan.md`。

| 場所 | 中身 |
|---|---|
| `series-30/plan.md` | シリーズの柱、5つの道、30本の設計、公開の順番（第1陣の10本を一斉に）、確認すること |
| `series-30/00-index/` | 30本の入口になる目次記事（プロフィールの最初に置く） |
| `series-30/NN-<slug>/` | 1本ずつ。`article.md`（note に貼る本文）、`03-titles.md`（題・見出し画像の文言・説明・タグ・事実の確認）、`cover.jpg`（見出し画像 1280×670） |

- 見出し画像は `cd scripts/og && npm install && node note-cover.mjs` で作り直せる（`03-titles.md` の「見出し画像の文言」から。絵はサイトの月夜の絵）。
- 末尾の `{URL_S30_NN}`・`{PAID_URL_*}`・`{URL_FREE_*}` は、公開した note の URL に置き換えてから貼る。
- **記事の形は「気づかせる」**（2026-10-17、オーナー。`BRAND.md`）：ワーク（今日の一歩・書き込みの空欄）とやり方は置かない。場面 → 本質 →「このまま続くと」→「周りを見ると」→ 問いで終わる。本文は千字前後。見本の 01・03・09 はオーナーが公開し、02・04・10 も書き直した。ほかは書き直しの下書き（Claude の確認前）か、まだ前の形（どれがどれかは `series-30/plan.md` の各記事の「状態」）。入門3本は、書き込みの節とやり方を外した。習慣設計（66日のワーク）は、無料の20本からいったん外した。
- 本文に実体験として書いた場面はない（仮の場面と、読み方・考え方だけ）。**オーナーの経験は載せない**（2026-10-17、オーナー：「私の経験を載せると、偶像崇拝が薄れる」）。
- **無料記事20本で世界観を伝え、信頼を得てから有料3本を出す**（2026-10-17、オーナー）。1日目は世界観の4本（はじめての方へ・入門3本）、2〜4日目は30本のうち16本と目次。それまで、無料記事から有料記事への案内は外し、外した部分は各フォルダの `paid-section.md` に残してある。出し方は `series-30/plan.md` の「公開の順番」。

## note に貼るとき（Markdown の扱い）

`article.md` は Markdown で書いてある（note 用の書き方：表と HTML は使わない、URL は1行に1つ）。note のエディタとの対応：

- 1行目の `# タイトル` は本文に入れず、タイトルの欄に貼る。本文の見出しは `##`（大見出し）と `###`（小見出し）だけ。
- note の公式ヘルプ「Markdownショートカット」に書いてあるのは、**打ち込んだときの変換**（`## `＋スペースで大見出し、`### `＋スペースで小見出し、`> ` で引用、`---` で区切り線、```` ``` ```` でコード）。
- **貼り付けたときの変換**は、公式ヘルプでは確かめられなかった。ブログには「今のエディタは、貼った Markdown を見出し・太字・箇条書きに変える」という説明があるが、この環境からは試せない。
- だから、**貼るときは公開キットの「本文をコピー」を使う**。書式つきの形（HTML）と Markdown の形を一度にクリップボードに入れるので、note が HTML を読めば書式が、テキストしか読まなければ Markdown が入る。どちらでも、見出し・太字・引用・箇条書き・リンクは貼るだけで入る（ブラウザでクリップボードの中身を確かめた。note の画面ではこの環境から試せない）。
- 万一、見出しが `##` のまま出たら、貼った本文を消して「書式だけでコピー」（HTML だけを入れる）で貼り直す。

## コピーの決まり（2026-10-18、オーナー：「美しさよりもコピーが大事だ」）

考え方は `BRAND.md`「コピーを先に」。場所ごとの書き方・前 → 後の実例・公開前の5分チェックは `docs/note-copywriting-guide.pdf`（2026-10-18、オーナーの依頼でまとめた）。note では次のように使う。

- **見出し画像の大きな文字は、題をくり返さない**（題は画像の下に出る）。記事の中の場面・問い・哲学者の言葉など、題にない一行を置く。意味の切れ目で改行すると文字が大きくなる（30本・次の30本は `03-titles.md` の「大：」に「／」、入門と有料は `scripts/og/note-cover.mjs` の表に `\n`）。検査（`scripts/note-kit/lint_*.py`）が、題のくり返しに近いと注意を出す。
- **有料ラインの直前の案内は、貼る**（買うかどうかを決める直前に読まれる）。章の名前ではなく、読むと何が分かるかで書く。全文の分数も書く。
- **無料の記事から有料への案内**は、題・副題に、悩みの場面と読むと何が分かるかの一行（出品シートの「無料の記事からの案内（一行）」）を足す。
- 「読んだあとに」は、結果の約束（「〜できる」「〜ずにすむ」）ではなく、手に入る考え方・方法・問いで書く。
- 強くするのは、具体さと読者の言葉。あおり・誇張・押しつけはしない。

## 公開キット（コピー用のページ）

https://claude.ai/artifact/Gs3AeLZ44JgAd9faz77DAR （claude.ai のアーティファクト。オーナーだけが開ける。作り直し方と記事の検査は `scripts/note-kit/README.md`）

- はじめにアカウントの設定（名前・ID・自己紹介・リンクのコピー、アイコン・ヘッダーの保存）。そのあと、無料の20本と目次を日ごとに、公開する順に並べ、そのあとに有料（3本と、16 から派生した「選べない」。まだ出さない）、最後に次の30本。タイトル・本文・ハッシュタグ・記事の説明のコピーと、見出し画像の保存ができる。
- **公開した記事の URL は、公開したらすぐカードに入れる**（note の記事の URL か、`n` から始まる記事の番号）。入れていない記事へは、ほかの記事の「次に読む」・目次・有料記事への案内からリンクできない（2026-10-18 時点で、公開ずみ12本の URL がまだ入っていない。キットの「残っていること」のいちばん上に出る）。
- 下書きの「公開時の URL」を入れると、本文の `{URL_...}` が埋まる。目次は、URL を入れた記事だけを「いま読める」に載せて組み立てる。入れた URL と「下書き」「公開」の印はページに保存され、Claude が読み取れる（リポジトリの `{URL_...}` を埋めるとき、サイトに「note で購入」を足すときに使う）。
- 有料3本は、無料の冒頭と設定だけ。有料の続きは、オーナーの手元の原稿から貼る。「おわりに」のあとに、カードの「最後の結びをコピー」で結びを足す（満足して閉じず、次があることを暗示する。2026-10-18、オーナー。文面は各 `listing.md` の「最後に足す結び」）。「選べない」（`paid-choice/`）は、カードの「有料の続きをコピー」で続きも貼れる（キットは非公開のページなので、全文を置いている）。
- **無料の記事から有料記事への案内**（2026-10-18、オーナー：「無料の記事に有料記事のリンクを貼りたい」）：有料記事のカードに公開した URL を入れると、案内先の無料記事の「本文をコピー」に、その有料記事への案内が入る（最後の問いのあと、「参考」の前。入門・はじめての方へ・目次は `paid-section.md` の場所）。公開ずみの無料記事には、カードの「有料記事への案内をコピー」でコピーし、note で「編集」して貼る。どの無料記事からどの有料記事へ案内するかは `paid-links.md`。
- 末尾の「次に読む」は、行き先の記事の URL を入れたときだけ、コピーした本文に入る（行き先がまだ出ていない記事に「{URL 未入力}」の文字が残らないように）。行き先を出したら、その記事を note で編集して、カードの「「次に読む」をコピー」で末尾に足す。
- Claude が書き直しを確かめていない記事は「確認中」と出て、本文をコピーできない。
- 有料を出す日や、有料の2本目（`paid-perfect/`、案）を足すときは、Claude に「公開キットを更新して」と頼む。

## 公開するとき（人がやること）

1. `04-review.md` の「人が確認すべきこと」を見る
2. `article.md` を note のエディタに貼る（上の「note に貼るとき」）
3. 見出し画像・ハッシュタグ・記事の説明を `03-titles.md` から設定して公開
4. 公開した URL を `05-sns.md` の `{URL}` に入れて投稿する

AI は note や SNS に投稿しない。公開の判断はムートン本人がする。
