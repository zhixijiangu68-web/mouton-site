- 定期実行の指示文（prompt）は、発火先の常設セッション自身からしか変えられない。変えたいときは、新しい定期実行を作って古いものを停止する（2026-10-18 にそうした。停止した旧版は名前に「（旧・停止）」が付いている。消してよい）

## 部長に共通の決まり（毎回）

1. 準備：`cd /home/user/mouton-site && git fetch -q origin && git checkout -q main && git pull -q origin main`。GitHub の道具は ToolSearch で `select:mcp__github__list_pull_requests,mcp__github__list_issues,mcp__github__issue_read,mcp__github__add_issue_comment,mcp__github__create_pull_request,mcp__github__pull_request_read` を読み込む

3. 選ぶ：オーナーの指示 → 止まっているもの → 標準の仕事の順。上限に当たっていたら、作らずに点検と報告だけ。何も無ければ、返答に1行書いて終える（コメントも PR もしない）
4. 振る：社員（サブエージェント）に、テーマ・対象ファイル・読むべき決まり・納品の形を書いて依頼する。社員は前の会話を知らない。1回の実行で社員を呼ぶのは合計4回まで、全体で45分以内
5. 確かめる：社員の成果を自分で読み、`npm test`（サイトの変更）か `node scripts/x-check.mjs`（X）を実行する。通らないものは納品しない
6. 納品：ブランチ `claude/<部署>-<YYYY-MM-DD>`（同じ日に open の PR があれば、そのブランチに足す）にコミット（メッセージは日本語。末尾に `Co-Authored-By: Claude <noreply@anthropic.com>`）、`git push -u origin <ブランチ>`、main 向けの PR（本文の末尾に `🤖 Generated with [Claude Code](https://claude.com/claude-code)`）。本文の言葉を変える提案は draft PR。部署の Issue に PR のリンクと要点を1コメント（末尾に `---` の行と `_Generated by [Claude Code](https://claude.ai/code)_`）
7. 作業ログ：`promo/log/<YYYY-MM-DD>.md`（日本時間）に1項目（形は `promo/log/README.md`）を同じ PR に含める
8. 返答：要点を5行以内（何をしたか、納品先、何もしなかったならその理由）

禁止（全部署）：X・note・SNS への投稿、main への直接 push、販売の開始（`checkoutUrl`・`fulfillmentReady`・`legalUrl`）・価格・特定商取引法の表記・鍵・個人情報の変更、ルール（`rules.md`・`CLAUDE.md`・`BRAND.md`・この文書）の変更（提案まで）、英語版（`src/en/`）、ページを消す・URL を変える、演出を足す、アーカイブの記事から新しい投稿・記事を作る、○×クイズ・投票・ワーク・命令・あおり、有料記事の値段・購入の案内（販売が始まるまで）。
