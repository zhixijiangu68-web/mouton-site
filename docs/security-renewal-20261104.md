## 書くときの決まり

1. **試すのは、自分の環境と、許可された演習（CTF・学習用の演習）の中だけ**。他人のシステムやサービスには、許可なく試さない（不正アクセス禁止法）。記事の中でも、読む人にそう書く
2. **まだ修正されていない脆弱性の悪用の手順は書かない**。脆弱性は、仕組み・見つけ方（検知）・防ぎ方を中心に書く。公開された修正・回避策を先に書く
3. 攻撃の道具やコードを載せるときは、演習の環境で使う形にとどめ、実在の他人の環境を狙う形（実在のドメイン・IP・認証情報）を書かない
4. 事実・数字・日付は、公式の発表（CISA・JPCERT/CC・IPA・メーカーの告知など）と一次資料で確かめ、出典を付ける。確かめられないことは書かない
5. 弱点を見つけたら、公開せず、作った会社や窓口（日本なら IPA の届出の窓口）に知らせる
6. 文章は日本語、一人称は「僕」。専門家ではなく、勉強している一人として書く。言い切れないことは言い切らない
7. 長さ・記事の型（判定表など）は、まだ決めていない（オーナーが決める）。2026-10-22 の「本文1万〜2万字」（`scripts/check-current-pages.mjs`）は、今の記事に入れたときに効く
