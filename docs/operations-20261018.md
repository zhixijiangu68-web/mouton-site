# 3つの運用（X・note・サイト）の回し方（2026-10-18）

**目的は一つ**：トップ → 悩みから選ぶ有料の3本（PDF）→ 第三者の実購入1件。X・note・サイトの運用は、すべてこの流れに人を連れてくるためにある。
販売が始まるまで（Worker の確認 → Stripe の3商品 → PDF を R2 へ → 特定商取引法の表記。`docs/philosophy-sales-20261016.md`）は、X と note のリンク先は**無料の入門記事・3つの姿勢の記事・ムートンについて・トップ**。販売が始まったら、販売ページへの案内を順番表と note に足す。

決まりの出どころ：`BRAND.md`（世界観）、`docs/content-quality.md`（文章の品質基準。X の投稿と note にも同じ物差し）、`.claude/skills/x-staff/`（X）、`.claude/skills/note/`・`note/README.md`（note）、`.github/ai-shain.md`（AI社員）。この文書は「誰が・いつ・何を・どこに」だけを書く。

## 役割

| 運用 | 役割 | 作るのは | 出すのは | 置き場所 |
|---|---|---|---|---|
| X（@kodoku__alone） | 見つけてもらう。毎日の「点」 | AI（x-staff の5担当） | オーナー（投稿・リプライ・返信） | `promo/x-posts.md`（投稿文と順番表）、`promo/x-analysis/` |
| note | サイトの外から、長い文章で入口へ | AI（note事業部の5担当） | オーナー（公開） | `note/<slug>/article.md`・`05-sns.md` |
| サイト | 商品と入口を磨く（記事・点検・直し） | AI社員（ai.shain。Issue → draft PR） | オーナー（確認してマージ） | GitHub の Issue と PR |

AI は X・note に投稿しない。数字（X のアナリティクス・GA4・Stripe）の取得もオーナー。AI はスクショか CSV をもらって読む。

## 毎日（オーナー、15分）

1. **朝**：Claude Code で「今日の3本」と言う（または `npm run x:today`）。朝・昼・夜の本文と、リプライの1行が出る。投稿したら `promo/x-posts.md` の順番表に ✓
2. **すきま**：ほかの人の投稿へのリプライ（`promo/x-replies-out.md` の型。リンクは貼らない）
3. **返信が来たら**：「このリプに返信案を」＋本文やスクショ → x-staff ⑤ が返信案

## 毎週

| 曜日 | 何を | 誰が |

| 水 | note を公開（`04-review.md` の「人が確認すべきこと」を見てから）。`05-sns.md` の告知文を、その日の X の1枠と差し替える | オーナー |

## 毎月（10/31、以後は月末）

- 振り返り：売上（最重要）→ `paid_buy_click`（販売開始後）→ サイトの訪問のうち `utm_source=x` と `utm_source=note`（GA4）→ X の投稿ごとのリンクのクリック → フォロワー。x-staff ③ と編集長（S1）が `promo/status.md` に書き、翌月の計画を3つに絞る
- 順番表の次の月の分を、伸びた型で作り直す（x-staff ②）

## 数字の見方（優先順）

1. 実購入の件数と、どの記事から来たか（Stripe の支払い記録と D1。GA4 では数えない）
2. `paid_buy_click`（販売ページの購入ボタン。販売開始後）
3. GA4：ソース / メディアが `x / social` と `note / referral`。キャンペーンは記事のファイル名（X は `utm_content=reply|body|pinned`）
4. X：投稿ごとのリンクのクリック、プロフィールへのアクセス、フォロワーの増減
5. note：スキ・フォロー・記事の表示回数（note のダッシュボード）

アクセス・フォロワー・クリックは「流れが太くなったか」を見る数字で、成果ではない（`CLAUDE.md`「最新の事業方針」）。

## 3つに共通の決まり（2026-10-17・10-18）

- 言い方は BRAND.md と `docs/content-quality.md`。命令・断定・約束・あおりは使わない。ムートンの経験と提案として書く。最後に問いを一つ
- ○×クイズ・投票・穴埋め・ワーク・「今日やること」・手順の箇条書きは、X・note・サイトのどれでも使わない
- X の材料は残す記事（`src/_data/currentArticles.js`）と「ムートンについて」。note の材料は有料の3本の悩みと3つの姿勢。アーカイブの記事（選び方・身体・食事）からは作らない
- 事実と数字は、サイトの記事に出典つきで書いてあるものだけ。note で新しい研究を使うときは一次資料で確かめる
- 有料記事のことは、販売が始まるまで「近く、このサイトで PDF にする」までにとどめ、値段と購入の案内は書かない
