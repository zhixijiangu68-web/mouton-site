# 記事とコピーの品質基準（2026-10-17。2026-10-18 に「0. コピーライティング第一」、2026-10-28 に「7. 記事の型の段階1」と「8. 記事の型の段階2」を足した）

AI社員（ai.shain）と AI チーム（S2 記事担当・S3 チェック）、そしてムートン自身が、記事を書くとき・直すとき・公開前に確かめるときの物差し。対象は残す記事（有料の3本・連載「哲学者に聞く」・3つの姿勢）と販売ページの文章。X の下書きにも同じ基準を当てる。
決まりの出どころは `CLAUDE.md`「点と線」「安易に与えない」「文章のルール」と `BRAND.md`「一人に語りかける」「信者をつくらない」「取り入れないこと」。ここは、それを一本の記事に当てはめたもの。

## 0. コピーライティング第一（2026-10-18、オーナー）

> 全てコピーライティングを第一優先にしてください。美しさなんて二の次です。美しさを求めれば、コピーライティングの質が下がる。完全な両立は不可能である。（オーナーの言葉）

記事・販売ページ・トップ・X・note のすべてで、言葉を最初に決め、見た目は言葉に従わせる。下の 1〜6 と、この節がぶつかったら、こちらが先。ただし「言い切らない」「押しつけない」「約束しない」（1 の 5）は、コピーを強くするための制約であって、ゆるめない。全文は `BRAND.md`「コピーライティング第一」。

一本の記事・一つのページ・一本の投稿で、この順に確かめる：

1. **1行目で止まるか。** 読んでいる一人が「自分のことだ」と思う場面か、常識の反対の一文か、意外な一文か。いちばん強い一文が後ろにあるなら、前に出す。「朝、いつもの電車に乗って、いつもの席に着く。」のような、まだ何も起きていない場面で始めない
2. **具体か。** 場面・数字・固有名詞・本の章・ムートンがしたこと。「見え方が変わる」「材料を置く」「考えが動きだす」のような抽象だけで終わらせず、何がどう分かるかを一つ添える
3. **読む理由が、段落ごとに続くか。** 雰囲気のための一文、余韻のための改行、詩的な言い回しは、伝える役に立っていなければ削る。短いほうが強い
4. **次に何をするかが分かるか。** 無料の見本を読む、記事を開く、問いを持ち帰る。ボタンとリンクの言葉は、動作と中身がそのまま分かる言葉（「冒頭を無料で読む」「3本をくらべて選ぶ」）
5. **見出しが本文の約束と一致するか。** 見出しで引いて、本文で裏切らない。見出しは、本文を読まない人にも、いちばん大事なことが伝わる文にする
6. **見た目が言葉を削っていないか。** 字数制限・行数の切り詰め（line-clamp）・0.8rem 未満の文字・折りたたみ・演出で遅れて出る文字・英語だけの小見出しがあれば、言葉のほうを守って見た目を直す

**美しさとの関係**：きれいな言い回しと、伝わる言い回しが同時に手に入らないときは、伝わるほうを取る。「読むだけでは、何も変わらなかった。」は、きれいだから残すのではなく、読んだ人が自分のことだと思うから残す。

## 1. 一本の記事が満たすこと

1. **誰の、どんな夜のための記事か、冒頭の3段落で分かる。** 場面（転職サイトを開いては閉じる夜、既読のまま三日たった LINE）から入る。定義や説明、「〜とは」から入らない
2. **一つの悩みに、一人の哲学者（または一つの研究の束）。** 広く浅く並べない。キルケゴール＝考えすぎて決められない、ニーチェ＝人の目が気になる、スピノザ＝感情に振り回されて続かない
3. **哲学者の言葉には出典。** 書名・章（できれば訳・ページ）。要約なら「（要約・僕の訳）」と添える。出典を確かめられない名言（「ニーチェはこう言った」）は書かない
4. **研究は番号付きの参考文献。** 著者・年・誌名・巻号。本文の数字は論文の数字。逸話は逸話と書く。異論・再現の弱さ・相関と因果の違いがあれば、本文に書く（例：「意志力が使うと減るという説は、大規模な追試でほぼ確かめられなかった」）
5. **言い切らない。** 命令（〜しなさい・〜しろ・〜するな・〜してください・〜しましょう）、断定（〜すべき・必ず・誰でも・絶対に）、結果の約束（〜できるようになる・続けられる・人生が変わる）、あおり（今すぐ・手遅れ・損）を使わない。「僕はこうしている」「〜かもしれない」「〜だと思う」「〜という見方を手元に置ける」
6. **読んでいる一人に語りかける。** 「人は〜」より「〜していませんか」「あなたがいま、こうなら」。ただし「あなた」を毎文に入れない。読者の気持ちを決めつけず、選ぶ余地を残す
7. **最後に問いを一つだけ。** 答えも、手順の箇条書きも、「今日やること」も置かない。書き込みワーク・穴埋め（＿＿＿＿）・「1分だけ書いてみる」は置かない（`npm test` が止める）
8. **判断の理由・作り方・直したことが、一か所以上ある。**（2026-10-28 に直した。前は「ムートン自身の迷いと試したことが、一か所以上ある」。`docs/article-type-20261028.md` の★3、PR のマージで承認）判定に迷った行の理由（主語を置かずに「この行を△にしたのは、〜からだ」）、作り方（何を・どこで探し、どう確かめたか）、書く途中で直したこと（判定や題の範囲）のどれか。ムートン自身の体験と気持ちは、オーナーだけが書く欄に書き、AI は書かない（7）
9. **有料記事への案内は、その悩みの続きとして一つ。** `{% set ctaSlug = "paid-xxx" %}{% include "partials/paid-cta.njk" %}`。価格は「2,980円（税込）」、買えないうちは「販売準備中」が部品から自動で出る。本文で売り込まない
10. **「取り入れないこと」を混ぜない。** 引き寄せ・量子力学・「恐怖は存在しない」・「負け組」・退路を断つ・怒りや自己嫌悪を燃料にする・環境の差の否定・「決断疲れ」などを事実のように言うこと（`BRAND.md`「変わる順番」の末尾）。ほかのやり方を否定しない（「どれも、合う人と合う時期がある」）

## 2. 文体

- 一人称は「僕」。常体（だ・である）。敬体は部品（FAQ・運用の案内・著者欄）だけ
- 一文は短く。「〜ということ」「〜することができる」「〜において」を減らす。漢語より和語
- 見出しは文で書く（「不安を『めまい』と呼んだ人」「待つことにも、コストがある」）。名詞だけの見出しを並べない
- 表記：数字は半角、年は西暦、「2,980円（税込）」、鉤括弧の入れ子は『』、「バールーフ」など固有名詞は既存の記事にそろえる
- 長さの目安：**新しい型のサイトの記事（`layout: renewal-article.njk`）は本文1万〜2万字**（2026-10-22、オーナー「サイトは決定版だから重厚にして欲しい」。front matter・参考文献・タグ・空白を除いて `npm test` が数える）。note は2,000〜4,000字（サイトの記事の一部。続きはサイト）、X は1投稿140字まで（120〜140字をめざす）。以下は今までの型（アーカイブ）の目安：入門（連載）は約5〜8分（本文2,500〜4,000字）、掘り下げは約10〜15分（5,000〜7,500字）。読了時間は `約{{ readMinutes }}分で読めます（目安）` で自動
- 比較は表より文章の2段落で（既存の記事の書き方）。箇条書きは、参考文献と「動いていいとき／時間をかけたいとき」のような対比に限る

## 3. 構成の型（無料の記事）

場面（1〜3段落）→ 問い（太字の一文）→ 哲学者の言葉・研究（出典）→ 僕の読み方 → 中央の一文（`.identity`）→ 別の角度・異論・動かないほうがいい場面 → 僕が試していること → 問いを一つ（`.question`）→ 参考（`<section class="refs">`）→ 有料への案内（`paid-cta.njk`）→ `article-end.njk` → `reading-next.njk`

- front matter は `CLAUDE.md`「記事を追加するとき」と `README.md`「記事を追加する」。`title` は末尾に「 — ムートン」、`description` は80〜120字、`journal`（category・title・excerpt）、`related`
- HTML の骨組みは見本（`src/articles/kierkegaard.html`・`action-bias.html`）をコピーする：`<main data-nav="light" data-nav-solid="light"><article>`、`.meta`、`<h1>`（文節で `<br>`）、`.reading-time`、`.article-share`、`.lead`、`<h2 id="section-n">`、`.question`、`.identity`、`.refs` の `<p id="ref-n">`
- 残す記事にするなら `src/_data/currentArticles.js` に足し、関係のある残す記事から本文の1文でリンクする。シェア用の画像 `images/og/<slug>.jpg`

## 5. 公開前チェックリスト（S3 チェック・AI社員のチェック担当）

- [ ] **コピー**（最初に見る）：1行目で止まる。具体で、次に何をするかが分かる。雰囲気のための一文・英語だけの小見出しがない。見た目のために文字を小さく（0.8rem 未満）・短く（line-clamp）・遅く（演出）していない（0 の 1〜6）
- [ ] **出典**：本文の `[n]` と `<p id="ref-n">` が一致。文献は著者・年・誌名まであり、実在を確かめた。確かめられないものは削った
- [ ] **数字**：本文の数字が出典の数字と一致（割合・人数・年）。逸話は逸話と書いた
- [ ] **言い方**：命令・断定・約束・あおり・見下しがない（`npm run lint:writing -- <slug>` の警告を読み、引用と FAQ 以外は直した）
- [ ] **終わり方**：最後に問いが一つ。手順・ワーク・穴埋め・「今日やること」がない
- [ ] **事実**：健康・医療の言い切り（治る・効く）がない。「取り入れないこと」の主張が混ざっていない
- [ ] **一人に**：冒頭が場面から入り、読んでいる一人に向いている。判断の理由・作り方・直したことが一か所以上ある（1 の 8。2026-10-28）
- [ ] **導線**：有料への案内が一つ（`paid-cta.njk`）、`currentArticles.js` に登録、`related`、既存の記事からの相互リンク、OG 画像、リンク切れなし
- [ ] **重複**：同じテーマの既存の記事と役割が分かれている（入門と続き、要約と掘り下げ）
- [ ] **規約**：front matter、ファイル名（英小文字とハイフン）、`npm run build` → `npm test`、生成物、作業ログ（`promo/log/`）
- [ ] **スマホ**：既存のクラスだけを使い、固定幅を増やしていない（390px で横にはみ出さない）

## 6. 販売ページ（`paid-*.html` の `lp`）の文章

- 冒頭の4つ（どんな悩みに／読んで、考えられること／届くもの（PDF）と価格／いま買えるか）→ 見本 → 詳しい内容 → 制作理由の順（`CLAUDE.md`）
- 見出し（h1）は商品の題そのもの（`paid.title`。「決められないのは、考えが足りないからではない。」のような、常識の反対の一文）。その上に読者の心の声（`lp.hook`）、下に副題（`paid.subtitle`）。別の見出し（`lp.headline`）は使わない（2026-10-18「コピーライティング第一」）。節の小見出し（`plp-step`）は日本語で
- `after`・`benefits` は結果の約束に読める文（「〜できるようになる」「続けられる」）にしない。「〜という見方を手元に置ける」「〜を考えられる」
- 本ごとの固有の文（`lp.scope`・`toc`・`faq`）を、ほかの本から流用しない（2026-10-17 にスピノザ本でキルケゴール用の文が見つかった）
- ブランドの考え方（押しつけない・問いを渡す）の説明は「ムートンについて」（start.html）に1か所だけ。販売ページで繰り返さない
- 購入ボタン・価格・販売状況は部品と `npm test` が管理する。文章で「買える」と書かない

## 7. 記事の型の段階1（2026-10-28。`docs/article-type-20261028.md` の★2・★3・★7、PR のマージで承認）

今の記事（`layout: renewal-article.njk`）の決まり。1〜5 と食い違うときは、こちらが先（1 の 6「一人に語りかける」・1 の 8、4 の見本の「僕の実践」を含む）。くわしくは `docs/article-type-20261028.md` の「3. 文体の決まり」。

- **署名の行と続きの口は、自動で付く。** 署名の行（書いた人・参考文献の数・判定の決まり・AI の使い方）は読む時間の下に、続きの口（新しい記事を RSS で知らせていることと、X の案内）は「次に読む」の下に、テンプレートが全記事に付ける。本文には書かない
- **僕の体験の欄（front matter の `owner.note`）は、オーナーだけが書く。** AI は書かない・作らない。健康の記事に体の変化、性の記事に性の体験は書かない。400字まで（空白と改行は数えない。`npm test` が数える）。空なら何も出ない
- **「僕」は、オーナーがしたこと・決めたことにだけ使う**（例：オーナーが原典を開いた行の「僕が原典で確かめた」）。判定の理由は、主語を置かずに書く（「この行を△にしたのは、〜からだ」）。体験と気持ち（驚いた・信じていた・試した・感じた・思っていた）は、僕の体験の欄に書く（本文にあれば `npm run lint:writing` が知らせる）
- **読む人への問いは、最後の一つだけ**（`.rn-question`。`npm test` が数える）。本文の「あなた」は1本に2回まで（lint が知らせる）。命令・勧誘（〜しよう・〜すべきだ・〜するとよい）と、読む人の体や性の経験を尋ねる文は書かない
- **生き方の結論は書かず、問いに変える。** 文末の「大切だ」「大事だ」「〜するとよい」「〜したほうがいい」「おすすめ」は lint が知らせる。性・外見の記事では、かぎ括弧の外で「モテる」「色気が出る」を使わない（lint が知らせる）

## 8. 記事の型の段階2（結果の3行と判定表）（2026-10-28。`docs/article-type-20261028.md` の★1・★5 と 6-3、PR のマージで承認。まず色気の記事で試す）

front matter に `results` と、`claims` の各行の `section`・`refute` を書いた記事だけに効く。書いていない記事は、今の表のまま（生成物も変わらない）。残りの記事は `docs/article-type-20261028.md` の 6-4 の順で直す。くわしい理由は同じ文書の「2-2」「2-3」「3. 文体の決まり」。

**結果の3行**（`results` の `yes`・`no`・`open`）。署名の行のすぐ下に「支持されたこと／支持されなかったこと／分かっていないこと」として出る。見出し（h2・h3）にはならないので、節の番号（s-N）はずれない。

- **主語は研究。** 「〜を調べた研究では」「〜の研究で」と書く。「僕」も「あなた」も主語にしない
- **条件を同じ文に入れる。** 何を・誰で測ったか（写真・録音・初対面の数分、大学生、異性愛など）。X や AI の要約に1文だけ抜き出されても、条件が落ちないようにする。例：「見知らぬ人の写真や録音、初対面の数分を調べた研究では、…と結びついた（確かさはどれも中）。」
- **数字は本文にあるものだけ。** `npm test` が本文と照らす（出典の番号 [N] は本文の数字に数えない）。表の数字を写すときも、本文に同じ数字があることを確かめる
- **読む人の行動を書かない。** 〜するとよい・〜してみる・〜を選ぶ、は書かない。生き方の結論は、最後の問いに任せる
- **使わない言葉**：「だから」「つまり」「結論」「おすすめ」「あなた」。`docs/article-type-20261028.md` の「3. 文体の決まり」にある使わない言葉（判明・衝撃・驚き・科学的に証明 など）と、性・外見の記事の「モテる」「色気が出る」「〜すれば」も使わない
- **長さ**：各行120字まで・3つで300字まで（空白を数えない。`npm test`）。確かさを添えるなら、表と同じ言葉で（「確かさはどれも中」）

**判定表**（`claims`）

- **1行目は題の主張。** あとは本文の節の順（表が目次を兼ねる）。確かさの順には並べない
- **行き先の節**（`section`）：本文の h2 か h3 の文字を、そのまま書く。表の「よく言われること」が、その節へのリンクになる（h2 は `#s-N`、h3 は `#s-N-M`。N はその h3 が入っている h2 の番号、M はその h2 の中で何番目の h3 か）。どの見出しとも一致しない行と、同じ文字の見出しが二つ以上ある行があると、ビルドが止まる。h2 の文字を変えたら、`section` と理解度テストの `section` も直す
- **× の種類**（`refute`）：研究で差がなかったら `nodiff`、主張と逆の結果なら `opposite`。× の行には必ず書き、× でない行には書かない（`npm test`）。表には「× 否定（差がない）」「× 否定（主張と逆）」と出る。記号と朱は今のまま。どちらにもあたらない ×（主張の言い方が、研究の示す大きさや数字と食い違う）をどう扱うかは、まだ決まっていない
- **根拠**（`basis`）：一文で、60字めやす・80字まで（`npm test` は80字を超えるものと、文の途中の「。」で止める）。主な人数か数字を一つ入れる。限定の言葉（研究が一つ・写真への印象・動物だけ・観察だけ）は、字数のために消さない
- **表の上の一行は自動。** 内訳（「17のうち、○ 支持 4・× 否定 4・△ 弱い 9。」）・確かさの説明・「判定の決まり」へのリンクを、テンプレートが表のすぐ上に出す。健康の記事（`health: true`）には「この表は、医療の助言ではない。」が付く。本文には書かない。その記事だけの注は、表の前に一〜二文（`.rn-note`）で書く（例：色気の記事の「判定するのは、よく言われることを研究がどこまで支えるかで、声や体や顔の良し悪しではない。表の「色っぽい」は、その研究が測った魅力の評価や選ばれやすさに置きかえた。」）。注には、自動の一行にあること（確かさの説明）を重ねない

**本文に足すもの**（本文の字数に数える）

- **判定に迷った節の理由の一文**：迷った節にだけ、主語を置かずに書く（例：「だから、この行は○でも×でもなく、△にした。」）
- **作り方の段落**：判定表のあとの最初の節の終わりに100〜200字。何を・どこで探し、どう確かめたか。AI の役割と確かめ方。確かめられなかったものは、そう書く。オーナーが原典で確かめたら「主な数字は、ムートンが原典で確かめた」に直す
- **いちばん弱いところの段落**：最後の節の「分かっていないこと」のあとに。判定でいちばん弱いところ（同じ研究グループのデータに頼っている、など）と、書く途中で直したこと（題や判定の範囲）
