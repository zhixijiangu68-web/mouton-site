オーナーの依頼：「社員を役割ごとに分けて、それぞれの成果の最大化を図りたい。3つ（note・サイト・X）は繋がっている。休みなく24時間働いてほしい」。

## 一本の流れ（3つは繋がっている）

```
X（見つけてもらう）──┐
                      ├─→ サイトの入口（無料の入門記事・3つの姿勢・ムートンについて）─→ 悩みから選ぶ有料の3本（PDF）─→ 実購入
note（外から連れてくる）┘                                  ↑
                                                   サイト事業部（入口と商品を磨く）
```

- X と note は「入口に人を連れてくる」までが仕事。入口から先（商品ページ・購入）はサイト事業部の仕事
- 数字は逆向きに流れる：実購入と `paid_buy_click` → どの入口から来たか（utm）→ X・note の次のテーマ。月曜の分析担当がこれをまとめ、編集長が3つに配る
- 販売が始まるまで、X・note は有料記事の値段・購入の案内を書かない（入口までを太くする）

## 24時間の回し方（自動で動く時刻。日本時間）

Claude Code の「定期実行」（claude.ai の scheduled tasks）が、部署ごとの**常設セッション**（mouton-site のリポジトリと GitHub の道具が付いたセッション）に、決まった時刻に仕事の指示を送って働かせる。`ANTHROPIC_API_KEY` の登録は要らない（オーナーの Claude の契約の利用枠を使う）。

| 常設セッション | 受け持つ定期実行 |
|---|---|
| MOUTON 常設：X事業部（朝の3本・週次分析） | 毎朝 5:27、毎週月 6:13 |
| MOUTON 常設：note事業部（週1本） | 毎週火 4:11 |
| MOUTON 常設：サイト事業部（AI社員・週1件） | 毎週木 4:17 |

2026-10-18 の確認：定期実行が「新しいセッションを起動する」形だと、リポジトリも GitHub の道具も付かず仕事ができなかった（試し実行で確認）。リポジトリ付きの常設セッションに向けて発火する形に変え、常設セッションでリポジトリ・GitHub の道具・push 権限の3つを確かめた。そのうえで、毎朝の手順を一回だけ発火させる試し運転をしたところ、X事業部の常設セッションが順番表（未マージのブランチ）を読み、3本を点検して Issue #230 に「今日の3本（試し実行）」をコメントした（https://github.com/zhixijiangu68-web/mouton-site/issues/230#issuecomment-6243748345 ）。
注意：定期実行の一覧から手動で「今すぐ実行」すると、常設セッションではなく新しいセッションが起動して仕事ができない（同日に確認）。試すときは、常設セッションにメッセージを送るか、一回だけの定期実行（run once）を作る。

| いつ | 誰 | 何をする | 届く場所 |
|---|---|---|---|
| 毎朝 5:27 | 編集長＋X担当 | PR・Issue の状態を確認。前日の ✓ を読む。今日の3本を点検して出す | Issue #230 に1コメント（コピーして投稿） |
| 毎週月 6:13 | X 分析担当 | ✓ と数字を順番表に反映、週の分析、翌週の順番表 | PR「X の週次」＋ Issue #230 |
| 毎週火 4:11 | note事業部 | 5段階で1本（テーマは Issue #231 の希望か、まだ無い悩み・姿勢） | PR「note：…」＋ Issue #231 |
| 毎週木 4:17 | サイト AI社員 | `ai-task` の Issue を古い順に1つ、担当 → チェック担当で draft PR | PR ＋ その Issue ＋ Issue #232 |

- 「24時間」の意味：人が寝ているあいだに AI が仕事を進め、朝にはオーナーが押すボタン（投稿・公開・マージ）だけが残っている状態にする。毎時間動かしても、投稿・公開・マージという人の手が間に合わないので、価値の出る時刻にだけ動く
- 各回の費用の目安：毎朝の確認 $0.5〜1.5、週次の分析 $2〜4、note 1本 $5〜10、サイトの AI社員 $3〜5（合計で月に $80〜100 ほどの利用枠）。多いと感じたら、下の「止め方」
- GitHub Actions 側にも同じ仕事の定期実行を用意した（`.github/workflows/ai-shain-schedule.yml`）。リポジトリの変数 `AI_SHAIN_SCHEDULE` を `on` にし、Secret `ANTHROPIC_API_KEY` を登録すると動く（API の従量課金）。**Claude Code の定期実行と二重に動かさない**：GitHub 側を on にしたら、Claude Code 側の「毎朝」と「火曜」を止める

## 10/5〜10/7 に作った古い定期実行は止めた（2026-10-18）

オーナーのアカウントには、10/5〜10/7 に作った定期実行が10本残っていた（記事担当の毎日の仕事＝選び方の記事を毎日1本／編集担当＝選び方へのリンク足し／記事担当の note＝選び方から note／X担当の朝の仕事＝旧順番表の2本／指揮役＝AI の PR を検査してマージ／編集担当＝制作の記録／ラベル担当・デスク／企画・リサーチ／サイト保守／編集者）。いずれも 10/15〜10/17 の方針（選び方・知識の記事・クイズ・ワークは作らない、点と線、安易に与えない）より前の決まりで動いていて、新しい4本と役割が重なる。「指揮役」は AI の PR を自動でマージする仕事だったので、人が確認してマージするいまの流れとも合わない。
そのため10本を**一時停止**にした（削除していない。claude.ai の定期実行の一覧で再開できる）。「10月の目標リマインド」だけは、朝のリマインドとして残し、指示文を新しい流れ（販売の準備 → 入口 → 有料の3本、Issue #230〜232）に書き換えた。

## 止め方・変え方（オーナー）

- claude.ai の Claude Code → scheduled tasks（定期実行）の一覧で、各タスクを一時停止・削除できる。名前は「MOUTON 編集長＋X担当」「MOUTON X 分析担当」「MOUTON note事業部」「MOUTON サイト AI社員」。常設セッション（「MOUTON 常設：…」）はセッションの一覧にあり、アーカイブすると定期実行も止まる
- Claude Code の会話で「毎朝の定期実行を止めて」「note を週2回にして」と言えば、AI が変える（時刻・回数・やること）
- 各タスクの指示文は、この文書と各部署の決まり（`rules.md`・`SKILL.md`・`.github/ai-shain.md`）を読む前提なので、**決まりを変えるときはファイルを直せば、翌日から反映される**
