# MOUTON — 商品起点の事業方針・初回販売の検証（2026-10-15）

**決定日**：2026-10-15  
**位置づけ**：オーナーの事業方針。顧客像・価格受容性・商品適合性は、販売を通じて検証する仮説。  
**対象**：MOUTONサイト・哲学商品の開発、販売準備、集客判断、週次振り返り。

## 1. MOUTONの定義

> **MOUTON = 自分の人生を、自分の意志で変えていくための実践ブランド。**

自分を変えたいけれど、何から始めればいいか分からない人に、**知識と実践方法**を提供する。

目指す価値は、情報を読んで終わることではない。自分の現在地と理想の差を理解し、次の行動を選び、実践と振り返りにつなげることである。何を作るかだけでなく、なぜ作るか、どう生きるかを大切にする。

変化の土台は、自分の意志・価値観・生き方・マインドセット。そこから必要に応じて外見、身体、食などの改善に進む。哲学は飾りではなく、行動のための手段にする。

## 2. 誰の、どんな悩みを、いくらで解決するか

### 顧客仮説（未検証）

- **誰のためか**：自分を変えたいのに、何から始めればよいか分からない人。年齢や性別を最初から固定せず、実際の購入者やヒアリングから絞る。
- **中心的な悩み**：「理想の自分と現在の自分の間にある、行動できないという壁」。選択できない、先延ばしになる、他人の評価が気になる、方法が多すぎて一歩を選べない、といった具体的な悩みを検証する。
- **提供する価値**：知識だけでなく、現在地の把握、優先課題の特定、最初の行動、実践と振り返りを支える仕組み。
- **対価を払う理由の仮説**：漠然とした不安を「今、何をすればよいか」という具体的な行動に変えられるから。「情報量」だけでなく「迷わず行動できる仕組み」に価値があるかを検証する。
- **いくらか**：商品ごとに価格を設定し、実際の購入で受容性を確かめる。価格の設定やLP閲覧を、支払意思の証拠とみなさない。

商品で答えるべき三つの問い：

1. **何が足りないのか？** — 本人が理解できる現在地・不足・阻害要因。
2. **何をすればよいのか？** — 小さく具体的で、今日から実行できる行動と手順。
3. **それが分かるとどうなれるのか？** — 自分の意思で選び、行動を積み重ねられる状態。ただし変化を保証・誇張しない。

**既存商品の扱い**：「清潔感の科学」は **2,980円（税込）** の販売準備中の商品であり、決済・納品・法務条件の確認が完了するまで「販売中」とは表現しない。哲学商品を中心にする方針と、既存商品の販売準備を混同しない。今後の商品価格は商品別に定義・検証する。

## 2.5 哲学商品の定義（2026-10-15 改訂、オーナー採用）

「変わりたいのに動けない」だけでは、ほかの自己啓発ブランドと区別がつかない。対象・悩み・商品を、買う人の言葉で具体的にする。

- **誰のために**：転職・独立・人間関係などの岐路に立ちながら、「人の目が気になる」「考えすぎて決められない」「始めても続かない」状態にいる20〜30代。哲学YouTubeの企画と同じ対象（20代・自己啓発の初心者）にそろえ、YouTube → 記事 → 商品の流れを一本にする。
- **何を解決するか**：自分の判断基準がないせいで、選べない・続かないという悩み。解決後の状態は「自分の基準で選び、選んだことを続けられる」。
> **2026-10-17 更新（オーナー）**：書き込みワーク・「1分だけ、書いてみる」・PDF の書き込み用ページ・「次の一歩」はなくした（安易に与えると、それ自体が受け身になる。読者に考えてほしい）。この文書の「書き込み」「ワーク」の記述は古い。いまの考え方は `BRAND.md`「安易に与えない」。

- **何を売るか**：3人の哲学者の考えを、自分の悩みに合わせて使える書き込み式の実践プログラム。
- **何をしないか**：学術的な解説はしない。精神論は語らない。特定の信仰は勧めない。正しい生き方を押しつけない（`BRAND.md`）。
- **一言で**：「哲学を、読むものから使うものへ。」
- **価格**：ブランド定義には含めず、商品設計の段階で決める。哲学の有料記事3本は各 **2,980円（税込）**（2026-10-16、オーナー決定）。
- **本との違い（範囲）**：価格は一般的なビジネス書より高い（オーナーの見積もりで約440円）。「キルケゴールの哲学が学べる」だけでは、既存の本ではなくこちらを買う理由にならない。そこで範囲を「自己理解」から「**ひとつの具体的な選択を決めて、実行するところまで**」に絞る（2026-10-16、オーナー案）。販売ページでは、対象（ひとつの決断・選択・続けたいこと）と4つの段（書く → 決める → 一歩を踏む → 1週間後に見直す）を `lp.scope` で示し、「思想の全体像や人生全体の自己分析は扱わない。それは本のほうが向いている」と書く。比較表の先頭に「哲学の入門書・ビジネス書」、FAQ に「本との違い」。**この差に価格分の価値があるかは、購入の有無で確かめる仮説**。
- **読むだけで得られる価値／有料にする理由**（2026-10-16、オーナー）：まず「読むだけで得られる価値」を成立させ、行動の負担を小さくする。哲学なら、悩みを違う角度から捉え直せること自体に価値がある（販売ページの `lp.reframe`）。書き込みワークは任意。ただし短くするだけでは無料の記事と差が出ないので、有料の理由は情報量ではなく設計に置く：①自分の悩みに当てはめやすい（場面の例、`lp.scenes`）②必要な答えにたどり着ける（PDF の最初に「いまの状態 → 読むところ」の地図、`lp.map`）③次の行動まで分かる（PDF の最後に「次の一歩」と「やめること」）。
- **身体・食事のページも同じ形に**（2026-10-16、オーナー）：`topic-body.html`・`topic-food.html` を「悩み → 見え方の読み替え → 読む記事 → この悩みの続き」に（`src/_data/topics.js` の `lp`、`partials/topic-lp.njk`）。新しい有料商品はまだ作らない（オーナー選択）。身体の「清潔感」は清潔感の科学へ、「やる気・気分」と食事の「続かない」はスピノザの有料記事へつなぐ。記事はすべて「すべての記事」に残す。
- **売る場所**：note ではなく**このサイト**。Stripe で支払い、PDF をメールで届ける（2026-10-16、オーナー決定）。段取りと公開の条件は `docs/philosophy-sales-20261016.md`。

## 2.6 販売ページの作り方（2026-10-16、オーナー採用）

有料記事3本の販売ページ（`paid-*.html`、共通部分は `partials/paid-lp-*.njk`）は次の考え方で作る。

**取り入れること**
- **売るのは記事ではなく、読んで書き込んだあとの状態**。「いま → 読んで、書き込んだあと」をはっきり書く。
- **最初の画面（スクロールせずに見える部分）にいちばん力を入れる**。見出し＝「結果」＋「かかる時間（15分・ワーク）」＋「なぜ効くのか（哲学者の考え方）」。小見出しで「〜せずに」と、読者がすでに試したやり方（調べ続ける、気合い、デトックス、「気にするな」）との違いを示す。その下に得られることを3つと「冒頭を無料で読む」ボタン。
- **気の利いた言い回しより、分かりやすさ**。迷わせる文は売れない。
- **価格は中身を見せてから**（⑦）。最初の画面には出さない。
- **ほかの方法との比較**（⑤の中）。否定ではなく、「得られるもの」と「残りやすいこと」の違いとして書く。
- **買う前の不安を先に答える**：FAQ は購入のすぐ下に置く。返金の代わりに「冒頭を無料で読んで、文章が合うか確かめてから決められる」と書く。
- **ページの部品はすべて目的を持たせる**。目的を言えない部品は足さない。足すより、引けるものを探す。
- **画像は、信じてもらうことを足すか、引っかかりを外すためだけに置く**（2026-10-16）：飾りの画像は置かない。販売ページには、納品する PDF の実物（表紙・地図・最後の「次の一歩」）を見せ、「何が届くのか分からない」を外す（`partials/paid-pdf-look.njk`、画像は `images/paid/`）。AI で作った「ビフォーアフター」などの画像は使わない。全文が分かる部分（書き込みワーク全部など）は画像にしない。
- **読み返して削る（チーフィング）**：部品を足したら、ページを頭から声に出して読み、つかえるところと、同じことを何度も言っているところを削る。足すより、引く。
- **FAQ の材料は、買ってくれた人に聞く**：「買う前に、何が引っかかったか」。買わなかった人のコメントより、買った人が迷ったことのほうが、次の人の背中を押す（生き残った飛行機だけを見て補強しない＝生存者バイアスに注意）。

**使わないこと**（BRAND.md・CLAUDE.md と合わないため）
- 品切れ・残りわずか・期間限定などの希少性や緊急性、セールのあおり。
- おとりの価格（真ん中の選択肢を不利にして高い方へ誘う）や、目的のない特典の上乗せ。
- 実在しない口コミ・体験談、効果を約束する数字（「5分で」「必ず」）。口コミは、実際の購入者から許可を得たものだけを載せる。
- 恐れで動かす言い方（「明日死んだら」「いま買わないと」）。

## 2.7 目立ち方と、届け方（2026-10-16、オーナー採用）

マーケティングの考え方（8年分の広告運用の話、動画の書き起こし）から、MOUTON に合う原理だけを借りる。他人の文面を言い換えて使う「そのままのまね」はしない。

**取り入れること**
- **逆側に立つ（コントラスト）**：自己啓発の動画や本でよく見るもの（気持ちを上げる言葉、「人生が変わる」という約束、成功者の型、次々に流れてくる方法、「今だけ」）の反対側を引き受ける。哲学のページの「ここには、ないもの。代わりに、あるもの。」（`partials/philosophy-lp.njk`）。ほかのやり方は否定しない。
- **大きな市場の、小さな一角**：需要が確かな「自己啓発」の中で、「やる気の動画や本を見ても、行動が変わらなかった人」×「岐路（転職・独立・人間関係）」×「3つの悩み」に絞る。哲学のページの最初の一行にした。新しい欲求を作ろうとしない。すでにある欲求（決めたい・人の目を気にせず選びたい・続けたい）を、哲学という道具に向ける。哲学を売るのではなく、悩みが解けたあとの状態を売る。
- **1ページに、1つの段階**：読者がどこまで分かっているかで、ページの役割を分ける。

  | ページ | 読者の段階 | 役割 |
  |---|---|---|
  | はじめての方へ | まだ悩みに名前がない | 悩みに名前をつける・変わる順番を知る |
  | 無料の「哲学者に聞く」 | 悩みは分かっている | 悩みの見え方を一つ変える＋1分ワーク |
  | 哲学のページ | 解き方を探している | 3人から1人を選ぶ |
  | 有料記事の販売ページ | この記事を知っている | 見本を読み、買うかどうか決める |
  | PDF の末尾 | 買ってくれた人 | 次の1本（ほかの2人）へ |

- **最初の一行は、読者の言葉で**：販売ページの見出しの上に、読者が心の中で言っていそうな一行（`lp.hook`）。いまいる場所から始め、見出しで「書き込んだあとの状態」へ上げる。気の利いた言い回しより、中学生が読んで分かる言葉。今の一行は**仮説**で、買ってくれた人に聞いた言葉が集まったら、その言葉に置き換える。
- **売り込みに見せない。でも、隠さない**：無料の記事は読んで役に立つことを先に置く（「1分だけ、書いてみる」、`partials/mini-work.njk`）。そのすぐあとの案内で、続きが有料であること・価格を明示する。
- **流れの細いところを探す（計測）**：GA4 のイベントで、どこで人が止まっているかを見る。購入そのものは Stripe の支払い記録と D1 の注文で確かめ、クリックを購入と数えない。個人情報・書いた文字は送らない。

  | 段 | 見るもの | イベント |
  |---|---|---|
  | 1 | 無料の記事などから販売ページへ | `paid_cta_click`（`product_id`・`source_page`・`placement`） |
  | 2 | 販売ページの表示 | `page_view`（自動） |
  | 3 | 冒頭（無料）を最後まで読んだ | `paid_sample_read`（「ここから先は有料」が画面に入ったとき） |
  | 4 | 「購入する（PDF）」を押した | `paid_buy_click`（購入ボタンが出てから） |
  | 5 | 実際に買った | Stripe の支払い記録・D1 の注文（GA4 では数えない） |

  たとえば 3 は多いのに 4 が少なければ、価格か購入の案内に引っかかりがある。1 が少なければ、無料の記事か案内の問題。数字が出るまでは、どこが悪いと決めつけない。
- **出す前に、自分で壊してみる**：購入ボタンを出す前に、スマホで「無料の記事 → 販売ページ → 冒頭 → 購入する → Stripe の支払い → メール → PDF」を自分で通す（サンドボックスで）。ボタンの行き先、価格（¥2,980）、記事名、返品の扱いの表示が、サイト・Stripe・メールで食い違っていないかを確かめる。
- **1件あたりの数字**：いまは広告費を使っていないので、獲得の費用はほぼ0。広告を試すなら、販売ページから購入までの割合が分かってからにし、1人を獲得する費用を、1人が買ってくれる金額（Stripe の手数料を引いた手取り）の3分の1までにする。1本買った人が2本目を買う流れ（PDF の末尾から、ほかの2人へ）が、1人あたりの金額を上げるいちばん自然な方法。3本セットの値段は、オーナーが決めるまで作らない。
- **Meta 広告**（将来、2026-10-16 オーナー）：始める条件・計測・広告の中身の決まりは `docs/meta-ads-plan.md`。購入できる状態になるまで出さない。開始は2026年12月、月の上限は20,000円（オーナー決定）。
- **売れている商品の「別の売り方」を探す**（2026-10-16、動画から）：需要が確かめられた市場（哲学・自己啓発の本）で、ほかと同じ売り方をしない。既存の本の**公開されている読者レビュー**を読み、「なぜ買ったか」「何に困っていたか」の言葉を集めて、まだ使われていない角度（悩み・場面）を探す。レビューの文章はページに引用しない（傾向と言葉づかいだけを使う）。ページに載せる言葉は、最後は実際の購入者に聞いた言葉に置き換える。
- **決めつけない**：「この一行のほうが売れるはず」は仮説。1つずつ変えて、週次レビューで確かめる。

**使わないこと**
- 「意識のレベル」を数値で測る図（デヴィッド・ホーキンズの「意識のマップ」）。科学的に確かめられた方法ではない。
- 気持ちを上げてから、わざと元の場所へ落として「落差」で買わせる書き方。恐れや不足感で動かすことになる（BRAND.md）。見せるのは「書き込んだあとの状態」まで。
- 広告であることを隠す見せ方。MOUTON の商品であることは、いつも明示する。人に紹介を頼む場合は、広告であることを示す（景品表示法のステルスマーケティング規制、2023年10月施行）。
- 「チャンスの窓は閉じつつある」式の、時間であおる言い方。
- 汚い言葉・相手を見下す言い方。
- AI で作った「仮想の顧客」の声を、実際の顧客の声として扱うこと。仮説の整理に使うのはよいが、ページに載せる言葉は実際に聞いた言葉だけにする。
- 「見た目が悪い広告ほど売れる」をそのまま当てはめること。世界観は捨てない。取り入れるのは「飾りより、分かりやすさを先に」まで。
- 信者・カルト的な支持者をつくるやり方（『48の法則』第27法則：あいまいな大きな約束、熱狂、儀式、犠牲、序列、収入源を隠す、敵をつくる、見張る）。読者が離れにくくなる仕組みもつくらない。逆にしたものを `BRAND.md` の「信者をつくらない」に記録（2026-10-16）。

## 3. 何を成功とするか

**最初の重要な成果は、個人的な知り合いや関係者ではない誰かが、MOUTONの商品に自分のお金を払ってくれること。**

最初の成功指標は、実際に確認できる**第三者による有料購入1件**。アクセス数・フォロワー数・「興味がある」という発言・決済ボタンのクリックだけを成果とはしない。

評価は段階で分ける。

| 段階 | 確認すること | 成功と混同しないもの |
| --- | --- | --- |
| 商品完成 | 内容、対象課題、実践ワーク、価格、LP、無料サンプルが整う | 原稿の完成だけ |
| 販売可能 | 本番決済、特商法等の表示、返金条件、購入後の安全な納品、実際のE2E試験が完了 | テスト決済や未接続の購入ボタン |
| 初回検証 | 第三者による実決済1件と、購入商品・金額・流入経路の可能な範囲での記録 | 閲覧・クリック・フォロワー数 |
| 再現性検証 | 複数の購入・購入理由・返品/返金・費用・利益を把握して訴求や商品を改善 | 1件の購入だけで継続需要と断定すること |

- **主指標**：第三者による決済済み購入件数、実売上、返金控除後の売上・利益。
- **判断補助**：対象者の悩みの一致、購入理由、商品の利用・実践、満足・改善点、購入に至る導線。
- **補助指標**：アクセス、フォロワー、SNS流入、サンプル閲覧、LP到達率、チェックアウト開始。主指標の代替にしない。
- **未確認事項**：現時点で第三者による初回有料購入の実績は**未確認**。未確認の数字を実績と書かない。

## 4. 商品・ブランド・サイトの優先順位

先週までの中心は、サイト構築・UI改善と多機能・演出の試行錯誤。今週からは、**商品販売とブランドの確立**へ軸足を移す。

1. **商品と顧客の課題**：誰のどの悩みをどの価格で解決するかの仮説、実践価値、商品完成。
2. **販売準備**：説明・LP・価格・決済・法務・納品・問い合わせ・テストを整える。
3. **ブランドの一貫性**：MOUTONの哲学と世界観、シンプルで使いやすいサイト。不要な機能や演出を増やさない。
4. **集客と検証**：商品と販売準備が整ってから、本格的な集客を開始。誰がなぜ購入したかを学ぶ。
5. **記事・SNS・アプリ**：記事は主役ではなく理解や信頼を支える補助コンテンツ。哲学商品を主要な提供価値とし、アプリはブランドの実践体験・作品として紹介する。

**「何を作るか」より、「なぜ作るか」「誰がどんな変化を得るか」を優先する。**

## 5. 商品完成 → 販売準備 → 集客 → 検証

- [ ] 顧客像を一文にし、実際に困っている場面と具体的な言葉を集める
- [ ] 商品ごとに悩み、到達したい状態、提供する手順・ワーク、価格の仮説を整理する
- [ ] 最初に販売する商品の中身を完成させ、購入前に内容を判断できるサンプルを用意する
- [ ] LPで「誰の・何の悩みを・どう支えるか」「価格」「利用条件」を説明する
- [ ] 本番決済、特商法等の必要表示、プライバシー、返金・問い合わせ、非公開商品の安全な納品を整える
- [ ] 自分で本番相当の購入→納品→問い合わせまでテストし、未完了なら販売開始しない
- [ ] 条件が整ってから集客を開始し、実決済による第三者の初回購入を検証する
- [ ] 購入者の悩み・購入理由・行動結果を学び、商品と訴求を改善する（個人情報の扱いに留意）

**集客開始のゲート**：商品が未完成・購入できない・納品できない状態で集客を先行させない。素材の準備や既存のコンテンツの維持は可能だが、販売不能のまま集客数だけを追わない。

## 6. 週次レビューで問うこと

- 誰のどんな悩みが、本人の言葉で確認できたか。
- その人が「何が足りない／何をすればよい／どう変わりたい」に答えられる商品か。
- 実際にいくらを支払った人が何人いるか。未確認なら「未確認」とする。
- 商品完成・販売準備の障害は何で、次の一手は何か。
- サイトの改善は商品の理解や購入の障害を取り除くものか、単なる装飾か。
- 流れのどこが細いか（販売ページへの到達 → 冒頭を読み終える → 購入ボタン → 実際の購入）。数字が少ないうちは決めつけない。
