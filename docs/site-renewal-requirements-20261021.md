# サイト再構築 要件定義（2026-10-21）

> 状態：**案**（オーナーの承認待ち）。目的と進め方は `docs/site-renewal-plan-20261021.md`（立案書）。
> 「未決」と書いた項目は、オーナーが決めるまで実装しないか、仮の値で作って差し替えられるようにする。

## 1. 範囲

**やること**

- 新しいトップ、記事の型（判定表つき）、記事一覧、ムートンについて、の4種類のページを作る
- 今までの日本語の記事109本（有料の販売ページ3本を含む）をアーカイブに移す
- 最初の記事「肉を食べても、性欲は上がらない。」を書き、原典を確かめて公開する
- 新しい配色・文字・ナビにそろえる
- `CLAUDE.md`・`BRAND.md`・`docs/content-quality.md` を新しい方針に合わせる（承認後）

**やらないこと**

- ページを消す、URL を変える（外からのリンクと検索を切らない）
- 英語版（`src/en/`、62本）を作り直す（いまのまま残す。後で決める）
- 有料記事の販売を始める、価格・特定商取引法の表記・納品の仕組み（Worker・Stripe・R2）を変える
- 新しい演出（アニメーション、浮かび上がり、オープニング）を足す
- アーカイブに移した記事の見た目を作り直す

## 2. 用語

| 用語 | 意味 |
|---|---|
| 決定版 | サイトに置く、全文・無料・出典つきの記事。新しい研究が出たら書き直す |
| 柱 | 記事のテーマの分け方。食・身体・お金・生き方の4つ |
| 判定 | 「よく言われること」1つごとの結論。下の4種類 |
| 確かさ | その判定がどれくらい確かか。研究の数・規模・質から付ける目安 |
| アーカイブ | 今までの記事。URL はそのまま、記事一覧から外し、上に注記を出す |

**判定の4種類**（記号と色。色だけに頼らない）

| 判定 | 記号 | 色 | 使うとき |
|---|---|---|---|
| 支持 | ○ | 藍 | ヒトの研究で、主張の向きの結果が出ている |
| 否定 | × | 朱 | ヒトの研究で、主張と逆、または差がない結果が出ている |
| 弱い | △ | 灰 | 研究はあるが、小規模・短期・資金の偏りなどで確かさが低い |
| 証拠なし | ― | 灰 | ヒトで確かめた研究が見つからない |

**確かさの段階**：高／中／低／非常に低。一つの研究だけ、動物や試験管だけ、観察研究だけ、のときは「中」より上にしない。

## 3. ページの構成

| ページ | URL | 新しい扱い |
|---|---|---|
| トップ | `index.html` | 作り直す（4.1） |
| 記事（新しい型） | `<ファイル名>.html` | 新しい型で作る（4.2） |
| 記事一覧 | `journal.html` | いまの記事だけを並べる（4.3） |
| ムートンについて | `start.html` | 書き直す（4.4） |
| アーカイブ | `archive.html` | 今までの記事をすべて並べる（4.5） |
| 運営者情報・プライバシーポリシー・お問い合わせ・特定商取引法 | 今のまま | 残す。新しい見た目にそろえる |
| 有料の販売ページ（`paid-*`）・哲学の3本（`topic-philosophy`） | 今のまま | アーカイブへ。ナビから外す。購入ボタンは今までどおり出さない |
| クイズ・選び方・制作・お気に入り・now・リンク集・連載など | 今のまま | ナビ・トップから外す。ページは残す |
| 英語版 | `en/` | 触らない。日本語のナビとフッターからのリンクは残すか外すか未決 |

**ナビ**：記事／ムートンについて／アーカイブ の3つ。
**フッター**：運営者情報／プライバシーポリシー／お問い合わせ／X／note（ユーザー名が入ったら）。

## 4. 機能の要件

### 4.1 トップ（R-01）

上から順に：

1. ヘッダー（MOUTON、ナビ3つ）。ロゴの下の一言は**未決**（決まるまで出さない）
2. 見出し：「君はどういう人間として生きたいのか？」「答えられないのなら知識が足りていない。」（2文目は藍）
3. 見出しの下の文（案）：答えられなかったのは、僕も同じだ。だから、食・身体・お金・生き方で「よく言われていること」を、一つずつ出典まで遡って確かめている。…確かめた知識は、全部ここに無料で置いておく。
4. ボタン：最初の記事を読む／記事の作り方
5. いちばん新しい記事のカード（題、柱、読む時間、参考文献の件数、要約、判定から3つ）
6. 記事の作り方（3つ：主張ごとに判定と確かさ／出典はすべて番号で開ける／分からないことは分からないと書く）
7. 書いている人（本人の言葉は**オーナーが書く**）、X と note へのリンク
8. フッター

- 記事のカードは front matter から自動で作る（手で書き足さない）
- 見出しを隠す・遅らせる演出は入れない

### 4.2 記事の型（R-02〜R-07）

**R-02 front matter に足す項目**

```yaml
pillar: food            # food / body / money / life
updated: 2026-10-30     # 最後に中身を変えた日（無ければ date）
claims:                 # 判定表。上から重要な順
  - claim: 肉を食べると性欲が高まる
    verdict: none       # support / refute / weak / none
    certainty: ""       # 高 / 中 / 低 / 非常に低（none のときは空）
    basis: 性欲を測ったヒトの研究がない
    refs: []            # 参考文献の番号
changes:                # 更新履歴（新しい順）
  - date: 2026-10-30
    note: 公開
```

**R-03 判定表**：`claims` から自動で作る。列は「よく言われること／判定（記号＋文字）／確かさ／主な根拠」。スマホ幅（390px）では1件ずつのカードにする。

**R-04 本文の順番**：題 → 副題 → 著者・日付・読む時間・参考文献の件数 → 冒頭の要約 → この記事で分かること（3つ）→ 判定表 → 根拠の節（見出しは主張の答えを書く）→ 僕の結論 → 問いを一つ → 健康の注意（`health: true`）→ 参考文献 → 更新履歴 → 次に読む。

**R-05 出典**：本文の数字には必ず `<a href="#ref-N">[N]</a>`。参考文献は番号付きで、著者・年・題・掲載先・リンク。原典を開いて確かめたものだけを載せる。

**R-06 更新履歴**：`changes` を記事の末尾に出す。数字や判定を変えたら、何をどう変えたかを1行で残す。

**R-07 図**：数字の推移は、目盛りどおりの棒グラフで描く（例：訓練中のテストステロン）。出典を図の下に書く。

### 4.3 記事一覧（R-08）

- いまの記事（`currentArticles.js`）だけを新しい順に並べる
- 柱で絞り込める（記事が4本以上になってから。それまでは一覧だけ）
- 一覧の下に「これまでの記事（アーカイブ）」への案内

### 4.4 ムートンについて（R-09）

- なぜ確かめるのか（本人の言葉）、記事の作り方、判定と確かさの定義（2章の表）、X・note・サイトの役割
- ブランドの考え方の説明は、ここに1か所だけ置く（今の決まりのまま）

### 4.5 アーカイブ（R-10）

- `currentArticles.js` を新しい記事だけにすれば、今までの109本は自動でアーカイブになる（今の仕組みを使う）
- アーカイブの記事は、今の見た目のまま。上の注記の文言を「この記事は、サイトを作り直す前（2026年10月まで）のものです。今の記事はこちら」に変え、新しいトップへのリンクを付ける
- `archive.html` は新しい見た目にし、柱ではなく今までの分類で並べる

### 4.6 そのほか（R-11〜R-14）

- **R-11 ダークモード**：端末の設定が暗いときは、黒い地に自動で切り替える（色は配色の表のダーク版）
- **R-12 計測**：GA4（`G-CLF0SMB36X`、設定済み）で、記事の閲覧、最後まで読んだか、参考文献のリンクのクリック、`utm_source`（note・x）を見られるようにする
- **R-13 広告**：記事の中に広告枠は出さない（今の `adsenseSlot: ''` のまま）。自動広告の扱いは**未決**
- **R-14 シェア画像**：新しい記事の OG 画像を新しい配色で作る（`scripts/og`）

## 5. 見た目の要件

**配色**（決定：1 藍）

| 役割 | 色 | 使うところ |
|---|---|---|
| 紙 | `#FAF8F3` | 地 |
| 面 | `#F1EDE4` | 要約の枠、区切りの帯 |
| 墨 | `#1A1A1A` | 本文、見出し |
| 灰（文） | `#3E3C38`／`#4A4A4A` | 補足の文 |
| 線 | `#DDD8CC` | 罫線、枠 |
| 藍 | `#165E83` | リンク、ボタン、○、見出しの2文目 |
| 朱 | `#C8361B` | × だけ |
| 灰（印） | `#5E5E5E` | ―、△ |

- 文字と地の明るさの差は4.5以上（本文 16.4／藍 6.7／朱 5.0 を確かめ済み）
- リンクは色だけでなく下線でも分かるようにする
- **文字**：日本語は Noto Sans JP（400・700・900）。今の明朝（Noto Serif JP）と英字の書体は新しいページでは使わない
- **大きさ**：記事の本文 18px（スマホ 16px）、行間 1.9〜2.0。0.8rem 未満の文字はラベルだけ
- **幅**：本文は1行 約35〜40字（最大 760px）
- アニメーションは使わない

## 6. 文章の要件

- 一人称は「僕」。文体は常体（だ・である）
- 読者の呼び方は**未決**（「君」か「あなた」）。決まるまでは呼びかけを使わずに書く
- 見出しは主張の答えを書く（例：「46万人のデータでも、肉を食べる男性のテストステロンは高くない」）
- 「効く」「治る」と言い切らない。結果を約束しない。嘘の急がせ方をしない
- AI の調査原稿の書き方（「調査チームによる定性評価」など）は使わない。判定と確かさは、ムートンの目安として書く
- ワーク・穴埋め・「今日やること」は付けない。最後は問いを一つだけ

## 7. 最初の記事の要件（R-15）

- 元の原稿：「肉は性欲を高めず、地位を物語る」（PDF 8ページ）と「性欲を動かすのは食材ではなく、過不足と期待」（MD）を1本にまとめる
- 題：肉を食べても、性欲は上がらない。／副題：「精がつく食べ物」を、ヒトの研究で確かめた
- 柱：食。`health: true`。約20分
- 判定表8行（デザイン見本の表を出発点に、原典で確かめて直す）
- **原典の確認**：本文に出す数字と参考文献は、すべて原典（論文・公的な資料）を開いて確かめる。確かめられないものは書かない。確かめた結果は、作業ログに一覧で残す
- 既に分かっている直し：偽薬が薬の効果の約7割（67.7%）は**女性**の試験の数字。地中海食の「2.1万人」は原稿で確かめられなかった
- 「僕の結論」の2〜3文は**オーナーが書く**
- 最後の問い（案）：あなたが「精がつく」と思って食べてきたものは、本当は何を満たしていたのだろう。（呼び方が決まったら合わせる）

## 8. 移行の要件

- `src/_data/currentArticles.js` を、新しい記事だけの一覧に置き換える（公開と同時）
- トップから外れるもの：哲学の有料3本、点と線、3つの姿勢、「読むだけでは、何も変わらなかった。」の流れ
- `CLAUDE.md`：先頭に「2026-10-21 サイト再構築」の節を足し、古い節（トップの構成、点と線、有料3本の販売の優先）に「再構築前」の注記を付ける
- `BRAND.md`：決まったこと（見出し・配色・柱・記事の型・3つの場所の役割）を足す。「ブランドメッセージ」は、看板の一言が決まったら差し替える
- `docs/content-quality.md`：記事の型（4.2）と判定・確かさの定義（2章）を足す
- AI社員の手順（`.claude/agents/`、`.github/ai-shain.md`）：古い記事を前提にしている所を直す（公開後）
- PR #243（記事100本の追加）は、この方針とぶつかるので閉じる（**オーナーの確認後**）

## 9. 品質の要件

- `npm run build` → `npm test` が通る（リンク切れ・ID の重複・title と description・h1 は1つ）
- 新しいページはスマホ幅（390px）で崩れず、横にはみ出さない
- 外から読み込むのは GA4・AdSense・Google Fonts だけ（今の決まり）
- 生成物（リポジトリ直下の `*.html`・`picks.json`・`quizzes.json`）は `src/` から作り、一緒にコミットする
- 公開前に Chromium で、トップと最初の記事をスマホ幅・パソコン幅・ダークモードで確かめる
