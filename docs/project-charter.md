## 2. スコープ

### 含むもの

- ブランドサイトの構造・UI/UX・世界観の設計と改善
- プロフィール、思想・哲学コンテンツ、作品・プロジェクト一覧
- 記事・動画・アプリ等へのわかりやすい導線
- サイト運用、品質確認、効果測定、継続改善
- GitHubでの仕様・変更内容・品質判断の記録

### この定義で直ちに実装が確定しないもの

- 会員登録・会員データベース・独自決済の新規構築
- 既存トップ演出、タブ構成、記事群の全面置き換え
- 新しい収益商品・販売手段の自動的な追加

これらは別途Issueで要件・優先順位を判断する。

## 3. 成果物と開発優先順位

**2026-10-15の最新優先順序**：①誰のどんな悩みをいくらで解決するか検証 → ②実践価値のある商品を完成 → ③本番決済・法務・納品を含む販売準備 → ④集客開始 → ⑤第三者による初回有料購入の事実を確認。下の表はサイト制作面の優先順位であり、商品・販売のゲートに優先しない。詳細は [2026-10-15の商品起点の方針](product-first-strategy-20261015.md)。

| 優先度 | 領域 | 方針 |
| --- | --- | --- |
| 1 | ブランドアイデンティティ | ロゴ、色、文字、動き、語り口の一貫性を整える |
| 2 | トップページ | 世界観を伝えつつ、スクロール負荷を減らし導線を明確にする |
| 3 | 思想・哲学 | 独自の考え方や文章を読める形で蓄積する |
| 4 | 作品・プロジェクト | 記事、動画、アプリ、制作物を見つけやすく集約する |
| 5 | プロフィール | 活動の背景と目的をわかりやすく伝える |
| 6 | ブランド分析 | 指名検索、SNS流入、再訪・関心、問い合わせを継続把握する |

優先順位は初期方針。個別のIssueで利用者への価値、作業量、影響範囲を考慮して更新する。

## 4. 品質管理・変更管理

原則として **Issue → ブランチ → 実装 → テスト → Pull Request → レビュー → マージ** の順で進める。

- **設計レビュー**：ブランド方針に合うか、既存の世界観を壊さないか
- **文章レビュー**：タイトル・コピー・説明の正確性、読みやすさ、表記ゆれを確認
- **表示・操作レビュー**：モバイル幅、各タブ、リンク、ページ遷移、アクセシビリティを確認
- **自動検証**：コード変更を伴う場合は原則 `npm run build` および `npm test` で確認
- **変更履歴**：Issue/PRで意図と結果を残し、既存の `promo/log/` 運用に従う

## 5. 成功指標と見方

**主指標：知り合いや関係者以外の人が、自分のお金でMOUTONの商品を購入したことが決済記録から確認できる最初の1件。** 商品や販売環境の完成を先に行い、本格的な集客はその後に開始する。既存の下表（指名検索、SNS流入等）はブランド指標として維持するが、販売成功の代替にはしない。購入件数・売上・返金や利益は決済記録で確認し、実測のない指標は「未確認」とする。

| 指標 | 見たい変化 | 主な確認方法（導入・設定に応じて） |
| --- | --- | --- |
| 指名検索数 | 「ムートン」などブランド名で探す人の増加 | Google Search Console 等の検索クエリ |
| SNS流入 | SNSからブランドサイトを訪れる人の増加 | GA4 の参照元・UTM付きリンク |
| ファン化 | 再訪、作品の回遊、購読等の継続的関心 | GA4 の再訪・主要導線イベント等 |
| 問い合わせ数 | コンテンツや作品への具体的な関心 | 問い合わせフォーム・メール等の記録 |

数字の現状値・目標値は**未設定**。測定方法が整った後に実測値を基準として決める。単一指標のみで「ファン化」を断定しない。
