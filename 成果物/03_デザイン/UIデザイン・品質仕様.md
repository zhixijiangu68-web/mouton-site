- 基準日：2026-10-15／区分：現行実装の参照点＋追加レビュー規則
- 正本：[DESIGN.md](../../DESIGN.md) ／ [BRAND.md](../../BRAND.md)
- 実値の正本：[site.css](../../site.css)、[home.css](../../home.css)、[reading.css](../../reading.css)、[design-version.css](../../design-version.css)

## 1. 体験の方向性

MOUTONのUIは「雑誌の読みやすさ」と「映画的な入口」を両立させる。表現のためにリンク・メニュー・文章の理解を犠牲にしない。動きは意味のある入口と遷移に限定し、停止可能・低モーション対応にする。

| 場面 | 重視すること | 検証 |
| --- | --- | --- |
| 表紙 | 3テーマを選ぶ視線の流れ、静かな印象 | 最初の表示で操作可能か |
| 記事一覧 | 探せること、分類の明快さ | タイトル検索／絞り込み |
| 記事 | 行長・行間・出典・目次・次の記事 | モバイルでも長文が読める |
| 制作一覧 | 作品名、目的、現状、次の一歩の比較 | 3カードの理解のしやすさ |
| 商品LP | サンプルと価格、販売状態の透明性 | 誤認させないCTA |
| 全体 | 読みやすいコントラストと移動しやすさ | フォーカス、スクロール、リンク |

## 2. デザインシステムの管理

色・余白・文字サイズ・アニメーション速度の**具体的な値はCSSを正本**とし、ここへ架空の値を転記しない。

| 管理対象 | 正本 | 変更時に確認する条件 |
| --- | --- | --- |
| サイト全体の色・余白 | site.css | カラーコントラスト、全ページへの影響 |
| 表紙のレイアウト／演出 | home.css、home.js | 3テーマ・Day/Nightの状態 |
| 記事の可読性・目次 | reading.css、article-share.js | スクロール、本文幅、目次ダイアログ |
| 表示バージョン切替 | design-version.css、design-version.js | ヘッダーに重複コントロールが出ない |
| 画像・サムネイル | [images/README.md](../../images/README.md) | 著作権・容量・代替テキスト |
| サイトの共通ナビ | [src/_includes/](../../src/_includes/) | 日本語・英語・モバイルの整合 |

## 3. コンポーネントの仕様

| ID | UI | 必須の振る舞い | よくある不具合 |
| --- | --- | --- | --- |
| UI-01 | テーマカード | カード全体が適切なページへ移動 | 透明な装飾がクリックを妨害 |
| UI-02 | Day/Night | 状態が視覚で分かり、選択が保持される | 保存不可時の例外、切替時のチラつき |
| UI-03 | メニュー | マウス・タッチ・キーボードで開閉 | フォーカスが失われる、リンクが反応しない |
| UI-04 | 記事検索 | 文字入力と絞り込み結果が一致 | 該当なし表示が不明確 |
| UI-05 | 記事の目次 | 現在章が分かり、閉じて本文へ戻れる | 背面にフォーカスが残る |
| UI-06 | 商品CTA | 発売前の購入は不可能 | テスト用URLに誘導してしまう |
| UI-07 | 言語切替 | 訳があるページへ移動し、ない場合の行き先も明確 | 404やループ |
| UI-08 | 制作カード | 目的・現状・次の一歩が識別可能 | 古い進捗が現状に見える |

## 4. レスポンシブ／アクセシビリティ

- レイアウト確認の最低条件（提案）：390pxのスマートフォン、768px付近のタブレット、1280pxのデスクトップ。特定機種に依存させない。
- 高解像度・拡大率200%に近い閲覧条件でも文章が欠けず、横スクロールが不必要に発生しない。
- 主要リンクをキーボードだけで操作できる。フォーカス位置が視覚で分かる。
- 見出しレベル・ボタン名・フォームラベルが意味を表す。装飾画像は読み上げ対象を調整し、内容画像には代替テキスト。
- prefers-reduced-motionの設定時には強い動きや長い演出を抑える。
- WCAG 2.2 AAを目標として点検するが、現時点の適合を宣言しない。
- Safari実機とChromiumの確認結果は別々に保存する。

## 5. 画面レビュー記録の書式

| 欄 | 記載方法 |
| --- | --- |
| 変更ID | 例：UI-03（対象コンポーネント） |
| 画面／状態 | URL、Night/Day、幅、ログインや同意の有無 |
| 操作 | 再現操作を番号付きで記述 |
| 期待動作 | 画面がどう見え、何が押せるか |
| 実際の動作 | 不一致の有無を事実だけで記す |
| 証跡 | 画像、録画、CIリンク、端末・ブラウザ |
| 修正PR | 対応したPR番号 |
| 判定 | 未確認／要修正／確認済み |

## 6. 改善候補（未実装・優先判断待ち）

1. 初見読者向けの案内文と記事の「読む理由」を短く補う。
2. 制作カードの進捗を最新データに保つ。KIOKU／DIARYの完成誤認を防ぐ。
3. 商品LPの販売準備中ステータスをわかりやすく保つ。
4. 記事冒頭の読みやすさと目次の操作性を定期的に実機点検する。
5. トップを大幅に改変する前に既存の3テーマ・世界観を守る。

デザインの好みと、アクセシビリティ・売上などの成果は別々に評価する。
