## 4. 作業の進め方

1. Issue：課題、対象利用者、現状、変更理由、受け入れ条件、リスクを1件にまとめる。
2. ブランチ：mainから変更用ブランチを切り、対象外のファイルを変更しない。
3. 実装・資料：正本を更新し、必要なら本台帳からリンクする。
4. テスト：コード変更時は npm ci、npm run build、npm test。重要導線はBrowser smokeとiPhone Safariも点検。
5. PR：差分を読み、全必須チェックと秘密情報の混入を確認する。
6. 人間のレビュー：本番販売有効化・法的表記・プライバシー影響は必ず最終承認を受ける。
7. マージ後：変更日と理由を意思決定ログ、結果を運用台帳に記録する。
