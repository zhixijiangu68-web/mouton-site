# MOUTON｜成果物

MOUTON Personal Brand Project の資料を、役割ごとに探せるよう整理したナビゲーションです。

> **このフォルダは資料の入口です。** 既存の `src/`、`docs/`、`BRAND.md`、`REQUIREMENTS.md`、`DESIGN.md` などの正本は移動しません。サイト表示や決済・納品処理を変更せず、各分類の README から参照します。

## 分類

- [00_プロジェクト管理](./00_プロジェクト管理/README.md) — 目的・範囲・進行・品質基準を一か所から参照する。
- [01_ブランド戦略](./01_ブランド戦略/README.md) — MOUTON の思想、表現、価値観、読者像を整理する。
- [02_情報設計](./02_情報設計/README.md) — サイト全体の情報構造、導線、必要機能を整理する。
- [03_デザイン](./03_デザイン/README.md) — 視覚表現・UI/UX・アクセシビリティの判断を整理する。
- [04_実装](./04_実装/README.md) — サイト制作、改修、テスト、デプロイ関連の資料を整理する。
- [05_商品・LP](./05_商品・LP/README.md) — 有料商品、LP、決済導線、納品の企画と検証を扱う。
- [06_コンテンツ](./06_コンテンツ/README.md) — 哲学・科学・記事・動画・SNS投稿を制作・管理する。
- [07_運用](./07_運用/README.md) — アクセス解析、改善、問い合わせ、発売後の運用を扱う。
- [08_意思決定記録](./08_意思決定記録/README.md) — 重要な選択を「なぜ決めたか」まで追えるようにする。
- [09_要件追跡管理](./09_要件追跡管理/README.md) — 要件→設計→実装→テスト→公開判断の対応を追う。

## 使い方

1. 対象の分類を開いて、既存資料のリンクと用途を確認する。
2. 新しい計画書・レビュー記録などは適切な分類に Markdown で保存する。ただしサイトの実装・公開設定・既存設計文書は本来の場所を正とする。
3. 変更は Issue → ブランチ → PR → レビュー → マージで管理する。実装変更時は `npm run build` と `npm test` を確認する。
4. 意思決定は `08_意思決定記録`、要件から検証までの関係は `09_要件追跡管理` に残す。

## 公開リポジトリの注意

このリポジトリは **public** です。完成版の有料PDF・未公開原稿・顧客情報・秘密鍵・環境変数・個人情報をここに置かないでください。特に「清潔感の科学」の販売用本体は**非公開管理／納品**を維持してください。
