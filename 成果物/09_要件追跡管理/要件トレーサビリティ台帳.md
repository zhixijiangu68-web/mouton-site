## 1. ステータスの定義

| ステータス | 意味 |
| --- | --- |
| CODE | 該当機能または制御を実装するソースが存在する |
| PARTIAL | 一部ソースがあるが、外部接続／対象機能の完結には追加作業が必要 |
| BLOCKED | 依存する外部サービスや承認が完了していない |
| VERIFY | ソースはあるが、本番・実機・管理画面の検証が必要 |
| PASS | 明確な手順と証跡があるテストに合格 |
| FAIL | 明確な手順で不具合が再現された |

複数の状態が併存する場合は「CODE／VERIFY」のように書く。本表に新しいPASSは登録していない。

## 6. 変更要求のトレース手順

1. 変更の理由と読者への影響をIssueへ記す。
2. 対象FR/NFR/画面IDを選び、影響するファイルを列挙する。
3. 少なくとも1つの合否判定可能なテストケースを設定する。
4. 実装PRでdiff、ビルドログ、Browser smoke、必要な実機証跡を残す。
5. 承認後に本表の状態と根拠・関連PRを更新する。

## 7. リリース不能となる典型条件

- 支払済み注文を確認できないのに「販売済み」と扱う
- 決済してもPDFを取得できない／期限・権限の検証がない
- 本番URLとテストURLが混在、特商法表示が閲覧不能
- 有料PDFまたは秘密鍵が公開リポジトリに存在
- 必須のCIが失敗、または必要な人間のレビューがない

この台帳はマージや公開の承認そのものではなく、判断に必要な材料を整理する文書である。
