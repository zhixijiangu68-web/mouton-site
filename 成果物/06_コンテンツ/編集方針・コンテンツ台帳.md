- 基準日：2026-10-15／用途：記事・動画・SNS・制作記録の企画から公開後の改善まで
- 既存の正本：[記事ディレクトリ](../../src/articles/) ／ [分類定義](../../src/_data/topics.js) ／ [ブランド原則](../../BRAND.md)
- 素材と履歴：[promo/](../../promo/) ／ [制作一覧データ](../../src/_data/projects.json) ／ [note/](../../note/)

## 1. 編集の目的

「考える」「試す」「作る」の蓄積によって、記事単体でも読者に価値があり、読み終えた後にムートンの別の記録へつながる編集を行う。PVのみを目的に健康・科学の主張を誇張しない。

## 2. 4つの既存コンテンツ分野

| コード | 正式分野 | 主な問い | 望ましいアウトプット |
| --- | --- | --- | --- |
| philosophy | 哲学・生き方 | 人生・自由・意味・自己理解 | 思想家の文脈・反論・問いを含む記事 |
| body | 身体 | 睡眠・体力・外見・行動 | 根拠の種類と限界を説明する記事 |
| work | 仕事・働き方 | 労働・転職・不安・制度 | 制度・統計・意思決定の整理 |
| food | 食事・化学 | 栄養・代謝・食品成分 | 研究の対象と条件が明示された記事 |

別軸で「制作の記録」を持つ：KIOKU、DIARY、MOUTON。作品の進捗は [projects.json](../../src/_data/projects.json) を照合し、制作中／試作中を実装済みとして書かない。

## 3. 記事のワークフロー

| 段階 | 作業 | 成果物 | 終了条件 |
| --- | --- | --- | --- |
| IDEA | 読者の問いと独自の切り口を記録 | 企画タイトル・対象読者・疑問 | 「何を明らかにするか」が明記 |
| RESEARCH | 一次資料、公的文書、研究の確認 | 出典リストと主張ごとの根拠 | 引用先が実在し、対象・限界を把握 |
| OUTLINE | 論旨と記事の構造 | 見出し案、問い、結論の条件 | 読み手の誤解が予想できる |
| DRAFT | 本文を書く | src/articles の記事原稿 | 事実・考察・個人の意見を分離 |
| REVIEW | 校閲・法務・SEO確認 | 差分とチェック記録 | 出典、PR、医療表現、リンクに問題なし |
| TEST | 生成・回帰テスト | build/test・ブラウザ記録 | テスト成功、スマホ表示確認 |
| PUBLISH | PRレビュー・公開 | URL・公開日 | デプロイ後にページ到達確認 |
| LEARN | 検索流入・読了・回遊を評価 | 改訂案 | 実測値と改善の仮説を分離 |

## 4. 記事原稿の品質基準

- タイトル：刺激があっても内容以上の効果・結論を断言しない。
- 導入：「誰の疑問か」「この記事で扱う範囲」を示す。
- 根拠：科学記事では研究デザイン、対象、結果、限界、反例を整理する。
- 引用：自分で確認した出典へたどり着ける。外部の全文転用を避ける。
- 独自性：研究の要約だけでなく、考察と問いを区別して示す。
- 表記：PR・アフィリエイトと健康上の注意は必要な位置に置く。
- 画像：出所・利用条件・肖像や権利の確認、内容を表すalt。
- UI：スマートフォンで見出し、要約、本文、参考文献が崩れない。
- 英語：翻訳済みかどうかを確認し、存在しない英語記事へリンクしない。
- 更新：科学的理解や商品状態が変われば日時と理由を記す。

## 6. 記事管理レコードの推奨項目

| フィールド | 記録例／規則 |
| --- | --- |
| content_id | E-001など、重複しないID |
| slug | src/articles/のファイル名（拡張子除く） |
| title | 読者が読むタイトル |
| category | philosophy／body／work／food等、現行分類と照合 |
| intent | 問い・検索意図・主張の範囲 |
| sources | 出典URLと確認日。引用内容を丸写ししない |
| status | IDEA／RESEARCH／DRAFT／REVIEW／TEST／PUBLISHED |
| created／updated | 記録日・公開日・最終改訂日 |
| owner | 担当者 |
| PR／URL | 差分・公開URL |
| review | 医療・PR・法務・翻訳・画面テストの結果 |

## 7. 週次編集カレンダーのひな形

| 枠 | 役割 | 初期運用例（確定日程ではない） |
| --- | --- | --- |
| 企画 | 過去記事の反応・疑問を収集 | 企画案を2件整理 |
| 取材・調査 | 一次資料の裏取り | 重点記事の出典を確認 |
| 制作 | 本文・画像・動画 | 最も価値の高い1本に集中 |
| 公開 | PR・テスト・告知 | 準備が整ったものだけ公開 |
| 振り返り | データと定性評価 | 次の改善を1〜3件選ぶ |

実際の制作ペースは時間と品質をもとに決定し、上の例を必達目標にしない。
