## 1. 目的と観測する領域

| 領域 | 目標とする変化 | 計測の正本 |
| --- | --- | --- |
| 発見 | 初見ユーザーが記事に到達 | GA4、Search Console |
| 興味 | 記事・制作を回遊 | GA4のページ別・導線別分析 |
| 信頼 | 再訪、作品への関心、問い合わせ | GA4＋実際の問い合わせ記録 |
| 商品関心 | LPの閲覧とサンプル利用 | GA4 |
| 有料購入 | 支払い済み注文と返金、粗い利益 | Stripeの本番記録 |
| 配信 | 本人が同意した登録完了 | 将来契約するメール配信サービス |
| 品質 | 不具合・対応時間・安全性 | GitHub Issues／Actions／Worker運用ログ |

ブランド価値と売上を単一スコアにしない。イベントのクリック数を受注と表現しない。

## 5. 計測接続の確認手順

1. GA4の権限者が測定IDとウェブストリームを照合する。
2. Tag AssistantとDebugViewでページ・LP・サンプルの各イベントを検証する。
3. 同一操作で同じイベントが二重に飛ばないことを確認する。
4. Search Consoleのドメイン所有権・sitemap・検索パフォーマンスを確認する。
5. SNS投稿のUTM規約を統一し、テスト訪問で実際に流入元を確認する。
6. 決済・返金はStripe、登録は配信サービスの管理画面で確認する。
7. 実測値・抽出日時・対象期間・データの限界をセットで記録する。

## 6. 障害とサポートの一次対応

| 重大度 | 具体例 | 最初の処置 |
| --- | --- | --- |
| SEV-1 | 誤請求、非公開PDFの漏えい、認証回避 | 販売停止と影響範囲確認を優先、秘密情報を無効化 |
| SEV-2 | 本番購入済みだがPDF未着、フォームが情報を送信できない | 取引の照合・再送方針・顧客連絡 |
| SEV-3 | 記事やメニューのリンク切れ、モバイルの重大な崩れ | 再現記録→最小修正→回帰テスト |
| SEV-4 | 誤字、見た目の軽微な差異 | Issueで優先度を判断 |

顧客のメールアドレス、購入詳細、秘密鍵は公開Issueに貼らず、公開可能な事象IDだけを参照する。
