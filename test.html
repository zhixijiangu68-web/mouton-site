  1. IDS と IPS の違いについて、記事の内容と合うものはどれか。

    1. IDS は機械の中だけを見て、IPS はネットワークだけを見る。
    2. 違いは置き方で決まり、通信のコピーを見るなら知らせることしかできない。
    3. IDS はシグネチャ型、IPS はアノマリー型の検知を使う。
    4. IPS は IDS の古い呼び方で、いまはほぼ同じものを指す。
    答えと解説

    正解：違いは置き方で決まり、通信のコピーを見るなら知らせることしかできない。（2）

    IDS は見つけて知らせる仕組みで、通信の通り道に入って止めるのが IPS。通信のコピーを受け取って見る置き方なら、知らせることしかできない。Google Cloud IDS は検知と警告だけで、止めないと説明している。

  2. NIST SP 800-94 が挙げる検知の方式のうち、「ふだんからのずれを見る」ものはどれか。

    1. シグネチャ型
    2. ステートフルプロトコル解析
    3. アノマリー型
    4. サンドボックス型
    答えと解説

    正解：アノマリー型（3）

    SP 800-94 は、シグネチャ型（知られた攻撃の型と照らす）、アノマリー型（ふだんからのずれを見る）、ステートフルプロトコル解析（通信の決まりに合っているかを見る）の3つに分けている。サンドボックス型は IPA の手引書の5つの分け方に入っているもの。

  6. Zeek について、記事の内容と合うものはどれか。

    1. TLS 1.3 でも、証明書は x509.log に必ず残る。
    2. 通信を止めることが主な役目の IPS である。

    答えと解説

    正解：通信をプロトコルごとのログに書き出し、何が起きたかを細かく残すのが得意だ。（3）

    Zeek は通信をプロトコルごとのログ（接続・DNS・HTTP・TLS など）に書き出し、スクリプトで監視の方針を書く。ライセンスは BSD。TLS 1.3 では証明書が暗号化されるので、x509.log は出ない。

  7. 暗号化された通信の扱いについて、記事の内容と合うものはどれか。

    1. どの製品も、設定しなくても中身まで見られる。
    2. Google Cloud IDS は、暗号化された中身を復号して調べる。
    3. 復号しない製品は、暗号化された通信について何も分からない。
    4. 復号する、復号せずに通信の特徴で見る、中身は見えない、の3通りに分かれた。
    答えと解説

    正解：復号する、復号せずに通信の特徴で見る、中身は見えない、の3通りに分かれた。（4）

    NGFW の検査や ExtraHop は復号して見る。Cisco の EVE や Corelight などは復号せずに通信の特徴で見る。Google Cloud IDS は中身が見えない。復号するには、検査する機器の証明書を端末に信頼させる手間と、処理の重さがついてくる。
