SIEM とは何か。攻撃を止める道具ではなかった

  1. NIST・Gartner・ASD の ACSC などの手引きによる SIEM の定義について、記事の内容と合うものはどれか。

    1. どの定義も、怪しい通信を自動で遮断することを SIEM の中心の役目にしている。
    2. どの定義も、ログを集めることと、分析して人に示すことを含んでいる。
    3. 定義はログの長期の保存だけを扱い、リアルタイムの分析は含んでいない。
    4. 定義は製品ごとにばらばらで、共通する点は見つからなかった。
    答えと解説

    正解：どの定義も、ログを集めることと、分析して人に示すことを含んでいる。（2）

    三つの定義に共通するのは、ログを集めることと、分析して人に示すことだった。どの定義にも「攻撃を遮断する」は入っておらず、止める動きは SOAR のプレイブックや別の機器、人の側にある。

    記事のこの節を読む

  2. SIEM の「正規化」について、記事の説明と合うものはどれか。

    1. 量の多いログを間引いて、保存の費用を下げること。
    2. アラートの重さを、すべて同じ段階にそろえること。
    3. 機器ごとに違うログの項目を、送り元の IP アドレスやユーザー名などの共通の項目に当てはめ直すこと。
    4. 古いログを消して、新しいログだけを残すこと。
    答えと解説

    正解：機器ごとに違うログの項目を、送り元の IP アドレスやユーザー名などの共通の項目に当てはめ直すこと。（3）

    ファイアウォールのログ、Windows のログオンのイベント、Web サーバーのアクセスログは、項目の名前も並びも違う。Wazuh はこれを共通の項目に当てはめ直し、Elastic Security は ECS という共通の項目の決まりを使う。同じ検索やルールを、ログの出どころを気にせずに使うためだ。

    記事のこの節を読む

  3. 2025年の共同の手引き「Priority logs for SIEM ingestion」について、記事の内容と合うものはどれか。

    1. ログの源をおおよそ優先の順に並べ、最初に EDR のログを置いている。
    2. ファイアウォールと DNS のログを、量が多いので最も優先するとしている。
    3. すべてのログを同じ優先度で、一度に取り込むことを勧めている。
    4. クラウドのログは対象の外で、社内の機器のログだけを扱っている。
    答えと解説

    正解：ログの源をおおよそ優先の順に並べ、最初に EDR のログを置いている。（1）

    手引きは EDR のログを最初に置き、ネットワーク機器、ドメインコントローラーなどと続ける。クラウドのログも含まれる。ファイアウォールや DNS のログは量が多く、その量が情報の大切さを覆い隠すことがあると書かれている。優先の高いものから入れ、取り込みが続いているかを定期的に確かめることを勧めている。

    記事のこの節を読む

  4. MITRE ATT&CK の総当たり（T1110）の検知の例が、ログイン失敗の回数だけでなく、そのあとの成功も見ているのはなぜか。記事の説明と合うものを選ぶ。

    1. 成功のログのほうが、失敗のログより量が少なく、保存しやすいから。
    2. 失敗が続くだけなら打ち間違いの可能性もあるが、失敗のあとの成功は、推測が当たった可能性を示すから。
    3. Windows では、ログオンの失敗がログに残らないから。
    4. 成功のログがあれば、攻撃をその場で自動で止められるから。
    答えと解説

    正解：失敗が続くだけなら打ち間違いの可能性もあるが、失敗のあとの成功は、推測が当たった可能性を示すから。（2）

    失敗が続くだけなら、推測が外れ続けているか、誰かがパスワードを忘れているだけかもしれない。失敗のあとに成功があると、推測が当たった可能性が出てくる。1件ずつでは分からないことが、順番をつなげると見えてくるのが相関分析の考え方だ。

    記事のこの節を読む

  5. パスワードスプレー（T1110.003）が、アカウントごとに失敗を数えるルールをすり抜けやすい理由として、記事の内容と合うものはどれか。

    1. ログオンの失敗の記録を、攻撃者がその場で消してしまうから。
    2. 失敗が一度もログに記録されないから。
    3. DNS のログにしか記録が残らないから。
    4. 少しのパスワードを多くのアカウントに試すので、一つのアカウントあたりの失敗が少ないから。
    答えと解説

    正解：少しのパスワードを多くのアカウントに試すので、一つのアカウントあたりの失敗が少ないから。（4）

    パスワードスプレーは、よく使われるパスワードを一つか少しだけ用意し、多くの違うアカウントに試す。ロックを避けるためで、一つのアカウントあたりの失敗は1回か2回しかない。ATT&CK の検知の例は、時間の幅の中で多くのアカウントにわたる失敗を見る。

    記事のこの節を読む

  6. 製品に最初から入っている検知ルールについて、Elastic の手引きの書き方と合うものはどれか。

    1. 有効にすれば調整は要らず、そのまま使い続けられる。
    2. 調整と雑音の削減は最後の段階で、一度すませれば終わる。
    3. 調整と雑音の削減は、ずっと続くものとされている。
    4. 標準のルールは使わず、すべて自分で書くことを前提にしている。
    答えと解説

    正解：調整と雑音の削減は、ずっと続くものとされている。（3）

    Elastic の手引きは、保守されたルールの一式を有効にすることを流れの3番目に置き、調整と雑音の削減は最後の段階ではなく、ずっと続くものだと書く。ルールが広すぎるなら問い合わせやしきい値を変え、環境に特有の安全な動きに反応するなら例外を足す。

  7. 2022年の研究「99% False Positives」が示したこととして、記事の内容と合うものはどれか。

    1. 実務者が誤検知と呼ぶものの多くは、ルールどおりに鳴ったが、その環境では正当な動きだった。
    2. SIEM のアラートの99%が誤りだと、大規模な測定で確かめられた。
    3. 誤検知は、ルールの書き間違いだけが原因だった。
    4. アラートの数を減らせば、アナリストの負担の問題はなくなるとした。
    答えと解説

    正解：実務者が誤検知と呼ぶものの多くは、ルールどおりに鳴ったが、その環境では正当な動きだった。（1）

    研究は、誤検知と呼ばれるものの多くが、厳密には誤りではなく「benign trigger（害のない引き金）」だったことを示した。ルールが間違っているならルールを直し、ルールは正しいが文脈を知らないなら文脈を足す、という直し方の違いにつながる。記事は割合の数字を使っていない。

  8. AI と SOC アナリストの関係について、記事が資料から読めるとしていることはどれか。

    1. 公的な手引きは、AI があれば人の監視は要らないとしている。
    2. 長い期間のデータで、AI だけで SOC が回ることが確かめられている。
    3. Gartner は、数年のうちに自律した SOC ができると予測している。
    4. 公的な手引きは技能を持つ人による監視と改善を前提にしており、仕事の中身が変わる見通しまでが読める。
    答えと解説

    正解：公的な手引きは技能を持つ人による監視と改善を前提にしており、仕事の中身が変わる見通しまでが読める。（4）

    2025年の手引きは、技能を持つ人による監視・定期的な試験・改善の繰り返しが要るとし、費用にも人を雇い育てる費用を入れている。Gartner の2024年12月の予測の題は「自律した SOC は、これからもできない」。ただしどれも見通しで、長い期間のデータではない。

  9. SIEM と EDR の関係について、共同の手引きの描き方と合うものはどれか。

    1. EDR が広まったので、SIEM はもう使われなくなったとしている。
    2. EDR は、SIEM に入れるログの源の一つで、優先の最初に置かれている。
    3. EDR と SIEM は、同じ製品の別の名前だとしている。
    4. EDR のログは量が多いので、SIEM に入れないよう勧めている。
    答えと解説

    正解：EDR は、SIEM に入れるログの源の一つで、優先の最初に置かれている。（2）

    手引きは、SIEM に入れるログの優先の最初に EDR のログを置いた。EDR と SIEM は取って代わる関係ではなく、EDR が SIEM にログを渡す関係として描かれている。「SIEM は XDR に置き換わった」と言えるだけの公的な調査も、記事では見つからなかった。

  10. 自分のラボで SIEM に触れる方法について、記事の内容と合うものはどれか。

    1. Splunk Free は1日500MBまで取り込め、アラートの機能も制限なく使える。
    2. 学習のためなら、他人のサービスにログインを試してログを集めてもよい。
    3. Wazuh の手引きは、仮想マシンを使い、最初の設定のあとにスナップショットを取ることを勧めている。
    4. 学習用の公開のデータはなく、ログは自分で攻撃を起こして作るしかない。
    答えと解説

    正解：Wazuh の手引きは、仮想マシンを使い、最初の設定のあとにスナップショットを取ることを勧めている。（3）

    Wazuh の概念実証のガイドは、ラボに仮想マシンを使い、最初の設定のすぐあとにスナップショットを取ることを勧める。Splunk Free は1日500MBまでだが、作ったアラートは動かない。BOTS のような学習用のデータもある。試すのは自分の環境の中だけで、他人のシステムに許可なく試すことは法律に触れるおそれがある。
