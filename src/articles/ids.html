侵入されたことに、自分で最初に気づけた組織は52%だった。Mandiant が2025年に対応した事案のまとめ（M-Trends 2026）の数字だ。残りは、外から知らされて初めて気づいている。侵入から見つかるまでの日数の中央値は14日で、前の年の11日より延びた[1]。

中から気づくための道具の一つが、IDS（侵入検知システム。通信やログを見て、攻撃らしいものを知らせる仕組み）だ。僕は専門家ではなく、セキュリティを勉強している一人として、IDS を調べ直した。この1本目では、IDS とは何か、なぜ大事かを書く。

先に言うと、IDS は置けば守ってくれる箱ではなかった。見つけて知らせる道具で、知らせを誰かが読んで、初めて働く。

IDS について、4本に分けて書いている。1 IDS とは何か、なぜ大事か／2 無料の道具／3 商用とクラウドの製品／4 選ぶとき・運用するとき。

IDS は見つけて知らせる仕組みで、止めるのは IPS の役目だった

IDS の基本の文書は、米国の NIST（国立標準技術研究所）の SP 800-94 だ。いま有効なのは2007年2月の版だ。IDS と IPS（侵入防止システム。通信の通り道に入って、攻撃らしいものを止める仕組み）をまとめて、IDPS と呼んでいる[2]。2012年に改訂の案が出たが、最終版にならず、2022年7月に取り下げられた[6]。IPA が日本語訳を出している[7]。

この文書は、IDPS を見る場所で4つに分けている[2]。

  • ネットワーク型：ネットワークの通信を見る
  • 無線：無線の通信を見る
  • ネットワークの振る舞いの分析：通信の量や流れの変化を見る
  • ホスト型：1台の機械の中を見る

検知の方式は3つに分けている[2]。

  • シグネチャ型：知られた攻撃の型と照らす
  • アノマリー型：ふだんからのずれを見る
  • ステートフルプロトコル解析：通信の決まりに合っているかを見る

IPA の制御システム向けの手引書は、方式を5つに分けている。シグネチャ型・ルールベース・ステートフルプロトコル解析・振る舞い検知型・サンドボックス型（怪しいファイルを隔離した環境で動かして確かめる）だ[8]。分け方は文書によって違う。それぞれの方式が何を得意とし、何を見逃しやすいかは、SP 800-94 の本文で確かめてから書き足す。

違いは、製品の名前ではなく置き方で決まる

通信のコピーを受け取って見るなら、知らせることしかできない。通信の通り道に入るなら、止められる。Google Cloud IDS は、通信のコピーを作って調べる仕組みだ。検知と警告だけを行い、止めるには別の製品を使うと説明している[3]。

近い道具との違いを、言い切れる範囲で並べると次のようになる。

IDS と近い道具（この記事での使い分け）
道具見るもの止めるか
ファイアウォール決めた規則（宛先・ポートなど）規則で通す・通さないを決める
IDS（ネットワーク型）通信の中身や手順の怪しさ止めない。知らせる
IPSIDS と同じ通り道にいて止める
IDS（ホスト型）1台の機械のログ・ファイル・設定製品によって、その機械で対処する
NDR内側の通信の振る舞い（多くは通信のコピー）ほかの仕組みと連携して対処する
SIEMIDS を含む色々なログ止めない。集めて突き合わせる

NDR（ネットワークの検知と対応）や SIEM（ログを集めて分析する仕組み）の定義は、メーカーによって少しずつ違う。この表は、この記事を読むための目安だ。

侵入に自分で気づけた組織は52%で、気づくまでの中央値は14日だった

冒頭の数字をもう少し見る。M-Trends 2026 では、自分で最初に気づけた割合は52%で、前の年の43%から増えた。それでも、半分近くは外からの知らせで気づいている。気づくまでの日数の中央値は14日だ。中央値は、並べたときに真ん中に来る値なので、半分はそれより長い[1]。

IBM の Cost of a Data Breach の2026年版では、侵害を特定して封じ込めるまでの平均は247日だったと報じられている[9]。14日と247日は、矛盾ではない。M-Trends は、Mandiant が対応した事案の中央値だ。IBM は、調査した組織のデータ侵害の平均だ。数え方も対象も違うので、「調べ方によって、数週間から8か月」と幅で受け取るのが正確だと思う。

M-Trends 2026 は、最初の侵入の経路も並べている。1位は脆弱性（ソフトの弱点）の悪用で32%、6年続けて1位だった。2位は電話の声を使って人をだます手口で11%、3位は前に受けた侵害を足がかりにしたもので10%だった[1]。入口が弱点の悪用なら、通信の中にその跡が残りうる。IDS が見るのは、そこだ。

日本では、入口の多くが外とつながる境目だった

IPA の「情報セキュリティ10大脅威 2026」の組織編の1位は、ランサム攻撃による被害だった。1位は11年続いていて、4位は「システムの脆弱性を悪用した攻撃」だった。10大脅威は、前の年の事故や攻撃から候補を選び、約250人の選考会の投票で決めている[10]。警察庁によると、2025年上半期のランサムウェアの被害の報告は116件で、そのうち77件が中小企業だった。感染経路が分かったもののうち、VPN（外から社内のネットワークに安全につなぐ仕組み）の機器が62.2%だった。リモートデスクトップと合わせると8割を超える[11]。

境目を通る通信を見ることにも、入られたあと中で広がる動きを見ることにも、IDS の出番がある。ただし、これは感染経路の統計で、IDS があれば防げたと言える数字ではない。

基準は、見張ることと判断することを別の項目にしていた

CIS Controls v8.1 の Control 13 は、ネットワークの監視と防御の項目だ。侵入検知はホスト型（13.2）とネットワーク型（13.3）、侵入防止は 13.7 と 13.8 と、別々に置いている。13.3 は、最低限の対策の次の段階（実装グループ2）に入っている[5]。ネットワーク型とホスト型は、見る場所が違う。暗号化で見えなくなる部分は、端末からの記録で埋めると Security Onion の文書は書いている[4]。

NIST の Cybersecurity Framework 2.0 では、検知（DE）が2つに分かれている。継続的な監視（DE.CM）と、見つけたものの分析（DE.AE）だ[12]。見張ることと、見つけたものを分析して判断することが、別の項目として並んでいる。

IDS は、見つけたものを誰かが読んで初めて働く

まとめると、IDS は見つけて知らせる仕組みで、止めるのは IPS だ。その違いは置き方で決まる。侵入に自分で気づけた組織は52%で、外から知らされて気づく組織もまだ多い。基準も、見張ることと、見つけたものを判断することを分けている。

どの道具があるかは、2本目（無料の道具）と3本目（商用とクラウド）に書いた。選ぶときと置いたあとに見るところは、4本目に書いた。

この記事の事実は、公式の資料を検索で確かめたもので、原典のページを一つずつ開いて確かめ直している途中だ。下書きと資料の照らし合わせには AI を使い、公開の前にムートンが全文を読む決まりにしている。特定の製品を勧めるものではない。

自分の環境で、侵入に最初に気づくのは、中の誰かだろうか。それとも、外からの知らせだろうか。
