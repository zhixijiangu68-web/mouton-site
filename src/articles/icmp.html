ICMP は、IP のパケットが届かなかったことや途中で捨てられたことを、送り元に知らせる仕組みだ。ping と tracepath はこの知らせで届くかどうかと道筋を調べ、OS は同じ知らせで経路の途中の MTU（一度に運べる大きさ）を知る。だから ICMP を全部止めると、小さな通信は通るのに大きな通信だけが止まることがある。ルーティングの記事に出てきた「時間切れ（Time Exceeded）」と tracepath の続きとして、RFC と説明書で確かめた。例のアドレスは文書用の範囲とプライベートアドレスだけを使う[1]。

ICMP は、IP の失敗を送り元へ知らせる

ICMP（Internet Control Message Protocol）は、IP の通信で起きた問題を、問題が起きた場所から送り元へ返すための決まりだ。RFC 792 は、ICMP を IP の一部で、どの IP の実装も持たなければならないものとしている[2]。IPv6 には同じ役目の ICMPv6 があり、RFC 4443 が決めている[3]。

ICMP は IP を確かなものにする仕組みではない。RFC 792 は、パケットが届くことも、知らせが返ることも約束されない、と書いている[2]。知らせが返らないことは、問題がないことを意味しない。

知らせには、それを引き起こしたパケットの頭の部分が入る。IPv4 では元の IP ヘッダーとそのあとの8バイトで、TCP や UDP ならここにポート番号が入るので、受け取った OS はどの通信への知らせかを見分けられる[2]。知らせが知らせを呼び続けないよう、ICMP のエラーの知らせや、ブロードキャストあてのパケットへの返事としては、エラーの知らせを送らない決まりもある[4]。

よく出る知らせは、四つ

ICMP の知らせは、種類（Type）と、その中の細かい理由（Code）の二つの数で表す。ICMPv6 では、Type が 0〜127 ならエラーの知らせ、128〜255 なら情報の知らせだ[2][3]。よく使うのは次の四つになる。

主な ICMP の知らせと、IPv4・IPv6 での番号
知らせIPv4（ICMP）IPv6（ICMPv6）意味
Echo Request／Echo ReplyType 8／Type 0Type 128／Type 129届くかの確かめ（ping）
Destination UnreachableType 3（Code 0〜5）Type 1（Code 0〜6）宛先に届けられない
Time ExceededType 11Type 3通れるルーターの数の上限を使い切った、など
Packet Too BigType 3 の Code 4Type 2次のリンクの MTU より大きい

IPv4 には Packet Too Big という独立した種類がなく、Destination Unreachable の Code 4 が同じ役目をする[2]。

ping は、Echo の往復で届くかと時間を測る

ping は Echo Request を送り、相手が返す Echo Reply までの往復の時間を測る[5]。Echo に応える機能は、RFC 1122 がすべてのホストに、RFC 4443 がすべての IPv6 のノードに求めている[4][3]。返事には受け取ったデータをそのまま入れ、送り手は識別子と通し番号で、どの問い合わせへの返事かを突き合わせる[2]。

iputils の ping は標準で56バイトのデータを送り、ICMP のヘッダー8バイトと合わせて64バイトになる。返事が一つもなければ終了コード 1 で終わる[5]。

ただし、返事がないことは、相手がいないことと同じではない。Linux には Echo Request をすべて無視する設定（icmp_echo_ignore_all）があり[6]、RFC 4890 は、IPv4 ではスキャンの危険を減らすためにファイアウォールで Echo Request を落とすことがよく行われてきた、と書いている[7]。

届かない理由は、Destination Unreachable のコードに出る

宛先に届けられなかったとき、ルーターや宛先のホストは Destination Unreachable を返し、Code で理由を伝える。RFC 792 の Code は、0 がネットワークに届かない、1 がホストに届かない、2 がプロトコルが使えない、3 がポートが使えない、4 が分ける必要があるのに分けるなという印（DF）が立っている、5 がソースルートの失敗で、0・1・4・5 はルーターから、2・3 は宛先のホストから返る[2]。

「ポートが使えない」は、宛先までは届いたという意味でもある。RFC 4443 は、UDP のように受け手がいないことを伝える手段をほかに持たない決まりでは、受け手のいないポートあてのパケットにこの知らせを返すべきだとしている[3]。tracepath は UDP でプローブを送り、説明書の表では、!N・!H・!P がネットワーク・ホスト・プロトコルに届かないこと、!A が管理上の禁止にあたり、宛先に着いたことを示す reached が「接続を断られた（ECONNREFUSED）」にあたる[8]。

Time Exceeded で、途中のルーターが分かる

Time Exceeded は、パケットが通れるルーターの数の上限（IPv4 の TTL、IPv6 の Hop Limit）を使い切ったときに返る知らせで、tracepath や traceroute はこれで途中のルーターをたどる。RFC 4443 では、Hop Limit を 0 にしたルーターはパケットを捨て、Code 0 の Time Exceeded を返さなければならない[3]。Code 1 は別の意味で、断片に分けられたパケットを時間内に組み立て直せなかったことを表す[2]。

tracepath は1行ごとに、プローブの上限の値、返事をしたルーター、往復の時間を並べ、経路の MTU が変わったところで pmtu の値を出す。最後の行には、見つけた経路の MTU とホップの数をまとめる[8]。

途中の行が抜けても、そこで経路が切れているとは限らない。RFC 4443 は、機器が送るエラーの知らせの速さに上限を設けることを求めている[3]。Linux の IPv4 では標準で Destination Unreachable・Time Exceeded などが制限の対象で、同じ相手への知らせは1000ミリ秒の間隔を空ける[6]。抜けた行が表すのは、知らせが返らなかったことだけだ。

経路の MTU は、Packet Too Big で知る

経路の MTU（Path MTU）は、経路の途中にあるリンクの MTU のうち、いちばん小さいものだ。RFC 1191 の Path MTU Discovery（PMTUD）では、送り手は DF を立てて送り、途中のルーターは次のリンクに対して大きすぎるパケットを捨てて Destination Unreachable の Code 4 を返す。RFC 1191 は、このとき使われていなかった欄に次のリンクの MTU を入れることを決め、送り手はその値で見込みを下げる[9]。

IPv6 では、途中のルーターはパケットを分けず、分けるのは送り元だけだ[10]。大きすぎるパケットには Packet Too Big が返り、次のリンクの MTU が入る[3]。IPv6 のリンクは1280バイト以上の MTU を持つ決まりなので[10]、RFC 8201 は、1280 より小さい値を知らせる Packet Too Big は捨てるとしている[11]。

偽の知らせへの備えもある。RFC 1191 と RFC 8201 は、Packet Too Big を理由に見込みを上げてはならないとし、古いパケットや、妨害のために差し込まれた偽物かもしれないことを理由に挙げる。見込みを上げられるかを試すのは知らせから5分以上あとで、10分を勧めている[9][11]。

ICMP を全部止めると、大きな通信だけが止まる

PMTUD は大きすぎたという知らせに頼っているので、その知らせが届かないと、送り手は大きなパケットを送り続け、通信が止まる。RFC 2923 はこれを「ブラックホール」と呼び、原因の一つに、ICMP をすべて止めるよう誤って設定されたファイアウォールを挙げている[12]。

RFC 2923 によると、接続の最初のやりとりは小さいので通り、ping も通る。大きなデータのパケットだけが届かず、接続は最後にタイムアウトで切れる[12]。RFC 8201 も、IPv6 で ICMPv6 が止められると、TCP の接続は張れるのにデータを送る段階で止まる、と書いている[11]。見分けるには、ふつうの ping、MTU いっぱいの ping、同じ大きさで DF を立てた ping を比べ、最後のものだけ失敗するかを見る[12]。iputils の ping では、-s でデータの大きさを、-M do で DF を立てる送り方を選べる[5]。

手当ては、まず止めている設定を直すことだ[12]。送り手の側には、知らせに頼らない仕組みもある。RFC 4821 の方法は、TCP などが少しずつ大きなパケットを試し、届いたかどうかで経路の MTU を見つけるもので、ICMP を使わずに PMTUD を置き換えることもできる[13]。RFC 8899 は同じ考え方を UDP のような決まりに広げた[14]。Linux の TCP では tcp_mtu_probing で、ブラックホールを見つけたときだけ試す（1）か、いつも試す（2）かを選べる[6]。

止めてよい ICMP と、止めてはいけない ICMP

ICMP を止めるかどうかは、種類ごとに決める。RFC 4890 は、ICMPv6 は IPv6 が動くのに欠かせないので、IPv4 の ICMP の止め方はそのまま当てはまらないとし、ファイアウォールを通り抜ける ICMPv6 の扱いを種類ごとにまとめている[7]。

RFC 4890 の勧め（ファイアウォールを通り抜ける ICMPv6）
扱い主な知らせ
止めてはいけないDestination Unreachable（すべての Code）、Packet Too Big、Time Exceeded（Code 0）、Parameter Problem（Code 1・2）、Echo Request・Echo Reply
ふつうは止めないTime Exceeded（Code 1）、Parameter Problem（Code 0）
理由がなければ止めるNode Information Query・Response（Type 139・140）、Router Renumbering（Type 138）、実験用の Type 100・101・200・201

Echo が「止めてはいけない」に入るのは、IPv6 のアドレスの空間がとても広く、推測しやすい割り当て方をしていなければ、スキャンで相手を探すのが IPv4 よりずっと難しいからだ、と RFC 4890 は説明している[7]。Neighbor Solicitation など同じリンクの中で使う知らせは、ルーターを越えないので通り抜けの規則では特別に扱わなくてよいが、ファイアウォール自身あてのものを止めると、その機器が IPv6 で通信できなくなる[7]。IPv4 では、少なくとも Destination Unreachable の Code 4 を止めると PMTUD が壊れ、ブラックホールになる[12]。

偵察とトンネルは、ふだんとの違いで見つける

ICMP は、攻撃の下調べと隠れたやりとりにも使われる。攻撃の手口をまとめた MITRE ATT&CK は、ネットワークの中のほかの機器を探す手口（T1018）の例に ping を挙げている[15]。また、アプリケーションの層ではない決まりでの通信（T1095）の例に ICMP を挙げ、TCP や UDP ほど見張られていないことが多く、通信を隠すのに使われうる、と書いている[16]。RFC 4443 では、Echo に入れられるデータの量に制限がない[3]。RFC 4890 は、エラーの知らせの中身を使った隠れたやりとりには、中身が正当な通信に対応しているかを深く調べることで備えられる、としている[7]。

ログでの手がかりは、ふだんの形からのずれだ。一つの機器から多くのアドレスへの Echo Request が短い時間に並ぶこと、外の一つのアドレスとの Echo が長く続くこと、データの大きさがふだんの ping と違うこと、などが候補になる。どれもそれだけで攻撃とは決まらず、監視の道具も同じ形の通信を出すので、ふだんの量と相手を知っておくことが前提だ。tcpdump では icmp[icmptype] != icmp-echo and icmp[icmptype] != icmp-echoreply で ping 以外の ICMP だけを選べる[17]。

偽のエラーの知らせで TCP の接続を切ったり遅くしたりする攻撃もある。RFC 5927 は対策として、知らせの中の TCP の通し番号が、送ったがまだ確認されていない範囲にあるかを確かめる方法を挙げ、Linux には長く入っているとしている[18]。

自分の環境で確かめる

ICMP の観察は、自分の機器と自分のネットワークの中だけで行う。他人の機器やネットワークへ、許可なく大量の ping や調べるためのパケットを送らない。

家のルーターが 192.168.1.1 なら、ping -c 4 192.168.1.1 で4回だけ送って往復を見る[5]。IPv4 で MTU が1500のリンクなら、IP のヘッダー20バイトと ICMP のヘッダー8バイトを引いた1472バイトが、分けずに送れるデータの上限になる。ping -M do -s 1472 -c 3 192.168.1.1 は1500バイトのパケットになり、-s 1473 にすると、DF を立てているので手元の OS が大きすぎるとして送らない[5]。IPv6 は固定のヘッダーが40バイトなので[10]、上限は1452バイトになる。経路の MTU は、tracepath の pmtu の表示で見られる[8]。

ブラックホールは、ラボで作ると分かりやすい。Linux のネットワーク名前空間は、経路表・ファイアウォールの規則・ネットワーク機器をそれぞれに持つ、ネットワークの仕組みの写しで[19]、1台のパソコンの中に送り手・ルーター・受け手を作れる。文書用のアドレス（192.0.2.0/24 など）を振り、ルーターと受け手のあいだだけ MTU を小さくして、ラボのルーターで Destination Unreachable の Code 4 だけを落とす。ping と大きな転送を比べれば RFC 2923 の形を手元で試せ、送り手の tcp_mtu_probing を 1 にしたときの違いも比べられる[6]。tcpdump で icmp を見ていれば、知らせが行き来する様子と、落とされて届かない様子が分かる[17]。
