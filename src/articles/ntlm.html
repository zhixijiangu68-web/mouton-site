NTLM は、サーバーが出したチャレンジ（その場かぎりの値）に、パスワードから作ったハッシュで計算した応答を返す、Windows の認証方式だ。応答はパスワードそのものではなくハッシュから作られるので、ハッシュを盗まれれば本人として認証でき、Windows が外の SMB や WebDAV に自動で送る認証からは、応答が漏れる。SMB は TCP・UDP の記事のポートでいう TCP の 445 番を使い、その外向きの通信は ファイアウォールの記事の「出ていく通信も止める」の対象になる。試すのは自分の環境と、許された演習の中だけにする。

Windows の認証は、Kerberos が先で、NTLM は代わりに使われる

Active Directory のドメインでは Kerberos が優先され、NTLM は Kerberos が使えないときの代わりとして残っている。Microsoft の説明では、ワークグループの機器どうしの認証と、ドメインコントローラー以外の機器でのローカルのログオンには、今も NTLM が使われる[1]。

Kerberos では、利用者は先にドメインコントローラーの KDC からチケットを受け取り、サービスごとのチケットをサーバーに見せる。サーバーは、つなぐたびにドメインコントローラーへ問い合わせなくてよい。Kerberos は、クライアントとサーバーが互いに相手を確かめられる。NTLM は、クライアントがサーバーの正体を確かめる仕組みを持たず、サーバーが本物であることを前提に作られている[2]。

アプリが使う Negotiate という仕組みは、まず Kerberos を試し、必要なときだけ NTLM に戻る[3]。共有を名前ではなく IP アドレスや DNS の別名（CNAME）で開くと、Kerberos ではなく NTLM になる[4]。

NTLM は、チャレンジに応答を返して、パスワードを知っていることを示す

NTLM のやりとりは、3つのメッセージでできている。Microsoft の仕様 [MS-NLMP] によると、クライアントが NEGOTIATE を送り、サーバーが 8 バイトの乱数（チャレンジ）を入れた CHALLENGE を返し、クライアントが利用者の名前と応答を入れた AUTHENTICATE を返す[5]。

NTLM は自分のポートを持たない。SMB や HTTP のような別のプロトコルのメッセージの中に埋め込まれて運ばれる[5]。SMB の 445 番でも、HTTP の 80 番・443 番でも、同じ NTLM が流れうる。

応答を確かめるのはサーバーか、ドメインコントローラーだ。ローカルのアカウントなら、サーバーが自分のアカウントのデータベースで確かめる。ドメインのアカウントなら、サーバーは名前・チャレンジ・応答をドメインコントローラーに送って確かめてもらう[1][5]。

NTLM には LM・NTLMv1・NTLMv2 の3つの版があり、流れは同じで、応答の計算のしかただけが違う。仕様は、NTLM が AES や SHA-256 のような新しい暗号に対応せず、MD4・MD5・RC4 を使っていることを挙げ、アプリには一般に NTLM を使わないよう勧めている[5]。

応答の鍵は、パスワードの NT ハッシュから作られる

NTLM の応答に使う鍵は、パスワードを MD4 にかけた値（NT ハッシュ）から作られる。[MS-NLMP] は、NTLMv1 の鍵を MD4(パスワード) と定め、NTLMv2 の鍵を、この MD4 の値を鍵にして、利用者名とドメイン名を HMAC-MD5 にかけた値と定めている。応答は、この鍵で、サーバーのチャレンジとクライアント側の時刻や乱数を HMAC-MD5 にかけて作る[5]。

式の中でパスワードが出てくるのは、MD4 にかけるところだけだ。つまり、NT ハッシュを持っていれば、パスワードを知らなくても正しい応答が作れる。盗んだハッシュで本人として認証するのが「パス・ザ・ハッシュ」（MITRE ATT&CK の T1550.002）だ[6]。MD4(パスワード) には利用者ごとの違いが入らないので、同じパスワードを使うアカウントは同じ NT ハッシュになる。

NT ハッシュは、ドメインコントローラーやローカルのアカウントのデータベースに保存され[5]、ログオン中の端末のメモリーにも置かれうる。Microsoft の Protected Users グループの説明には、メンバーになると NTLM が NT ハッシュ（NTOWF）をキャッシュしなくなり、ドメインコントローラーでも NTLM で認証できなくなる、とある[7]。

ATT&CK が挙げる対策は、ネットワーク越しのログオンでローカルのアカウントに UAC の制限をかけること、一つのドメインのアカウントを多くの端末のローカル管理者にしないこと、端末どうしで同じ認証情報を使い回さないことだ[6]。

Windows は、外の SMB や WebDAV にも自動で認証を送る

Windows は、SMB の共有を開くとき、ログオン中の利用者の認証情報で自動で認証する。パスワードを打たずに社内の共有を開くための動きだが、行き先が攻撃者のサーバーでも認証は送られる。ATT&CK はこれを「強制された認証」（T1187）とし、SMB が止められたときには、HTTP の上の WebDAV（80 番・443 番）が代わりに使われることにも触れている[8]。

きっかけは、外のサーバーを指す UNC パス（\\サーバー名\共有名\… の形）を含むファイルやメッセージだ。ATT&CK の例では、開くと外のテンプレートを読み込む文書や、アイコンの場所を外の UNC パスにした .LNK・.SCF のファイルがあり、アイコンを表示しただけで認証が始まる[8]。

Outlook の CVE-2023-23397 もこの形だった。Microsoft の説明では、細工したメッセージの拡張プロパティ（PidLidReminderFileParameter）に外の SMB サーバーを指す UNC パスを入れると、メッセージが処理されたときに NTLMv2 の応答が送られた。修正版の Outlook は、信頼できるネットワークの外を指すパスを使わなくなった[9]。CISA は 2023年3月14日、これを悪用が確かめられた脆弱性の一覧（KEV）に加え、NTLM のリレーで別のサービスに本人として認証させうる脆弱性と説明している[10]。

漏れるのは NT ハッシュそのものではなく、そのチャレンジに対する応答だ。応答は別のチャレンジには使い回せない。ただ、チャレンジを出したのは攻撃者なので、パスワードの候補から応答を計算して突き合わせる、手元での総当たりができる[8]。長く推測しにくいパスワードは、この総当たりを遅らせる[4]。

リレーは、受け取った応答をそのまま別のサーバーへ渡す

リレーは、クライアントとサーバーの間に入った攻撃者が、本物のサーバーのチャレンジをクライアントに渡し、返ってきた応答をそのまま本物のサーバーに渡して、本人としてログオンする攻撃だ。NTLM のクライアントはサーバーの正体を確かめないので[2]、相手が中継しているだけだと気づけない。

ATT&CK の T1557.001 は、間に入る方法として名前の解決の乗っ取りを挙げている。LLMNR（UDP 5355）・NBT-NS（UDP 137）・mDNS（UDP 5353）で同じネットワークに名前を尋ねる端末に、攻撃者が「自分だ」と答えると、端末は攻撃者に認証を送る。受け取った NTLMv1・v2 の応答は、SMB だけでなく LDAP や HTTP のサービスへも中継されうる[11]。対策には、使っていない LLMNR・NBT-NS・mDNS を止めることと、SMB 署名を有効にすることが挙がっている[11]。

署名と EPA で、リレーされた認証を使えなくする

SMB 署名は、SMB のメッセージごとに、認証で決まったセッション鍵から作った署名を付ける。セッション鍵はパスワードから作られ、署名には送り手と受け手の情報も入るので、改ざんとリレーを防ぐ[4]。[MS-NLMP] でも、セッション鍵は NT ハッシュから作った鍵で計算される[5]。中継しているだけの攻撃者はこの鍵を持たないので、認証のあとに署名付きのメッセージを続けられない。

以前は、署名が既定で必須なのはドメインコントローラーとの接続などに限られていた。Windows 11 24H2 と Windows Server 2025 からは、すべての送受信の SMB 接続で既定で必須になった[12]。

HTTP の上の認証には、EPA（認証の拡張保護）を使う。EPA は、TLS の通り道の情報（チャネルバインディングトークン）を認証の中に入れる。攻撃者が間に入ると TLS の通り道が二つに分かれるので、サーバーは値の食い違いで中継に気づき、認証を断れる[13]。NTLMv2 では、この値と宛先のサーバーの名前を、応答の中の欄（MsvAvChannelBindings・MsvAvTargetName）で運ぶ[5]。サーバー側の設定は「なし・一部・すべて」の3段階で、「すべて」なら値を送らないクライアントを断る[13]。

外向きの 445 番を止め、NTLM を減らしていく

外のサーバーへの自動の認証は、通信そのものを止めれば起きない。Microsoft は、会社のファイアウォールで、インターネットへ出ていく TCP 445 番を止めるよう勧め、クラウドの一部のサービスを除けば外へ SMB を出す必要はまずないとしている。社外で使うノートパソコンにも、端末のファイアウォールで外向きの SMB を止める規則を当てる[14]。ATT&CK も、TCP 139・445 と UDP 137 の外向きの通信と、外への WebDAV を止め、必要なら許可リストで絞るよう挙げている[8]。

止めにくい端末では、SMB のクライアント側で NTLM を止める方法がある。Windows 11 24H2 と Windows Server 2025 の SMB クライアントは、外向きの接続で NTLM を使わない設定を持ち、例外のサーバーを名前やアドレスで指定できる[15]。

Microsoft は NTLM を段階的に減らしている。Windows Server 2025 で NTLMv1 は削除され、NTLMv2 も非推奨になった[3]。2026年1月29日の Windows IT Pro Blog では、NTLM の使われ方を調べる監査の強化から始め、Kerberos に移れない場面を減らす機能を足し、次の大きな版でネットワークの NTLM 認証を既定で無効にする計画を示した。NTLM を Windows から消すわけではなく、必要なら新しいポリシーで有効に戻せる[16]。

ログでは、4624 の認証パッケージと 4776 を見る

Windows のログの全体は Windows のイベントログの記事に書いた。

NTLM を見るときの主な記録
記録残る場所見るところ
4624（ログオンの成功）ログオンされた機器のセキュリティのログログオンの種類（3 はネットワーク）、認証パッケージ（NTLM・Kerberos）、NTLM の版
4776（資格情報の確認）アカウントの持ち主の機器（ドメインのアカウントならドメインコントローラー）どのアカウントを、どの端末から確かめたか、結果のコード
NTLM の Operational のログ（8001・8002・8004 など）NTLM の制限のポリシーで監査を有効にした機器外へ出す NTLM の宛先、受けた NTLM、ドメインコントローラーでの NTLM

NSA の手引きは、パス・ザ・ハッシュの横移動を見る条件として、4624 のうち、ログオンの種類が 3、認証パッケージが NTLM、ドメインのアカウントでなく、ANONYMOUS LOGON でもないものを挙げている[17]。4624 には NTLM の版（NTLM V1・NTLM V2）も入るので、残っている NTLMv1 を探すのにも使える[18]。

4776 は、NTLM で資格情報を確かめたとき、その持ち主の機器に残る。ドメインのアカウントならドメインコントローラー、ローカルのアカウントならその機器だ[19]。SIEM の記事の LogonTracer も、4776 を NTLM の認証として扱う。

NTLM の Operational のログは、止める前の監査に使う。Sigma のルールでは、8001 は宛先の名前を持つ外向きの NTLM、8002 は受けた NTLM、8004 はドメインコントローラーで端末の名前を持つ NTLM の記録として使われている[20]。Protected Users のメンバーが NTLM で認証しようとして失敗すると、ドメインコントローラーの ProtectedUserFailures-DomainController のログに 100 が残る[7]。

通信の記録も手がかりになる。ATT&CK の検知の例は、端末から信頼していない宛先への TCP 139・445 の接続や、NTLM の認証を含む WebDAV の要求を見る[8]。外向きの 445 番の遮断の記録は、端末が外の SMB に認証しにいこうとした跡でもある。

自分の環境で確かめる

確かめるのは、自分の仮想マシンだけのネットワークか、許された演習の環境の中だけにする。攻撃の道具は使わず、Windows の設定とログで見る。

Windows の PowerShell で Get-SmbClientConfiguration と Get-SmbServerConfiguration を実行すると、RequireSecuritySignature の欄で SMB 署名を必須にしているかが分かる[4]。Windows 11 24H2 以降なら、クライアント側に BlockNTLM の設定もある[15]。

ドメインの演習環境があれば、同じ共有を \\PC-01\share と \\192.168.10.20\share の両方で開き、共有を持つ側の 4624 を比べる。Microsoft の説明どおりなら、名前のときは Kerberos、IP アドレスのときは NTLM が認証パッケージの欄に出て、IP アドレスのときはドメインコントローラーに 4776 も残る[4][19]。

端末のファイアウォールで外向きの TCP 445 番を止め、止めた記録をログに残す設定にしてから、文書用のアドレス \\203.0.113.10\share を開くと、外の SMB への接続が止められた記録が残る。この記録を SIEM に送れば、外向きの 445 番の遮断を数える検知の練習になる。
