同じネットワークの中では、パケットは IP アドレスではなく MAC アドレスを宛先にして届けられる。送る側は、宛先が自分と同じ範囲の中ならその相手の、外ならデフォルトゲートウェイの MAC アドレスへ送り、IPv4 ではその MAC アドレスを ARP で調べる。ARP は返ってきた答えが本物かを確かめないので、同じネットワークにいる者が偽の答えを返すと、通信を横取りできる。ルーティングの記事のネクストホップと、IP アドレスの記事の「同じ範囲（/24）」から広げ、RFC と公式の説明書で確かめた。例のアドレスは文書用のものだけを使う[1][2][3]。

同じつながりの中は、MAC アドレスで届ける

イーサネットのような同じつながり（リンク）の中では、機器は MAC アドレスで相手を見分ける。MAC アドレスは48ビットの数で、8ビットずつ六つに区切って16進数で書く。先頭の3バイトは OUI と呼ばれる組織ごとの番号で、残りをその組織が機器ごとに付ける[2]。すべてのビットが 1 の ff:ff:ff:ff:ff:ff は、つながりの全員あてのブロードキャストだ[4]。

イーサネットで送るひとまとまり（フレーム）の頭には、宛先の MAC アドレス、送り元の MAC アドレス、中身の種類の番号が並ぶ[4]。種類の番号は、IPv4 が 0x0800、ARP が 0x0806、IPv6 が 0x86DD だ[2]。

IP のヘッダーの宛先は最後の相手のまま変わらないが、フレームの宛先は、そのつながりの中で次に渡す相手を指す。RFC 826 は、ルーティングが次の相手（ネクストホップ）の IP アドレスを決め、それを MAC アドレスに直してから送る、という順で説明している[4]。

宛先が範囲の外なら、ゲートウェイの MAC アドレスへ送る

機器は、宛先が自分と同じ範囲にあるかを確かめ、中なら相手へ直接、外ならゲートウェイ（ルーター）へ送る。RFC 1122 は、自分のアドレスと宛先のアドレスをネットマスクで取り出して比べ、同じなら宛先へ直接送り、違えばゲートウェイを通す、と決めている[5]。

たとえば、自分が 192.0.2.10/24 で、デフォルトゲートウェイが 192.0.2.1 の機器を考える。宛先が 192.0.2.20 なら、先頭24ビットが同じなので、192.0.2.20 の MAC アドレスを調べて直接送る。宛先が 198.51.100.200 なら範囲の外なので、IP のヘッダーの宛先は 198.51.100.200 のまま、フレームの宛先にはゲートウェイ 192.0.2.1 の MAC アドレスを書く。このとき機器が ARP で調べるのは、198.51.100.200 ではなく 192.0.2.1 だ。

デフォルトゲートウェイは、経路表のデフォルトルート（0.0.0.0/0）のネクストホップのことだ。Linux の ip route get 198.51.100.200 では、使われる経路に via 192.0.2.1 と、ネクストホップのルーターのアドレスが出る[6]。

ARP は、全員に聞いて、本人が答える

ARP（Address Resolution Protocol）は、IPv4 アドレスから MAC アドレスを調べる決まりで、1982年の RFC 826 で定められた。調べたい機器は、つながりの全員あてに要求をブロードキャストで送り、その IP アドレスを持つ機器だけが、自分の MAC アドレスを入れた応答を、聞いてきた相手に直接返す[4]。

ARP のパケットには、要求（1）か応答（2）かの番号と、送り手と相手それぞれの MAC アドレスと IP アドレスが入る。要求では、相手の MAC アドレスの欄に決まった値を入れない[4]。

RFC 826 の例では、X から要求を受けた Y は、要求に入っていた X の IP アドレスと MAC アドレスの組を先に自分の表に入れてから、応答を返す。X が Y に話しかけるなら、Y も X に話しかけるだろう、という考えからだ[4]。

ARP の表は、答えをしばらく覚えておく

機器は ARP で調べた結果を表（ARP キャッシュ）に覚えておき、送るたびには聞き直さない。古い行の消し方を RFC 826 は決めておらず[4]、RFC 1122 が、古い行を消す仕組みを持つことと、同じ IP アドレスへの要求を宛先ごとに1秒に1回程度までに抑えることを求めている[5]。

Linux では、ARP の表は近隣の表（neighbour table）の一つで、iproute2 の説明書は IPv4 の近隣の表を ARP の表とも呼ぶ、と書いている。ip neigh で見ると、行ごとに状態が付く。REACHABLE は確かめてから時間がたっていない、STALE は使えるが確かめ直しが要る、PERMANENT は管理者が登録して、管理者が消すまで残る、という意味だ[6]。

Linux の arp(7) の説明書によると、相手が見つかった行は、base_reachable_time（標準で30秒）の半分から1.5倍までのでたらめな長さのあいだ有効とみなされ、TCP の確認応答のような上の層からの手応えがあると延びる[7]。

IPv6 では、近隣探索が同じ役目をする

IPv6 には ARP がなく、近隣探索（Neighbor Discovery、NDP）が、MAC アドレスの調べとルーターの見つけ方をまとめて受け持つ。RFC 4861 は、近隣探索を、IPv4 の ARP、ICMP のルーター発見、ICMP のリダイレクトを合わせたものにあたる、と書いている[8]。

IPv4 と IPv6 の、同じリンクの中の届け方（RFC 4861 の対応づけから）
役目IPv4IPv6
MAC アドレスを調べるARP の要求と応答近隣要請（NS、ICMPv6 の 135）と近隣広告（NA、136）
要求の送り先全員（ff:ff:ff:ff:ff:ff）要請ノードマルチキャストアドレス

近隣要請は、全員あてではなく、相手のアドレスの下位24ビットから作る要請ノードマルチキャストアドレスへ送る。RFC 4291 によると、このアドレスは ff02::1:ff00:0/104 に下位24ビットを付けたもので、2001:db8::5e:10 なら ff02::1:ff5e:10 になる[9]。相手は、自分の MAC アドレスを近隣広告で直接返す[8]。

送り先を決める手順も IPv4 と同じ形だ。RFC 4861 では、宛先が同じリンクの中かをプレフィックスの最長一致で判断し、中なら宛先そのものを、外ならルーター広告で知ったデフォルトルーターの一覧から選んだルーターを、次の相手にする。近隣キャッシュの行の REACHABLE の標準の長さは30,000ミリ秒だ[8]。

近隣探索のメッセージは Hop Limit を255にして送り、受け取る側は255であることを確かめる。ルーターは転送のたびに Hop Limit を減らすので、255のまま届いたものは同じリンクから来たと分かる[8]。同じリンクの中にいる者の偽りは、これでは防げない。

ARP は、答えが本物かを確かめない

ARP には、答えた機器が本当にその IP アドレスの持ち主かを確かめる仕組みがない。RFC 826 の受け取りの手順では、表にすでにある IP アドレスについて ARP のパケットが届くと、自分あてかどうかを見る前に、その行の MAC アドレスを新しい値で書き換える[4]。機器が別のハードウェアに替わったときに、早く直るようにするための作りだ[4]。

この作りのため、同じリンクにいる機器は、偽の ARP でほかの機器の表を書き換えられる。これを ARP スプーフィング（ARP キャッシュの汚染）と呼ぶ。RFC 5227 は、悪意のある機器がすべての要求に自分の MAC アドレスで答え、ネットワークのすべてのアドレスを自分のものだと名乗るのはたやすい、と書いている[10]。たとえば 192.0.2.10 の表で、ゲートウェイ 192.0.2.1 の行が 00-00-5E-00-53-01 から偽の 00-00-5E-00-53-02 に書き換わると、192.0.2.10 から外へ出る通信は、すべて偽の機器に届く。偽の機器がそれを本物のゲートウェイへ流し直せば、気づかれにくいまま中身を見たり変えたりでき（中間者攻撃）、流さなければ通信が止まる。

Linux も、表にすでにある IP アドレスなら、頼まれていない ARP（gratuitous ARP）でも行を書き換える。Linux の説明書は、arp_accept の設定に関係なく、すでにある行は更新される、と書いている[11]。頼まれていない ARP には正しい使い道もある。RFC 5227 は、アドレスを使い始める機器が自分のアドレスを全員に知らせ、ほかの機器に古い行を直させる「ARP の告知」を決めている[10]。正しい告知と偽の告知は、パケットの形では見分けられない。

この攻撃ができるのは、同じリンクにいる者だけだ。ARP の要求はリンクの中の全員にしか届かず[4]、ルーターの向こうからは表を書き換えられない。IPv6 の近隣探索にも同じ弱さがあり、RFC 3756 は、偽の近隣要請・近隣広告で通信を別の MAC アドレスへ流させることと、偽のルーター広告で自分をデフォルトルーターに選ばせることを、脅威に挙げている[12]。

見つけるには、IP アドレスと MAC アドレスの組の変化を見る

ARP スプーフィングの手がかりは、同じ IP アドレスに結び付く MAC アドレスが変わることだ。arpwatch は、リンクを流れる ARP を聞いて IP アドレスと MAC アドレスの組を記録し、変化を syslog とメールで知らせる道具だ。主な知らせは次のとおり[13]。

arpwatch の主な知らせ
知らせ意味
new station初めて見る MAC アドレス
changed ethernet addressある IP アドレスが、新しい MAC アドレスに替わった
flip flop直前の MAC アドレスから、その一つ前の MAC アドレスに戻った
ethernet mismatchフレームの送り元の MAC アドレスと、ARP の中の送り手の MAC アドレスが合わない
bogon送り元の IP アドレスが、そのリンクの範囲の外

組の変化は、そのまま攻撃の証拠にはならない。ネットワークカードの交換[8]や、IP アドレスを別の機器に付け替えたとき[4]にも組は変わる。見る価値が高いのは、ゲートウェイのように動かないはずの IP アドレスの組の変化と、flip flop のように二つの MAC アドレスを行き来する動きだ。一つの IP アドレスに二つの機器が答えていると、表はその二つのあいだを行き来する。

機器の側でも見つけられる。RFC 5227 は、ゲートウェイや DNS サーバーのようにアドレスを手放せない機器が、自分のアドレスを名乗るほかの機器の ARP を受け取ったら、その送り元の MAC アドレスなどを記録し、管理者に知らせるべきだとしている[10]。Linux では ip monitor neigh で、近隣の表が変わるたびに表示させられる[6]。

防ぐには、スイッチで確かめるか、表を固定する

主な防ぎ方は、つながりの側で偽の ARP を通さないことと、大事な行を固定することだ。

一つ目は、スイッチの Dynamic ARP Inspection（DAI）だ。Cisco の設定の案内によると、DAI は信頼しないポートで受け取った ARP をすべて受け止め、IP アドレスと MAC アドレスの組が、DHCP スヌーピングで作った表（DHCP で実際に配られたアドレスの記録）と合うかを確かめ、合わないものを捨てて記録する。手でアドレスを決めた機器は、ARP 用のアクセスリストに正しい組を書く。ほかのスイッチやルーターにつながるポートは信頼するポートにして、確かめを省く。受け取る ARP の数に上限を設けることもできる[14]。

二つ目は、表の行を静的に登録することだ。Linux では ip neigh で状態を permanent にした行を登録でき、この行は管理者が消すまで残る[6]。Linux カーネルは、管理者の操作でない更新、つまり受け取ったパケットによる更新では、permanent と noarp の行を書き換えない[15]。ゲートウェイの行を固定すれば、その機器の表は偽の ARP では変わらない。ただし守れるのは固定した機器の表だけで、ゲートウェイの側の表は別に守る必要がある。機器を入れ替えるたびに手で直す必要もある。

IPv6 では、スイッチで偽のルーター広告を止める RA Guard がある。RFC 6105 が示すいちばん単純な形では、ルーターにつながるポートだけがルーター広告を通し、ほかのポートは止める[16]。近隣探索のメッセージに電子署名を付ける SEND（RFC 3971）も決められている[17]。

リンクに入れる機器を限ることも効く。RFC 3756 は、リンクに入れるのが信頼できる機器だけなら偽の近隣要請や近隣広告は心配にならないとし、その例に 802.1X で接続を制御する有線の LAN を挙げる[12]。最後の守りは暗号だ。TLS 1.3 の RFC 8446 は、TLS を、盗み聞き・書き換え・なりすましを防ぐよう作られたものとしている[18]。通り道を横取りされても、証明書を正しく確かめる TLS の通信なら、中身は読まれない。

自分の環境で確かめる

ARP と近隣探索の動きは、自分の機器の中で、Linux の標準の道具で観察できる。偽の ARP を送って試すのは、自分が管理する仮想マシンだけのラボの中に限る。会社や店のような共有のネットワークでは、ほかの人の通信を止めたり横取りしたりすることになるので、許可なく試さない。

ip neigh で ARP の表と近隣キャッシュを見られる[6]。ip route get に外の宛先を渡すと via のあとにゲートウェイが出て、そのゲートウェイの行が ip neigh に MAC アドレス付きで並ぶ。しばらく通信しないと、行は REACHABLE から STALE に変わる[7]。

パケットは tcpdump で見られる。フィルターに arp と書くと ARP だけを取り出せ、-e を付けると各行にフレームの送り元と宛先の MAC アドレスが出る[19]。自分の機器の表から一つの行を消してから同じ相手に通信すると、要求が ff:ff:ff:ff:ff:ff あてに出て、応答が自分の MAC アドレスあてに返ってくる様子が見える。そのとき表の行が変わる様子は ip monitor neigh で見られる[6]。
