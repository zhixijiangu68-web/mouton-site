2026年10月21日、オープンソースの Snort 2 は、すべての版のサポートが終わった[1]。ネットで見つかる IDS の解説の多くは、まだ Snort 2 が前提だ。この2本目では、いま無料で使える IDS を並べて、何が違うかを書く。

版や日付は、2026年11月4日時点で、公式の発表を検索で確かめたものだ。古くなりやすいので、使う前に公式のページを見てほしい。

IDS について、4本に分けて書いている。1 IDS とは何か、なぜ大事か／2 無料の道具／3 商用とクラウドの製品／4 選ぶとき・運用するとき。

無料の道具は、知らせるもの・記録するもの・機械の中を見るものに分かれた

無料で使える主な IDS（2026年11月4日時点）
名前見る場所と方式止めるか向いている使い方
Suricata 8ネットワーク。シグネチャとプロトコル解析IPS モードで止められる検知も遮断も一つで。記録を SIEM に流したいとき
Snort 3ネットワーク。シグネチャが中心IPS として使えるTalos のルールに合わせたいとき。Snort 2 からの移行
Zeek 9ネットワーク。プロトコル解析とスクリプト記録と分析が中心（止める機能は確かめていない）何が起きたかを細かく残して、あとから調べる
Security Onion 3Suricata・Zeek・Elastic をまとめた配布確かめていない（中の Suricata の設定による）学ぶ。小さな組織で一式をそろえる
Wazuh 4.14機械の中。ログ分析と改ざんの検知その機械で対処できるサーバーや PC の中の変化を見る
OSSEC機械の中。ログ分析と改ざんの検知その機械で対処できる小さく、軽く、ホスト型を始める

表の「止めるか」は、置き方と設定によって変わる。ネットワーク型の道具でも、通信のコピーを受け取る置き方なら、知らせることしかできない。SIEM は、ログを集めて分析する仕組みのことだ。

Suricata は、検知も遮断も一つでできる

Suricata は、OISF（Open Information Security Foundation）が作るネットワーク型の IDS/IPS だ。ライセンスは GPL v2 だ。8系の最初の版 8.0.0 は2025年7月に出た[4]。シグネチャ（ルール）での検知に加えて、通信のプロトコルを解析する。その結果を、EVE JSON という1行1件の JSON で記録する。SIEM に流しやすい形だ。

遮断もできる。Linux では、NFQUEUE（通信を Suricata に回す仕組み）を使う。または、2枚の NIC（ネットワークにつなぐ部品）を橋渡しする AF_PACKET の IPS モードを使う。IPS モードのときだけ、drop のルールで実際に通信が落ちる[5]。

2026年9月の 8.0.7 は、これまでで最も多い脆弱性の報告を直した版だった。報告は AI を使った解析によるものとされる[6]。守る道具そのものも、更新し続けるものだ。

暗号化された通信では、中身の代わりに、JA3・JA4 と呼ばれる「話し方の指紋」を記録できる[7]。TLS（通信を暗号化する決まり）の始めのあいさつの特徴だ。

ルールは、何を見つけたらどう扱うかを1行で書いたもの

考え方を見るために、演習用の例を一つ置く。自分の環境で、example.com という名前を DNS で引いたら知らせる、というだけのルールだ。

alert dns any any -> any any (msg:"演習: example.com の名前を引いた"; dns.query; content:"example.com"; nocase; sid:1000001; rev:1;)
  • 先頭の alert：扱い方（知らせる）
  • dns：見るプロトコル
  • any any -> any any：送り元と宛先（どこでも）
  • かっこの中：条件と、記録に残す文言

sid はルールの番号だ。自分で作るルールには、配布されるルールとぶつからない番号を使う。IPS モードでは、先頭を drop にすると止める扱いになる。この1行は書き方の例で、僕はまだ自分の環境で動かして確かめていない。書き方の細部は、使う版の Suricata の文書で確かめてほしい。

Snort は、これから学ぶなら Snort 3 から始める

Snort は、Cisco の Talos が作る IDS/IPS で、エンジンは GPL v2 だ。Snort 2 のサポートが終わり、Talos も Snort 2 向けのルールを出さなくなった。設定を Snort 3 の書き方に変える、snort2lua という道具を案内している[1]。

Snort 3 は、1つのプロセスでいくつものスレッドを動かせる。設定は Lua というプログラムの言葉で書き、Snort 2 の設定はそのままでは動かない[8]。

ルールは3つある[9]。

  • Community：無料で、登録も要らない
  • Registered：無料の登録で使える。新しいルールは Subscriber より30日遅れて届くと説明されている（2014年の説明で、いまも同じかは確かめていない）
  • Subscriber：有料

Suricata と Snort には、Proofpoint の ET Open（無料）と ET Pro（有料）のルールもある。ET Pro は ET Open を丸ごと含むので、同時には入れない[10]。

Zeek は、知らせるより、記録してあとから調べる道具だった

Zeek（旧名 Bro）は、通信をプロトコルごとのログ（接続・DNS・HTTP・TLS など）に書き出す道具だ。監視の方針は、専用のスクリプトで書く。ライセンスは BSD だ[2]。2026年9月に 9.0.0（長期サポートの版）が出た[11]。10月には 8.0.11 と 9.0.1 が、「これまでで最大のセキュリティリリース」として出た[12]。

TLS のやりとりは ssl.log に、証明書は x509.log に残る。ただし TLS 1.3 では証明書が暗号化されるので、x509.log は出ない[13]。Security Onion や Corelight は、Zeek と Suricata を組み合わせている[14][15]。

Security Onion は一式をまとめて試せ、Wazuh と OSSEC は機械の中を見る

Security Onion は、Suricata・Zeek・Elastic（検索と可視化）をまとめて入れられる配布だ。2026年3月に 3.0.0 が出て、パケットの保存も Suricata が担うようになった。対応する OS は Oracle Linux 9 だけだ[14]。2.4 系は2026年10月1日でサポートが終わった[16]。これも、古い手順書に注意が要る。

ホスト型の代表が Wazuh と OSSEC だ。どちらも、サーバーや PC のログを分析し、ファイルの改ざんを見つける。active response という仕組みもある。変化を見つけたときに、その機械でスクリプトを動かして対処する[17][18]。

ネットワーク型とは、見る場所が違う。暗号化で見えなくなる部分は、端末の記録で埋めると Security Onion の文書は書いている[3]。どちらか一つではなく、組み合わせるものだ。

無料の道具は、役目の違うものを組み合わせて使う

まとめると、無料の中心は Suricata・Snort 3・Zeek だ。Suricata と Snort は知らせて止める道具、Zeek は記録してあとから調べる道具だった。Snort 2 と Security Onion 2.4 は、2026年にサポートが終わった。機械の中は、Wazuh や OSSEC のようなホスト型が見る。

無料の道具はソフトの代金がかからない。その代わり、更新とルールの調整と、警告を読む人の時間がかかる。そのことは4本目に書いた。

この記事の事実は、公式の資料を検索で確かめたもので、原典のページを一つずつ開いて確かめ直している途中だ。下書きと資料の照らし合わせには AI を使い、公開の前にムートンが全文を読む決まりにしている。特定の製品を勧めるものではない。

自分が最初に触るなら、知らせる道具と、記録する道具の、どちらから始めたいだろうか。
