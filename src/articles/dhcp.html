DHCP は、ネットワークにつないだ機器に、IP アドレス・ネットマスク・デフォルトゲートウェイ・DNS サーバーを期限つきで貸す仕組みで、基本の DHCP には、返事を送ったサーバーが本物かを確かめる仕組みがない。だから偽のサーバーはスイッチで止め、リースの記録でアドレスと機器を結びつける。この記事は、IP アドレスの記事に出てきた「169.254 のアドレスは、DHCP からアドレスをもらえていない手がかり」から広げて、仕組みと守り方を RFC とソフトの公式文書で確かめたものだ。例のアドレスと MAC アドレスは、文書のために取ってある値を使う[1][2]。

DHCP は、つなぐのに要る設定を期限つきで貸す

DHCP のサーバーは、機器（クライアント）に IP アドレスを決まった期間だけ貸す。この期間をリースと呼び、RFC 2131 は秒で表すと決め、0xffffffff を「無期限」に取ってある[3]。アドレスのほかの設定は「オプション」として同じ返事に入れて渡す。番号と形は RFC 2132 が決めている[4]。

機器がつながるのに使う主なオプション（RFC 2132 から）
番号名前中身
1サブネットマスクネットマスク（例 255.255.255.0）
3ルーター同じつながりにあるルーターのアドレス。優先する順に並べる。機器はこれをデフォルトゲートウェイに使う
6DNS サーバー名前を引くサーバーのアドレス。優先する順に並べる
51リース時間貸す期間（秒）
53メッセージの種類1 が DISCOVER、2 が OFFER、3 が REQUEST、5 が ACK など
54サーバー識別子返事を送ったサーバーのアドレス

DHCP は UDP を使い、クライアントからサーバーへはポート67、サーバーからクライアントへはポート68に送る[3]。アドレスをもらう前の機器は自分のアドレスを持たないので、送り元を 0 にしたブロードキャストで、同じつながりの全員に向けて送る[3]。

四つのメッセージで、アドレスが決まる

新しくアドレスをもらうときは、DISCOVER・OFFER・REQUEST・ACK の四つのメッセージを順にやりとりする。RFC 2131 の流れは次のとおりだ[3]。

まず機器が、DISCOVER をブロードキャストして、サーバーを探す。サーバーはそれぞれ、空いているアドレスと設定を OFFER で返す。サーバーは新しいアドレスを貸す前に、そのアドレスが使われていないかを ICMP の Echo Request などで確かめるべき（SHOULD）とされている。

機器は届いた OFFER から一つを選び、選んだサーバーのサーバー識別子を入れた REQUEST を、またブロードキャストする。全員に届くので、選ばれなかったサーバーも、自分の申し出が断られたと分かる。選ばれたサーバーは貸し出しを記録し、ACK で設定を確定させる。

ACK を受け取った機器は、そのアドレスを ARP で確かめるべき（SHOULD）とされ、すでに使われていれば DECLINE をサーバーに送ってやり直す。やり直す前には10秒以上待つべきとされる。サーバーは、REQUEST に応えられないとき NAK を返す。機器がアドレスを手放すときは RELEASE を送る[3]。

ブロードキャストはルーターを越えないので、サーバーが別のネットワークにあるときは、ルーターなどの中継（リレーエージェント）がメッセージをサーバーへ渡す。中継は自分のアドレスを giaddr という欄に入れ、サーバーはその値で、どのネットワークのアドレスを貸すかを決める[3]。

リースは、期限の半分で延長を頼む

機器はリースが切れる前に延長を頼み、その時刻は T1 と T2 の二つで決まる。RFC 2131 では、T1 はリースの長さの0.5倍、T2 は0.875倍が標準で、サーバーはオプション58と59で別の値を渡せる[3][4]。

T1 になると、機器は貸してくれたサーバーにだけ、ユニキャストで REQUEST を送る（RENEWING）。T2 までに ACK が来なければ、ブロードキャストで、どのサーバーにでも延長を頼む（REBINDING）。それでもリースが切れたら、機器はそのアドレスでの通信をやめ、最初からやり直す。返事がないときの送り直しは、残り時間の半分ずつ待ち、間隔は60秒より短くしない[3]。

たとえばリースが1日（86,400秒）なら、T1 は12時間後、T2 は21時間後になる。RFC 2131 は、多くの機器が同時に延長を頼まないよう、T1 と T2 に少しのばらつきを持たせるべきとしている[3]。

もらえないときは、169.254 の中から自分で決める

DHCP のサーバーから返事がないとき、機器は 169.254.0.0/16 の中から自分でアドレスを決めることがある。この方法は RFC 3927 が決めていて、169.254.1.0 から 169.254.254.255 までの中から乱数で一つを選ぶ。最初と最後の256個は、将来のために取ってある[5]。

選んだアドレスは、すぐには使わない。送り元を 0 にした ARP の問い合わせ（ARP Probe）を3回送り、誰かが同じアドレスを使っていれば選び直す。重ならなければ、ARP で2回知らせてから使い始める[5]。

このアドレスは同じつながりの中だけで使うもので、送り元か宛先が 169.254/16 のパケットは、ルーターへ渡してはならず、受け取った機器も転送してはならない[5]。インターネットにはつながらない。RFC 3927 は、このアドレスを付けたあとも DHCP のクライアントの動きを変えず、アドレスを求め続けるよう求めている[5]。

169.254 のアドレスを付けるかどうかは、OS の設定で変わる。たとえば systemd-networkd では、IPv4 のこのアドレスは LinkLocalAddressing= で ipv4 か yes を選んだときだけ、DHCP がしばらく失敗したあとに付く。標準の値は ipv6 で、IPv4 では付かない[6]。

IPv6 では、ルーター広告からアドレスを作れる

IPv6 の機器は、DHCP のサーバーがなくても、ルーターの広告からアドレスを自分で作れる。この仕組みを SLAAC（ステートレス自動設定）と呼び、RFC 4862 が決めている。ルーターは、つながりで使うプレフィックスを広告し、機器はそのプレフィックスに自分のインターフェース ID を足してアドレスを作る。使う前には、同じアドレスがないかを確かめる（重複アドレス検出）[7]。

デフォルトゲートウェイも、ルーター広告から知る。広告にはルーターの寿命（Router Lifetime）の欄があり、0 でなければ、機器はそのルーターをデフォルトルーターの候補に入れる。広告の M フラグは「アドレスを DHCPv6 で配っている」、O フラグは「DNS などのほかの設定を DHCPv6 で配っている」ことを表す[8]。

DHCPv6 は RFC 8415 が決めている。機器はポート546で待ち、サーバーと中継はポート547で待つ。機器は Solicit を ff02::1:2 という中継とサーバーのためのマルチキャストのアドレスに送り、Advertise・Request・Reply と続く四つのやりとりでアドレスを受け取る。Rapid Commit というオプションを付ければ、Solicit と Reply の二つで済ませることもできる[9]。機器は MAC アドレスではなく DUID という識別子で見分けられ、事業者が家のルーターにプレフィックスごと貸すこと（プレフィックスの委任）にも使われる[9]。

DNS サーバーのアドレスは、DHCPv6 のほか、ルーター広告のオプション（RDNSS）でも渡せる[10]。また、SLAAC で作るアドレスには、時間とともに変わる一時アドレスもあり、RFC 8981 は、同じアドレスを使い続けることで通信が結びつけられるのを減らすためと説明している[11]。

偽の DHCP サーバーは、ゲートウェイと DNS を差し替える

同じつながりにいる機器なら、DHCP の返事を送ることができる。RFC 2131 は、許可されていない DHCP サーバーは簡単に立てられ、間違ったアドレス、偽のルーターを含む間違った経路の情報、偽の DNS サーバーなどを配れる、と書いている[3]。

機器が偽のサーバーの OFFER を選ぶと、デフォルトゲートウェイが偽のサーバーの指定したアドレスになり、外へ出る通信がまずそこを通る。DNS サーバーが差し替えられれば、名前を引いた答えを偽のサーバーが決められる。RFC 8415 も、偽のサーバーの目的として、DNS や NTP のような相手を偽物に差し替える中間者攻撃と、間違った設定で通信を止めるサービス妨害を挙げている[9]。

悪意がなくても同じことが起きる。RFC 8415 は、間違えて設定された DHCP サーバーが意図しない設定を配ることも脅威として挙げている[9]。DHCP サーバーの機能を持つ家庭用のルーターを社内のネットワークにつなげば、それも返事を送りうる。

クライアントの側からの攻撃もある。RFC 2131 は、悪意のあるクライアントがアドレスをすべて借りてしまい、正しい機器が借りられなくなるおそれを書いている[3]。IPv6 では、許可されていないルーターや設定を誤ったルーターが出すルーター広告（rogue RA）が同じ問題を起こし、RFC 6105 はそれをスイッチで止める枠組みを書いている[12]。

スイッチは、決めたポートからだけサーバーの返事を通す

偽のサーバーへのいちばんの対策は、機器がつながるスイッチで、サーバーの返事を受け取ってよいポートを決めておくことだ。IPv4 では DHCP snooping と呼ばれる機能として広く使われてきた、と RFC 7610 は書いている[13]。

RFC 7610 は、同じ考えを DHCPv6 に当てた DHCPv6-Shield を決めている。スイッチには、サーバーからクライアントへのメッセージを受け取ってよいポートを先に設定し、それ以外のポートから来たサーバーのメッセージを捨てる。IPv6 のヘッダーの連なりを最後まで読み、途中で切れた断片は捨てて記録を残すことも求めている。読む長さに上限があると、すり抜けられるからだ[13]。ルーター広告には、ルーターのポート以外からの広告を止める RA-Guard がある[12]。

DHCP のやりとりを見たスイッチは、どのポートの機器にどのアドレスが貸されたかの表を作れる。RFC 7513（SAVI-DHCP）は、この表を使って、貸されたものと違う送り元のアドレスを名乗るパケットを捨てる方法を決めている。サーバーのメッセージを送ってよいかを表す DHCP-Trust の属性は、標準で FALSE、つまり「サーバーではない」とされている[14]。

アドレスを借り尽くす攻撃には、一つのクライアントが借りられる数をサーバーで制限する方法がある、と RFC 8415 は書いている[9]。設定の名前や書き方はスイッチやサーバーの製品ごとに違うので、使っている機器の説明書で確かめる。

リースの記録で、アドレスと機器を結びつける

ファイアウォールなどのログに残った社内のアドレスがどの機器かは、その時刻に有効だったリースの記録で分かる。同じアドレスは時間がたてば別の機器に貸されるので、アドレスだけでなく時刻で照らす必要がある。

記録の場所はソフトごとに違う。ISC の Kea は、リースを CSV のファイル（memfile）に追記していき、読み込むときは最後の行を有効なものとして扱う。古い行は、標準で3,600秒ごとに動くクリーンアップ（LFC）で消える[15]。リースのファイルは履歴として残るものではないので、あとで調べたい期間の分は、ログとして別に集めておく必要がある。dnsmasq は、リースを作ったとき・消したときに指定したプログラムを動かし、「add」「del」などの種類、MAC アドレス、IP アドレス、ホスト名を渡す[16]。たとえば「add、00:00:5e:00:53:01、192.0.2.57」という記録があれば、その時刻の 192.0.2.57 はこの MAC アドレスの機器だ。

中継が DHCP のメッセージに足すオプション82（Relay Agent Information）の Circuit ID には、スイッチのポートの番号などが入る。RFC 3046 は、サーバーがこの値をリースのログに残すよう勧めている[17]。MAC アドレスに加えて、どのポートにつながっていたかも分かる。

結びつけには限りもある。機器によっては、つなぐたびやつなぐネットワークごとに MAC アドレスを乱数にする。RFC 7844 は、そうした機器のために、DHCP のメッセージから見分けに使える値を減らす方法を書いている[18]。IPv6 の SLAAC のアドレスは機器が自分で作るので、DHCP のサーバーには記録が残らない[7]。

見張りの手がかりもリースの記録にある。知らないサーバー識別子からの返事や、DECLINE の急な増え方は、偽のサーバーやアドレスの重なりの手がかりになる。RFC 2131 は、DECLINE を受けたサーバーに、そのアドレスを使えないものとし、管理者に知らせるよう求めている[3]。

自分の環境で確かめる

DHCP のやりとりは、自分の機器と自分のネットワークの中で観察できる。試すのは自分の環境だけにする。共用のネットワークで練習用の DHCP サーバーを動かすと、それ自体が偽のサーバーになるので、仮想マシンの内部ネットワークのような閉じた場所で試す。

systemd-networkd を使う機器では、networkctl dhcp-lease <インターフェース> で、受け取った ACK の中身が見られる。オプションの番号ごとに、ネットマスク・ルーター・DNS サーバー・リース時間・サーバー識別子・T1・T2 が並ぶ。この命令は systemd の 261 版で足された[19]。

つなぎ直すときのやりとりは、tcpdump -n -v -i <インターフェース> 'udp port 67 or udp port 68' で見られる[20]。DISCOVER・OFFER・REQUEST・ACK が順に流れ、ACK のオプションに表の値が入っているのが分かる。

IPv6 では、ip -6 addr show dynamic で SLAAC で作ったアドレスだけを並べられる。valid_lft と preferred_lft は、RFC 4862 の有効期間と推奨期間だ[21]。IPv4 で 169.254 のアドレスが出ていれば、DHCP の返事を受け取れていない。
