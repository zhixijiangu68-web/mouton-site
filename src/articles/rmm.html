RMM（リモート監視・管理）ツールは、運用を受け持つ事業者や社内の情報システムの担当が、離れた場所から多くの端末を見守り、操作するための正規のソフトだ。攻撃者は同じソフトを、だまして入れさせる道具や、入り込んだあとの出入り口として使う。業務と同じソフトなので見分けにくく、守る側は、使ってよい RMM を決めてほかを止めること、管理する側のアカウントを固めること、見慣れない導入と外への通信をログで見ることで備える。

RMM は、離れた場所から多くの端末を見て、操作する道具

RMM は、端末に入れたソフトを通じて、離れた場所から画面やコマンドで端末を扱う道具だ。MITRE ATT&CK は、遠隔操作の道具を使うと、利用者がその場にいるかのように端末を操作でき、利用者やソフトの権限をそのまま受け継ぐと説明している。使い道は、障害の調査、ソフトの導入、システムの管理だ[1]。

2023年6月に CISA などが出した手引き「Guide to Securing Remote Access Software」も、RMM を、MSP（運用を受け持つ事業者）のような管理者が離れた場所から仕事をするための道具としている[2]。

多くの RMM は、入れるときに Windows のサービスを作り、裏で動き続ける。ATT&CK は、この導入の作りが、そのまま攻撃者にとっての居座り（永続化）にもなると書いている[1]。

MSP は、RMM で多くの顧客の端末につながっている

MSP は、契約している多くの会社の端末を、RMM で管理していることが多い。CISA・NSA・MS-ISAC の勧告 AA23-025A は、MSP と社内のヘルプデスクが、利用者のサポート、ネットワークの管理、端末の監視のために、ふだんから正規の RMM を使っていると書いている[3]。

同じ勧告は、攻撃者がこうした RMM の正規の利用者を狙うことが多く、MSP のネットワークの信頼関係を悪用して、その MSP の多くの顧客に入り込めると注意している。MSP が侵害されると、顧客にはランサムウェアや情報を盗む攻撃の危険が及ぶ[3]。

ATT&CK は、この形を「信頼された関係」（T1199）としてまとめている。組織は外部の業者に高い権限を渡すことが多く、その権限が組織のほかの部分と同じネットワークにあることもある。業者のアカウントが乗っ取られれば、そこから入られ、その入り口はふつうの入り口ほど注意して見られていないことがある[4]。一社への侵入が、その会社の顧客へ広がるのが、MSP を通したサプライチェーンの攻撃の形だ。

攻撃者が正規の RMM を選ぶのは、止められにくく、目立ちにくいから

正規の RMM は、ウイルス対策に止められにくく、自前の不正なプログラムを用意しなくても遠隔操作ができる。AA23-025A は、守る側が知っておくこととして、次の点を挙げている[3]。

  • 攻撃者は、どの正規の RMM でも悪用できる
  • RMM は、インストールの要らない単体で動く版（ポータブル版）として取ってこられる。これを使うと、管理者の権限と、ソフトの導入を管理する仕組みの両方をすり抜けられる
  • RMM を使っても、ウイルス対策や不正なプログラムの対策は、ふつう反応しない
  • RMM は、居座りと、外から命令を送る通り道（C2）のための裏口として使われてきた
  • RMM を使えば、攻撃者は自前の不正なプログラムを作らずに済む

ATT&CK も、VNC・TeamViewer・AnyDesk・ScreenConnect・LogMeIn といったデスクトップのサポート用ソフトは、正規のサポートに広く使われているため、アプリの制御で許されている場合があると書いている[5]。

CISA などの手引きは、攻撃者が遠隔操作のソフトを、最初の侵入、居座り、ほかの道具の持ち込み、ネットワークの中の横移動、データの持ち出しに使うと整理している[2]。業務で同じ製品を使っている組織では、その製品の通信先はふだんから許されているので、通信だけを見て業務と攻撃を見分けるのは難しくなる。

偽のサポートを装い、本人に入れさせる手口がある

攻撃者は、サポートの窓口を装って、相手自身に RMM を入れさせることがある。AA23-025A は、2022年に米国の連邦政府の職員が狙われた例を書いている。ヘルプデスクを装ったメールに電話番号やリンクがあり、電話した人やリンクを開いた人は、最初の不正なサイトから実行ファイルを受け取る。それが次のサイトから、攻撃者の RMM のサーバーにつながるよう設定された AnyDesk と ScreenConnect のポータブル版を取ってきた[3]。

この例では、攻撃者は RMM でつないだまま相手に銀行のサイトへログインさせ、残高の表示を書き換えて返金しすぎたように見せ、差額の「返金」を求めた。勧告は、得たアクセスがほかの攻撃者に売られ、職場の組織への攻撃につながりうると注意している[3]。

ATT&CK は、電話を使うこの形を「音声によるフィッシング」（T1566.004）としてまとめ、メッセージで電話番号に電話させ、遠隔管理の道具を入れさせる例を挙げている[6]。日本でも IPA が、ブラウザーに偽のセキュリティ警告と電話番号を出し、電話してきた人に遠隔操作のソフトを入れさせる「サポート詐欺」に注意を呼びかけている[7][8]。IPA の勧めは、警告に出た番号に電話しないこと、警告の画面を閉じること、遠隔操作されてしまったらネットワークを切り、入れられたソフトを消して相談することだ[7][8]。

MSP の管理画面を乗っ取られると、顧客へまとめて広がる

RMM の管理画面は、つながっている端末にソフトを配り、命令を動かせるので、ここを乗っ取られると被害が一度に広がる。ATT&CK は、組織全体の端末を管理するソフトに入られると、つながっているすべての端末で命令を動かされうると書いている[9]。2021年7月、Kaseya の RMM「VSA」の脆弱性を使ったランサムウェアの攻撃が、複数の MSP とその顧客に広がった[10]。Kaseya によると、直接侵害された顧客は60社未満で、すべてオンプレミス版の VSA の利用者だった。その多くがほかの会社に IT のサービスを提供していたため、影響は合わせて1,500社未満の会社に及んだ[11]。この脆弱性について、Kaseya は2021年7月11日にオンプレミス版の修正を出している[11]。

このとき CISA と FBI は、MSP に、すべてのアカウントでの多要素認証、RMM との通信を決まった IP アドレスの組だけに許すこと、RMM の管理画面を VPN か管理専用のネットワークの内側に置くことを勧め、顧客には、切り離したバックアップと、管理者のアカウントを必要最小限の権限にすることを勧めた[10]。

2026年11月にも、ConnectWise が、ScreenConnect の利用者を狙った攻撃を調べるなかで、外部の会社が作った拡張機能を止めたと報じられている[12]。調査は、この記事を書いている時点で続いている。

使ってよい RMM を一つに決め、ほかを止める

守りの最初は、組織の中でどの RMM が使われているかを洗い出し、使ってよいものを決めて、それ以外を動かさないことだ。AA23-025A は、ネットワークの中の遠隔操作の道具を調べて、使っているものと許したものを把握すること、アプリの制御で許した RMM だけを動かすこと（許可リスト）を勧めている。その制御は、許していない RMM のインストールだけでなく、ポータブル版の実行も止めるものにする[3]。ATT&CK の対策も、許していないソフトの導入と利用をアプリの制御で止めることと、要らない遠隔接続の機能を無効にすることを挙げている[1]。

Windows では、App Control for Business（以前の名前は WDAC）のような仕組みで、動かしてよいプログラムを決められる。Microsoft の教材は、いきなり止めずに、まず監査モードで動かして、止めるはずだったものを記録させる手順を示している。記録は「Microsoft-Windows-CodeIntegrity/Operational」のログのイベント ID 3076 に残り、それを見て、業務に要るのに許していないものを足してから強制に切り替える[13]。

許した RMM も、使える経路をしぼる。AA23-025A は、許した RMM を VPN や仮想デスクトップのような認めた遠隔接続の内側からだけ使わせること、よく使われる RMM のポートとプロトコルを、ネットワークの境界で入りも出も止めることを勧めている[3]。

MSP との契約で、権限と責任の分け方を決める

MSP に預けるなら、誰が何をできるか、何かあったときに誰が何をするかを、契約で先に決めておく。2022年5月に英国・豪州・カナダ・ニュージーランド・米国の機関が出した共同の勧告 AA22-131A は、MSP と顧客の契約で、セキュリティの役割と責任を誰が持つかをはっきりさせるよう勧め、顧客には、MSP のアカウントを組織の中の管理者のグループに入れないこと、ネットワーク全体で必要最小限の権限にすることを挙げている。侵入に気づくまで何か月もかかることがあるので、重要なログを少なくとも6か月は残すことも勧めている[14]。

ATT&CK の T1199 の対策も、信頼した相手のアカウントと権限を、相手の乱用と乗っ取りの両方を考えて管理することと、ネットワークを分けることを挙げている[4]。

管理画面とアカウントは、多要素認証で守る

RMM の管理画面と、MSP が顧客の環境に入るためのアカウントは、パスワードだけで守らない。ATT&CK は、外部の業者に委ねた管理者の権限（委任された管理者）を持つアカウントのすべてに、多要素認証を求めるよう勧めている[4]。Kaseya の件の手引きも、すべてのアカウントでの多要素認証を、MSP への勧めの一つに置いている[10]。多要素認証の仕組みと弱点は、多要素認証の記事にまとめた。

外への通信を見て、許していない RMM の通信先を止める

遠隔操作のソフトは、端末の側から外のサーバーへつなぎに行く形で使われることがあるので、入ってくる通信だけでなく、出ていく通信を見る。AA23-025A の例でも、ポータブル版は攻撃者の RMM のサーバーへつなぐよう設定されていた[3]。ATT&CK の対策は、ファイアウォールやプロキシで、遠隔操作のソフトが使うサイトやサービスへの外向きの通信を制限することを挙げている[1]。出ていく通信を許すものだけにする考え方は、ファイアウォールの記事の「出ていく通信も止める」の節に書いた。

許した RMM の通信先が決まっていれば、ほかの RMM の通信先へのアクセスは、それだけで調べる理由になる。プロキシやファイアウォールのログを SIEM に集めておけば、どの端末がいつからつないでいるかをさかのぼれる。

ログでは、見慣れない RMM の導入と、そのあとの動きを見る

ログで見るのは、許していない RMM が入ったこと、動いたこと、外へつなぎ続けていることの三つだ。RMM の多くはサービスとして入るので[1]、Windows のシステムのログに残る、サービスが入ったことを表すイベントが手がかりになる。Microsoft の文書によると、ソースが Service Control Manager のイベント ID 7045 は「A service was installed in the system.」で、サービスの名前、実行ファイルの場所、種類、開始の方法、動かすアカウントが記録される[15]。イベントログの仕組みは、Windows のイベントログの記事にまとめた。

RMM の悪用を見つける手がかり
見るものどこに残るか見落としやすい点
サービスの導入システムのログのイベント ID 7045[15]ポータブル版はインストールしないので、ここに出ないことがある[3]
RMM の実行プロセスの起動の記録、EDR の記録メモリーの中だけで動くものは、それを見られる道具が要る[3]
止めた・止めるはずだった実行CodeIntegrity のログのイベント ID 3076（監査モード）[13]監査モードの記録は、許したものをすべて残すわけではない[13]
外への通信ファイアウォール・プロキシのログ業務で同じ製品を使っていると、通信先だけでは見分けにくい

公開されている検知のルールでは、Sigma の「Remote Access Tool Services Have Been Installed - System」が、Service Control Manager のイベント ID 7045 と 7036 のうち、サービスの名前に TeamViewer・AnyDesk・LogMeIn・Atera などの文字を含むものを拾う。重さは medium で[16]、名前で拾うので、許した RMM を入れたときにも鳴る。鳴ったら、許可リストに載っている RMM か、導入した人と時刻に心当たりがあるかを確かめる。

一つの記録で決めず、つなげて見る。ATT&CK の検知の考え方は、遠隔操作のソフトが動き、サービスや自動起動で居座り、外へ長くつながり続け、そこからシェルなどのプロセスが生まれる流れを一続きで見る[1]。AA23-025A も、RMM の実行のログを見て、ポータブル版として動いている不自然な使い方を探すよう勧めている[3]。

自分の環境で確かめる

試すのは、自分の機械か、学習用に用意した仮想マシンと、許された演習の環境だけにする。他人の端末に RMM を入れたり、他人の管理画面に触れたりしない。

自分の Windows の仮想マシンで、ふつうのソフトを一つ入れたあと、イベントビューアーの「Windows ログ」→「システム」を開き、イベント ID 7045 で絞り込むと、サービスが入った記録と、名前・場所・開始の方法が見られる[15]。PowerShell なら Get-WinEvent -FilterHashtable @{ LogName='System'; Id=7045 } で同じものを取り出せる[17]。出てきたサービスがどのソフトのものかを一つずつ確かめておくと、ふだんの姿（ベースライン）が分かる。

許可リストを試すなら、学習用の仮想マシンで、App Control の監査モードの方針を入れ、CodeIntegrity のログのイベント ID 3076 に何が残るかを見る[13]。強制に切り替える前に、復旧の手段を用意しておく。
