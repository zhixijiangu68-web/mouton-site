SIEM が XDR に置き換わったことを示す公的な調査は、探した範囲では見つからず、似た名前の道具は、公的な手引きと製品の説明では、ログを渡し合い、機能が重なる関係として書かれていた。この記事は、似た名前の道具との違い、主な製品、入れたあとの難しさ、MITRE ATT&CK の使い方、自分のラボで SIEM に触れる方法を、公式の資料で確かめたものだ。SIEM の仕組みは1本目、検知のルールと SOC の仕事は2本目に書いた。

SOAR・EDR・XDR・ログ管理との違い

似た名前の道具は、何を見て、何をするかで分けると違いが分かる。下の表は僕の整理だ。

似た名前の道具の違い（僕の整理）
名前主に見るもの主にすること
ログ管理あらゆるログ集めて、保存し、検索できるようにする
SIEM多くの機器の、セキュリティにかかわるログ形をそろえ、つなげて分析し、アラートを出し、保存する
SOARSIEM のアラートや、ログプレイブックに沿って、対応を自動にする（端末の切り離しなど）
EDRパソコンやサーバーの中の動き端末で怪しい動きを見つけ、その端末で対応する
XDR端末に加えて、ネットワーク・メール・クラウドなどいくつもの領域の検知と対応を一つにまとめる（範囲は製品ごとに違う）

ログ管理と SIEM の境目は、セキュリティのための分析をするかどうかにある。NIST の SP 800-92 が扱うのはログの管理全体の基盤づくりで[1]、SIEM はその上で、セキュリティのための分析とアラートを受け持つ。

SOAR は、SIEM の隣に置かれることが多い。実務者向けの手引きによると、SOAR の中には、自分でログを集めて分析するものもあれば、すでにある SIEM とつないで、その機能を使うものもある[2]。

EDR は、端末の中を深く見る道具で、SIEM にログを渡す側にある。共同の手引きは、SIEM に入れるログの優先の最初に、EDR のログを置いている[3]。

XDR は、端末の外まで検知と対応を広げる考え方で、どこまでを XDR と呼ぶかは製品ごとに違い、一つの定義にまとまっていない。製品の側でも境目は重なっている。Wazuh は自分を XDR と SIEM の機能を一つにした基盤だと説明し[4]、Microsoft Sentinel は、クラウドで動く SIEM で、SOAR の機能も持つと説明している[5]。

主な製品は、提供のしかたと土台で分かれる

SIEM の製品は、クラウドのサービスとして使うものと、自分のサーバーやプライベートクラウドで動かすものに分かれ、土台にする基盤もそれぞれ違う。下の表は、勉強の中でよく名前を見る製品を、公式の説明に書かれた種類だけ並べたもので、どれを勧めるものでもない。

主な SIEM の製品と、公式の説明での種類
製品公式の説明での種類
Splunk Enterprise SecuritySplunk の基盤の上で動く SIEM。検索と相関の機能を使い、事案の管理、アラートのトリアージ・調査・対応をつなぐ[6]
Microsoft SentinelMicrosoft のクラウドで動く SIEM。SOAR の機能も持つ[5]
Elastic SecurityKibana に組み込まれた機能で、Elasticsearch と Kibana があれば使える。脅威の検知、クラウドのセキュリティ、端末の保護を一つにまとめる[7]
IBM QRadarネットワークのイベントや通信の流れ（フロー）のデータをリアルタイムに取り込み、まとめ、保存し、監視・アラート・「オフェンス」（QRadar での事案の呼び名）に使う[8]
Wazuh無料のオープンソース。XDR と SIEM の機能を一つにした基盤。エージェントと、インデクサー・マネージャー・ダッシュボードの三つの中心の部品でできている[4]

Gartner も、SIEM は SaaS として、または利用者の側のオンプレミスやプライベートクラウドで提供される、と書いている[9]。どれが合うかは、組織の環境と、すでに使っている道具で変わる。

入れたあとに難しいのは、お金とデータと人

SIEM は入れたあとに、取り込む量で増える費用、止まっても気づきにくいデータの取り込み、ルールを合わせる人、の三つで手間がかかる。

経営層向けの手引きは、SIEM と SOAR の費用として、製品の料金のほかに人の費用を挙げている。専門の技能を持つ人を雇ってとどめる費用、いまいる人の技能を上げる費用と続けての訓練、外に任せるならその委託料だ。料金はデータの取り込みの量で決まる仕組みが多く、取り込みを管理しないと払いすぎる危険がある、とも書いている[10]。一方で手引きは、適切に入れて動かす費用より、サイバーのインシデントが起きたときの費用のほうが、はるかに大きくなりうるとも書いている[10]。

ログの取り込みは、一度つないだら終わりではない。機器の更新でログの形が変わる、エージェントが止まる、送り先の設定が消える。そうなっても、SIEM の画面には何も起きていないように見える。アラートがないことと、何も起きていないことは違う。共同の手引きが、取り込みが正しく続いているかを定期的に確かめるよう勧めているのは、このためだ[3]。

ルールを調整するには、その組織のふだんの姿を知っている必要がある。誰が夜中にサーバーへ入るのか、どのアプリケーションが変わった動きをするのかは、製品の標準のルールには書かれていない。組織に合わせる作業は、組織のことを知る誰かがすることになり、手引きが「入れたら終わり」ではないと書いて技能を持つ人の費用を挙げているのも、この部分にあたる[10]。

MITRE ATT&CK は、ルールの抜けを探す地図になる

MITRE ATT&CK は、SIEM のルールに番号を付けることと、検知の抜けを探すことの二つに使われている。ATT&CK は、実際に観測された攻撃者の戦術と技術をまとめた知識のベースだ[11]。2026年10月に出た版（v20）の企業向けのマトリクスには、偵察から影響までの15の戦術と、227のテクニック、479のサブテクニックがある。数は、公開のデータから、取り消し・廃止されたものを除いて僕が数えた[11]。

一つめの番号付けでは、2本目で見た Wazuh のルール 40112（失敗が続いたあとの成功）に、T1078 と T1110 が付いている[12]。Elastic の SSH のルールにも、総当たり、パスワードの推測、パスワードスプレー、正規のアカウントといった ATT&CK の項目が書かれている[13]。アラートが出たとき、それが攻撃のどの段階にあたるかが、番号から分かる。

二つめの抜け探しでは、自分の SIEM のルールを ATT&CK の表に重ね、どの技術に検知があって、どこが空いているかを見る。Elastic の手引きも、足りないところを ATT&CK で探す段階を、検知の仕組みを育てる流れの中に置いている[14]。Wazuh のダッシュボードにも、ATT&CK の画面がある[4]。

表が埋まっていることと、検知できることは同じではない。ルールがあっても、必要なログが入っていなければ鳴らない。しきい値が環境に合っていなければ、鳴りすぎて読まれない。ATT&CK の検知の例が、使うログの種類と、調整する項目まで書いているのは、そこまでそろって初めて検知になるからだ[15]。

自分のラボで SIEM に触れる

SIEM は、無料の版と公開のデータを使えば、自分のパソコンの中の仮想マシンや、自分で契約したクラウドの中で学べる。試すのは自分が持っている環境の中だけにする。他人のシステムやサービスに、許可なくログインを試したり、攻撃をまねた通信を送ったりすることは、日本では不正アクセス禁止法などに触れるおそれがある[16]。

Wazuh の手引きには「概念実証（proof of concept）」のガイドがある。ラボに仮想マシンを使い、最初の設定のすぐあとにスナップショット（その時点の状態の保存）を取って、試すたびにきれいな状態に戻すことを勧め、小さなラボなら中心の部品を1台にまとめた構成で足りるとしている。ガイドの中には、総当たりのログインの検知を確かめる例もある。自分で用意した端末どうしで認証の失敗を起こし、Wazuh が複数の認証の失敗をつなげてアラートにするところを見る流れだ。ラボは、失敗を起こす側の Ubuntu 22.04、SSH を受ける RHEL 9.0、RDP（リモートデスクトップ）を受ける Windows 11 の3台で組み、アラートはダッシュボードの「Threat Hunting」の画面で、ルールの番号（Linux なら 5551 や 5712、Windows なら 60122 や 60204）で絞り込んで見る[17]。2本目で見た相関のルールが、自分の画面でどう鳴るかを確かめられる。

Elastic Security は、Elasticsearch と Kibana があれば使える[7]。検知ルールの公開のリポジトリの説明によると、Elastic Stack の標準の配布物に含まれる無料の機能の範囲でも、検知の画面を開けば最新のルールが入る[18]。どの機能が無料かは版とサブスクリプションで変わるので、使う前に公式の表で確かめる。ルールの中身はリポジトリで公開されていて、どんな条件で鳴るのかを一行ずつ読める[13]。

Splunk には「Splunk Free」という無料の版がある。公式の説明では、1日に取り込めるのは500MBまでで、期限はない。ただし1台だけで動かす使い方に限られ、作ったアラートは動かない[19]。Splunk が公開している「Boss of the SOC（BOTS）」の第3版は、セキュリティの練習用のデータセットで、CTF の形で問題を解く使い方もできる。データは取り込み済みの形で配られていて、取り込みの量による制限を気にしなくてよいと説明されている。AWS の CloudTrail や VPC のフローログなど、クラウドのログも含まれている[20]。攻撃の通信を自分で起こさずに、すでに記録されたログで調べる練習ができる。Splunk は、自分のクラウドの中に検知を試すための環境を組み立て、攻撃をまねて、そのログを Splunk に流す「Attack Range」も公開している[21]。こちらはクラウドの費用がかかり、使えるのは自分で契約した環境の中だけだ。

JPCERT/CC の LogonTracer は、Windows の Active Directory のイベントログから、ログオンに関わるイベントを読み、ホスト名（または IP アドレス）とアカウント名を結んでグラフにする道具だ。どのアカウントで、どの端末からログインが試されたかが、図で分かる[22]。SIEM そのものではないが、4624 や 4625 といったイベントが、つなげるとどう見えるかを学ぶのに向いている。
