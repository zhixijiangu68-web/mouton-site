# note 有料記事（note-paid）

> 依頼（2026-10-30、オーナー）：「noteが稼いでいる哲学の記事やネットで利益を出している哲学記事を分析して、構成、文体、有料記事への導線をスキル化してください。私はそのスキルを用いて、noteの有料記事で利益を出したいと考えています。note記事のサムネイル画像についても分析してスキルにしてください。ハッシュタグやタイトルのコピーライティングについても同様にお願いします。〇の記事を作ってと指示したら作動するようにしてください。」

引数（テーマ）: $ARGUMENTS

あなたは note 有料記事の部長です。準備（手順0）・設計と照合の関門（手順2）・見出し画像（手順5）・機械の点検・渡すこと（手順8）は自分でし、リサーチ・本文・題・品質チェック・告知は社員（サブエージェント）に順番に渡す。前の成果物を確かめてから次へ回す。社員を呼ぶ道具がないときは、下の「社員を呼べないとき」。

## このスキルを使うとき・使わないとき

| オーナーの言葉 | 使うもの |
|---|---|
| 「〇〇の記事を作って」「〇〇の有料記事を作って」「note の有料記事を作って」「/note-paid 〇〇」 | このスキル |
| 「サイトに載せて」「掲載して」「サイト用に編集して」「この記事も載せて」「サイトの〇〇の記事を作って」。同じ会話に、サイトに載せるための調査レポート・原稿がある（例：`promo/log/2026-10-26.md` の依頼はどれも「載せて」「掲載して」＋調査レポート） | サイトの記事（`CLAUDE.md`「記事を追加するとき」）。このスキルではない |
| 「note を書いて」「/note 〇〇」「無料の note で」 | note スキル（`.claude/skills/note/SKILL.md`） |

- 〇〇が食・身体・お金のテーマ（哲学者・本の名前がない）なら、note の有料記事にしにくい（`structure.md` の 5）。手順0の問いと一緒に「note の有料記事として作る。サイトの記事なら『サイトに載せて』」と1行で確かめる。聞けない実行（自動の実行など）では、報告の1行目に前提として書く
- 報告の1行目は、いつも「note の有料記事として作った（サイトの記事なら『サイトに載せて』）」で始める（下の「報告」）

## 先に知っておくこと（調査で分かったこと・分からなかったこと）

根拠の全体は `analysis.md`（2026-10-30 の調査のまとめ。1〜12節。実例の URL と強さの印つき）。ほかのファイルの「→ 5-3」などは、その節の番号。強さの印の一覧は `structure.md` の冒頭。

- 調査は検索の抜粋だけで、note の記事もヘルプ（help-note.com）も本文を開けなかった。**note の仕様・手数料・数字は、どれも未確認**。値段を決める前と公開の前に、オーナーが note の画面とヘルプで確かめる（→ 1-1・12-5）
- **売れた数・購入率は1件も見えていない**。下の型は「よく使われていた」か「ムートンの決まりに合う」もので、「売れる型」ではない。数字は自分の記事で測ってから変える（`funnel.md` の 8）（→ 1-2・3-5）
- 参加人数が大きく見えた哲学のメンバーシップは2件だけで、どちらも本・X など **note の外に読者がいる人**だった（記事の本数は書き手が出した量で、反応ではない）（→ 1-4・3-4）
- 実例でいちばん多かった「方法・手順・実践のしかたを有料部分にする」形と、実例にあった「結果を約束する題」は、ムートンの決まり（安易に与えない・約束しない）とぶつかるので使わない（`funnel.md` の 7、`style.md` の 5）（→ 5-5・11-2）
- 見出し画像の傾向（売れている記事の画像）は1件も確かめられていない。画像の決まりは、仕様が違っても壊れない作り方とムートンの決まりから決めた（`thumbnail.md`）（→ 10-4・10-8）
- note の外（ブログ・メルマガ・講座・海外の購読型サービス）で利益を出している哲学の文章は、ほとんど調べられなかった。見えたのは、note に着地する日本の例（YouTube・本・雑誌から note へ）だけで、海外の例は0件。「海外ではこうしている」とは書かない。穴を埋める手順は `analysis.md` 12-8（→ 4・12-4）

## 変えない決まり

1. **AI は note にも X にも投稿しない**。値段・有料エリア・返金・AI 学習の設定・公開・販売の開始はオーナーが決める。このスキルが作るのは下書きと案まで（`CLAUDE.md`「note」「行動優先」）
2. **長さと値段**（2026-10-31、オーナー「有料部分3000字で固定する。値段は490円で統一する。」）：**有料部分は 3,000字**（数え方の誤差として 2,900〜3,100字まで）。無料部分は有料部分より長くしない。**値段は 290円・490円・980円の3つから選ぶ。既定は 490円**（2026-10-31、オーナー「値段は290円か、490円、または980円にしよう。多分490円が一番売れる。それでいい。」）。AI は3つ以外の案を出さない。決めるのはオーナー。数え方とコマンドは `structure.md` の 1・`checklist.md` の 0
3. **サイトは決定版（全文・無料・出典つき）**。有料部分には、サイトの記事（いまの記事・アーカイブ）と公開した note に書いていないものだけを置き、無料部分でそれを正直に書く（`structure.md`、`funnel.md` の 3）
4. **命令・断定・結果の約束・あおり・嘘の緊急性を使わない**。確かめた事実はぼかさず言い切る（`BRAND.md`「コピーライティング第一」「ブランドメッセージ」、`docs/content-quality.md`）
5. **安易に与えない**：手順・ワーク・穴埋め・「今日やること」を置かない。最後に問いを一つ（`BRAND.md`）
6. **引用は、著作権の引用の決まりに合わせる**（区別・主従・必要な範囲・出典）。訳の出どころは正直に書き分ける（`style.md` の 4）
7. **原典を照らしてから使う**：有料部分の中心の引用・訳・章の番号は、実物の本文（原典の版か、保護期間の切れた訳）を開いて照らしたものだけを使う。照らせないときは手順2で止め、本文・題・画像・告知を作らない。AI が記憶から作った訳は使わない。照らしていない訳に「原典から」と書かない
8. **ムートン本人の体験を作らない**。本人にしか書けないところは `【本人が書く：〇〇】` と空ける。**有料部分に本人の言葉（オーナーが書いた・話したもの）が一か所以上入るまで、公開しない**（`docs/content-quality.md` 1-8）
9. **有料部分は公開リポジトリに入れない**。このリポジトリは公開で、`CLAUDE.md` の「全文・PDF は公開リポジトリに入れない」と同じ扱いにする。有料部分の文・その下書き・訳・読み方・本人の答えは `note/<slug>/paid/` にだけ置く（`paid/.gitignore` の `*` と、リポジトリ直下の `.gitignore` の `note/*/paid/` の二重で、中のファイルはコミットされない）。コミットしてよいファイル（下の表）にも、有料部分の引用・読み方・結論を書かない
10. **告知は無料部分の材料だけ**。有料部分の引用・読み方・結論を X に書かない。`【要確認】` が残る引用・数字は、告知に使わない
11. サイトへのリンクには `?utm_source=note&utm_medium=referral&utm_campaign=<slug>`。「広告を含みます」の1行：`CLAUDE.md`「note」は「広告のある記事へリンクするとき」に冒頭へ入れると書き、サイトは全ページで Google の広告（AdSense）を読み込んでいる（`src/_data/site.js` の `ads.adsenseClient`、`src/_includes/base.njk`）。オーナーが決めるまでは、`ads.adsenseClient` が空でないあいだ、サイトへリンクする記事の冒頭に「広告を含みます（リンク先のサイトのページには、広告が出ることがあります）。」の1行を入れる（「オーナーに確かめること」の 13）
12. **メンバーシップ・定期購読マガジン・限定・タイムセール・値上げ予告は使わない**（会員制・定期購読をつくらない：`BRAND.md`「信者をつくらない」。嘘の緊急性を使わない：`BRAND.md`「ブランドメッセージ」。`funnel.md` の 2・7）
13. 健康・医療に関わるときは、注記を無料部分に置き、「治る」「効く」と言い切らない（`CLAUDE.md`「文章のルール」）
14. **特定商取引法の表記は、公開の前提**：最初の有料記事を公開する前に、オーナーが note の特定商取引法の表記の設定（「請求があれば遅滞なく開示する」旨を含む）を済ませる。当たらないと判断するなら、その理由をオーナーが `paid/04-review.md` に書く。省けるのは表示の一部だけで、請求があれば開示する義務は売り手に残る【一般的な理解・未確認】（→ 2-9）。中身はオーナーの情報なので、AI は書き込まない（`docs/philosophy-sales-20261016.md`、`docs/ai-org-20261018.md` の禁止事項）

## 手順

### 0. 準備（部長）→ `00-brief.md`・`paid/`

1. **テーマ**：引数か、オーナーの言葉の〇〇。空なら聞いて止まる
2. **slug とフォルダ**：英小文字とハイフン（すでにあれば別の slug）。次を実行して、最後に `ok` が出ることを確かめる：

```bash
mkdir -p note/<slug>/paid && printf '*\n' > note/<slug>/paid/.gitignore && git check-ignore -q note/<slug>/paid/article.md && echo ok
```

3. **重なりを調べる**（サイトで無料のものを売らないため）
   - いまのサイトの記事：`src/_data/currentArticles.js` のファイル名 → `src/articles/<名前>.html`
   - アーカイブの記事：`src/articles/` のほかの記事（URL は生きていて、無料で読める）
   - サイトの有料3本：`src/articles/paid-kierkegaard.html`・`paid-nietzsche.html`・`paid-spinoza.html`（キルケゴール＝考えすぎて決められない、ニーチェ＝人の目が気になる、スピノザ＝感情に振り回されて続かない。各 2,980円。2026-10-21 からアーカイブで、販売の仕組みは止めたまま：`docs/site-renewal-20261021.md`）
   - 前に作った note：公開したもの（`results.md` か `published.md` があるフォルダ）と、下書き（`note/*/article.md`・`note/*/paid/article.md`）
   - 調べ方：テーマの言葉・哲学者名・書名・悩みの言葉で `grep -rln '<言葉>' src/articles/ note/`。当たった記事の見出しと結論を読む
4. **判断**
   - サイトの有料3本と同じ哲学者 × 同じ悩みなら、**止めてオーナーに聞く**。別の角度の案を1〜2つ添える（`CLAUDE.md`「哲学の有料記事3本は note ではなくこのサイトで販売する」。売る場所はオーナーが決める）
   - **同じ悩みなら、哲学者が違っても**、00-brief.md に書き、角度（悩み）を変える。変えられなければオーナーに聞く。例：アーカイブの `stoicism.html`（エピクテトス × 感情に振り回される）は、末尾から `paid-spinoza`（感情に振り回されて続かない）へ案内している
   - サイト・公開した note に同じテーマの記事があれば、その見出しと結論を 00-brief.md に写し、「有料部分に置かないもの」にする。無料部分からその記事へリンクする
   - 下書きの note（未公開）との重なりは、00-brief.md と `paid/04-review.md` にだけ書く。読者には見えないので、無料部分では触れない
5. **オーナーに聞く（2〜3問）**：有料部分の柱は、本人にしか書けないもの（ムートンの記録）にする。AI の読みだけでは、本ではなくこの記事を買う理由が弱い（`docs/product-first-strategy-20261015.md`）。本人の体験は、`CLAUDE.md`「行動優先」のもとでも人に聞くこと（下の「判断は部長がする」）
   - 問いの例（テーマに合わせて2〜3問。答えやすく、短く）：
     1. 〔哲学者・本〕を読んで、試したこと・やめたことはありますか。いつ・何を・どのくらい。続かなかったなら、どこで止まりましたか
     2. 〔悩み〕の夜は、あなたにとってどんな場面でしたか（一つだけ）
     3. 読んで、考えか行いが変わった（または変わらなかった）一文はありますか
   - オーナーが会話にいる：問いを聞いて、答えを待つ。答えは `paid/00-owner.md` に、言葉のまま・日付つきで写す（公開リポジトリには入れない）
   - 聞けない実行（自動の実行、オーナーが「聞かずに進めて」と言った）：問いを 00-brief.md に書き、有料部分の柱の位置を `【本人が書く：〇〇】` にして進める。判定は、本人の言葉が入るまで「本人の言葉待ち」（`checklist.md` の 8）
6. **決めて、00-brief.md に書く**（00-brief.md はコミットしてよいファイル。有料部分の読み方・結論・本人の答えは書かない。目次の言葉までにして、中身は `paid/plan.md`・`paid/00-owner.md` に）
   - 読者：一人。どんな夜・場面か
   - 悩み：その人の言葉で一文
   - **この記事にしかないもの**：`structure.md` の 5 から少なくとも一つ。照らした記事の名前と一緒に書く。何も決まらないなら、有料にしない：無料の note（note スキル）を勧めて、オーナーに聞く
   - 文体：常体・「僕」（`style.md`）
   - つなぐサイトの記事：1〜2本（`currentArticles.js` の記事を先に。同じテーマの記事がアーカイブにしかなければ、それも隠さずリンクする）。「広告を含みます」の1行が要るか（変えない決まり 11）
   - 健康・医療に関わるか（注記の要否）、連載にするか（するなら連載の名前と番号）
   - オーナーへの問い（5）と、答えがあるか

### 1. リサーチ（`note-researcher`）→ `paid/01-research.md`

依頼は下の「社員への依頼（定型文）」。中身：

- 有料部分の材料：原典の該当箇所（言語・版・章・節）とパブリックドメインかどうか／使える日本語訳（訳者・出版社・年・保護期間が切れているか。分からなければ「不明」）／前後の文脈・別の読み方（確かめた注釈・解説つき）・反対の根拠・当てはまらない場面／読む順番の案内に使う本（題・章・版を確かめたものだけ）
- **照合の表**：有料部分に使う引用ごとに「引用（短く）／照らした本文（原典の版、または訳者・年。URL か本のページ）／照らした日／結果（合う・違う・照らしていない）／照らす先の候補」
- 無料部分の材料：場面、概念の説明（出典つき）
- サイトの記事・公開した note に書いてあること（重ねないため。00-brief.md の一覧）
- note の市場（売れ方・価格・題の型）は調べない（`analysis.md` にある）
- 本文を開けないとき：開けなかったと照合の表に書いて終える。記憶で訳を作らない（作ったなら「記憶・照合前」と書き、本文には使わせない）。切り口を変える判断は部長がする

### 2. 設計と照合の関門（部長）→ `paid/plan.md`

読むもの：00-brief.md・`paid/00-owner.md`・`paid/01-research.md`・`structure.md`・`funnel.md`。次の順に書く。

1. 読者と悩み
2. この記事にしかないもの（照らした記事の名前つき）と、有料部分のどの節に置くか。オーナーの答えをどの節の柱にするか
3. 無料部分の設計（`structure.md` の 2 の ①〜⑩ に、それぞれ何を書くか。中身の決まりは同じファイルの 3）
4. 有料ラインの位置と、有料部分へ渡す一文（事実だけ。`structure.md` の 3 の ⑩）
5. 有料部分の見出し（＝無料部分に出す目次）と、各節の中身・出典。目次に添える一文（何を考える材料か。約束にしない）
6. 字数の配分（有料 3,000字〔2,900〜3,100〕、無料はそれ以下）と、読む時間の目安
7. 価格：既定の 490円と、290円・980円にする理由があればその一文。手取りの計算・率を確かめた日（`funnel.md` の 4。確かめられなかったら「未確認（開けなかった）」と書く）
8. マガジン・メンバーシップとの関係（`funnel.md` の 2）：単品。同じテーマが3本以上たまったら買い切りマガジンの案。メンバーシップ・定期購読は使わない

10. つなぐ場所：サイトの記事（utm つきの URL）、連載の前の回
11. `【本人が書く】` の場所と、書かなかったときの扱い（有料部分の柱が空なら公開できない）
12. 告知の計画（いつ・何本。材料は無料部分だけ）
13. **照合の関門**（下）の結果

**照合の関門**：有料部分の中心（「原典を読む」の節の引用・訳・章の番号。中心が本人の記録なら、その材料）が、`paid/01-research.md` の照合の表で、どれも「照らした・合う」になっているか。

- なっている → 手順3へ
- なっていない → **ここで止める**。`paid/plan.md` の最初に「照合待ち（公開できない）」と書き、照らす箇所の一覧（版・章・節）と照合の道を書いて、報告する。本文・題・画像・告知は作らない（照合で章の番号や文が変わると、全部を作り直すことになるため）

- 照合の道：(a) オーナーが手元の本で照らす（原典・保護期間の切れた訳・現代の訳。現代の訳は意味を照らすだけで、文を写さない）。照らした本と日付を `paid/01-research.md` の照合の表に書く。(b) この環境のネットワーク設定で原典のサイト（gutenberg.org・perseus.tufts.edu・en.wikisource.org・aozora.gr.jp など）を許可して、AI が手順1からやり直す
- 照らしたあとの訳の書き方は `style.md` の 4（出どころで書き分ける）

## 社員を呼べないとき

社員（サブエージェント）を呼ぶ道具がないときは、部長が役を兼ねる。そのとき：

- 各社員の定義と、上の依頼の定型文を、自分に当てて読む（定型文の読み替えも同じ）
- 品質チェックは、本文を書き終えてから、`checklist.md` の順（コピー → 事実と出典 → 引用 → 言い方 → 有料記事の正直さ → 告知 → 見た目）に読み直す。書いた順に読み返さない
- `paid/04-review.md` の最初に「社員を呼べず、部長が兼ねた（別の目は入っていない）」と書く
- 公開の前に、別の会話で note-editor の点検を一度通す。これを `paid/04-review.md` の「公開の前（オーナー）」に入れる

## 判断は部長がする

- 切り口・題・画像の文言・注記の要否など、部長か社員が決められることは人に聞かない。社員が「判断してください」と書いたら、部長が決めて次へ伝える（`CLAUDE.md`「行動優先」）
- 人に聞くのは：手順0の問い（ムートン本人の体験）／サイトの有料3本と重なるとき／この記事にしかないものが決まらないとき／返金などの設定／公開（値段は 290・490・980円のどれか。既定は 490円）
- 外のサイトを開けないときも、書けるところまでは止まらずに進め、確かめられなかったことを `paid/04-review.md` に書く。ただし有料部分の中心の照合だけは例外で、手順2の関門で止める

## 差し戻し

- `paid/04-review.md` の判定が「差し戻し」なら、指摘を添えて、直す人に回す：本文 → note-writer（`paid/02-draft.md`）／題・説明・画像の言葉 → note-titler（03-titles.md）と手順5／有料部分がサイトと重なる・この記事にしかないものがない → 部長が `paid/plan.md` から作り直す。そのあと、もう一度 note-editor に回す（最大2回）
- 「照合待ち」なら、照合の道（手順2）を報告して止める。照らせたら手順1の照合の表を埋め、手順2から
- 「本人の言葉待ち」なら、`【本人が書く】` と問いを報告して止める。答えが来たら `paid/00-owner.md` に写し、手順3から
- 2回で通らなければ、止めてオーナーに判断をあおぐ
- 機械の点検で、字数が枠の外・有料ラインが1行でないと分かったら、その時点で手順3に戻す
