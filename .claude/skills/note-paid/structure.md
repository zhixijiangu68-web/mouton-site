# 構成の型：無料部分 → 有料ライン → 有料部分

note の有料記事で、買う前に読めるのは有料ラインより上（無料部分）だけ。だから無料部分は「読んだ人が、買うかどうかを自分で決められる場所」にする。有料部分には、サイト（全文・無料・出典つきの決定版）に書いていないものだけを置く。

強さの印：【決まり】このリポジトリの決まり／【公式・未確認】note のヘルプを検索の抜粋で見ただけ（本文は開けていない）／【報道・未確認】note 社の発表を報道・転載で見ただけ／【実例・未確認】note の記事で見えた（ページ本体は開けていない。売れた数は1件も見えていない）／【個人・未確認】個人のブログ・伝聞・解説／【一般的な決まり】日本の著作権法の「引用」などで一般に言われる条件（条文・判例はこの調査では確かめていない）／【一般的な注意・法令は未確認】【一般的な理解・未確認】一般的な注意・理解で、法令・公式の本文は確かめていない／【計算】／【推測】／【未調査】。`analysis.md` の 1-3 のラベルとの対応：【決まり】＝【リポジトリ・確認】、【実例・未確認】＝【複数の実例／一つの実例・未確認】、【個人・未確認】＝【個人の説明・未確認】。

根拠の全体は `analysis.md`。各決まりの末尾の「→ 5-3」などは、`analysis.md` の節の番号。

---

## 1. 長さ（オーナーの決まり。有料記事でも変えない）

- **本文は、無料部分と有料部分を合わせて 2,000〜4,000字**。【決まり】CLAUDE.md「長さ」（2026-10-22、オーナー「noteが中くらい」）。note はサイトの記事（本文1万〜2万字）より短い「中くらい」で、有料記事もこの枠の中で作る。この決まりは無料の note のために作られ、有料記事の長さは決まっていなかった（→ 5-5・12-1）が、オーナーが変えるまではこの枠を使う
- **数え方**：本文の文字だけ。数えないもの：題の行（`# `）、見出しの記号（`##`・`###`。見出しの文字は数える）、引用と箇条書きの記号、太字の `**`、リンクの記号（`[題](URL)` の `[` `]` と URL。題の文字は数える）、URL、空白、`【有料ライン】` の行、`【本人が書く：…】`・`【要確認：…】` の空欄、参考文献の節（`## 参考文献…` から下）。無料部分・有料部分・合計の3つを出す（コマンドは `checklist.md` の 0）
- **配分の目安**（このスキルの目安。調査の数字ではない）：無料部分 900〜1,600字、有料部分 1,100〜2,400字。無料部分は下の 3 の要素がそろう長さ、有料部分は無料部分の目次で約束したことが全部入る長さ
- **有料部分は、無料部分より短くしない**（このスキルの決まり）。払った人が受け取る中身が、立ち読みより薄くならないように
- **長くするために水増ししない**。有料部分の文字数と売上の相関はほぼゼロだった、という note 社の分析がある【報道・未確認】。値段は長さでなく、「この記事にしかないもの」で説明する（→ 2-8・5-2）
- 有料部分だけで1万字を超える有料記事の実例もある（哲学の学び方の記事、¥980、有料部分 12,176字の表示。1件だけ）【実例・未確認】。売れた数は分からない。それでも長さはオーナーの決まりに従う（変えるかどうかは `SKILL.md`「オーナーに確かめること」）（→ 5-4）
- **読む時間**：有料部分の字数を 500 で割って切り上げた分（サイトの読了時間と同じ数え方：`src/articles/articles.11tydata.js` の `CHARS_PER_MINUTE`）。測った事実として目次に書く（「〇分で分かる」のような約束にしない。`style.md` の 5）

## 2. 全体の順番（1枚で）

| 部分 | 置くもの（この順） | なぜ |
|---|---|---|
| 無料部分 | （広告の1行）→ ① 1行目 → ② 誰の、どんな夜か → ③ 問い → ④ 考え方の土台（出典つき） → ⑤ サイトとの関係 → ⑥ 書かないこと（限界） → ⑦ 書いている人 →（⑧ 健康の注記）→ ⑨ 参考文献（無料部分） → ⑩ 有料部分に書いたこと（目次・分量・読む時間） | 買う前に見えるのはここだけ【公式・未確認】。中身を先に見せる【決まり】BRAND.md「信者をつくらない」。有料ラインの直前を目次にするのは、スマホで「参考文献で記事が終わった」と読まれず、買うかどうかを決める材料（何が書いてあるか・どのくらいか）が線のすぐ上に来るように（→ 5-1・5-6） |
| 有料ライン | `【有料ライン】` の1行 | オーナーが note の画面で「有料エリア設定」を置く場所を、迷わず見つけられるように |
| 有料部分 | サイトにないもの（ムートンの記録・原典を読む・当てはまらない場面など）→ 最後の問い → 参考文献（有料部分） | サイトは決定版で無料【決まり】CLAUDE.md。同じものを売ると、買った人が損をする |

## 3. 無料部分に置くもの

**広告の1行**（いちばん上。題のすぐ下）：`SKILL.md` の「変えない決まり」11 のとき（サイトへリンクし、サイトが広告を読み込んでいるあいだ）、「広告を含みます（リンク先のサイトのページには、広告が出ることがあります）。」。【決まり】CLAUDE.md「note」（→ 11-2）

1. **1行目：いちばん強い一文**。読んでいる一人が「自分のことだ」と思う場面か、常識の反対の一文か、意外な一文。まだ何も起きていない場面で始めない。【決まり】`docs/content-quality.md` の 0-1。note は一覧で題と見出し画像を見て開き、冒頭から読まれる（→ 5-6・6-2）
2. **誰の、どんな夜の話か**（冒頭の3段落まで）。定義や「〜とは」から入らない。【決まり】content-quality 1-1。この記事で何を読むかも一文で言う（例の形：「この記事では、〔哲学者〕の〔本〕から一章ずつを、〔悩み〕の夜に当てて読む。」）。有料部分の結論・読み方は、ここに書かない。実例では、無料部分で悩みをどう書いたかは見えていない（→ 5-3）
3. **問い**（太字の一文）。【決まり】content-quality 3
4. **考え方の土台を、出典つきで**：有料部分を読むのに要る概念・背景・例。哲学者の言葉は短く、出典つき（`style.md` の 4）。実例でいちばん多かったのは「概念・背景・例は無料、使い方・実践は有料」【実例・未確認：記録で裏づくのは3件】（→ 3-4・5-3）
5. **サイトとの関係**：サイトで無料で読めるもの（記事の題にリンクを付ける：`[記事の題](https://moutonarchive.com/<記事>.html?utm_source=note&utm_medium=referral&utm_campaign=<slug>)`。URL だけの行を書かない）と、この記事にしかないもの。同じテーマの記事がサイトにない場合は、つながる記事を1本だけ。読者に「前の note」と言うのは、公開した note だけ（下書きは読者に見えない）。【決まり】CLAUDE.md（サイトは決定版。note からのリンクの utm）（→ 5-5・12-1）
6. **書かないこと（限界）**：答え・手順・「こうすれば変われる」という約束は書いていない、僕の読み方は唯一の読み方ではない、訳の出どころ（`style.md` の 4。照らしていない訳に「原典から」と書かない）、など。実例でも限界を先に書いていた（「唯一絶対の正しい方法ではない」「あくまで概略」）【実例・未確認：1人・2本】。【決まり】約束しない（BRAND.md）（→ 6-1・11-3）
7. **書いている人**（1〜2文）：迷いながら哲学を自分の毎日で試し、記録している一人。先生ではない（`src/_data/site.js` の bio と同じ線）。経歴・部数・人数で信頼をつくらない（実例の書き手の部数・人数は本人申告で、確かめられない）（→ 1-2・11-2）
8. **健康の注記**（健康・医療に関わるときだけ）：「この記事は一般的な情報の提供を目的としたもので、個別の診断や治療を目的とするものではありません。」買う前の人にも見えるよう、無料部分に置く。【決まり】CLAUDE.md「文章のルール」（→ 11-2）
9. **参考文献（無料部分）**（無料部分に [n] があるときだけ）：無料部分の [n] の出典だけ。買わない人も、読んだ部分の出典を確かめられるように。サイトの記事は題にリンクを付ける（URL だけの行にしない）。番号は有料部分に続けて振る。【決まり】出典つき（CLAUDE.md・content-quality 1-3・1-4）
10. **この記事の有料部分に書いたこと**（有料ラインの直前）：見出しは「## この記事の有料部分に書いたこと」。頭の一文は事実だけ（例の形：「ここから先に、次の3つを書いた（有料部分は約〇字。読む時間は〇分ほど）。」）。続けて、有料部分の `##` の見出しを、そのまま箇条書きで（`- **〔見出し〕**：〔何を考える材料か、一文〕`）。一文は「何が分かるか／何を考えられるか」を、約束にならない形で（「〜を読む」「〜を書いた」。「〜できるようになる」「〜が分かる」と結果を言い切らない）。見出しが引用の形でも、何の材料かが買う人に伝わるように。一つの画面で「何が手に入るか・いくら・何分か」が分かるように【決まり】BRAND.md「コピーライティング第一」（値段は note が購入の場所に出す【公式・未確認】）。実例でも有料部分の目次・見出しを無料部分で見せていた【実例・未確認：2件】。note の目次の機能に有料部分の見出しが出るかは分からない【未調査】ので、手で書く（→ 2-4・5-3・5-6）

**有料部分へ渡す一文**（⑩ の頭）と、有料ラインの前後は事実だけにする。煽る一文で線を越えさせない。note は線の位置に「ここから先は有料部分です」という区切りを自分で出す【公式・未確認】。

## 4. 有料ライン（paid/article.md での書き方）

`paid/article.md` の中に、次の1行を**1回だけ**置く。前後は空行にして、別の段落にする。

```
【有料ライン】ここから下が有料部分。note では、この行を消し、上の段落と下の段落の間に「有料エリア設定」を置く。
```

- 位置：⑩ 有料部分に書いたこと（目次）のあと、有料部分の最初の見出しの前
- 理由：note の有料エリアは「段落と段落の間」にしか置けない、という説明がある【公式・未確認】。行で示せば、オーナーは note のエディタで検索して見つけられる。`【有料ライン】` の行は、数える文字にも入れない（→ 2-4・5-1）
- 位置の考え方：実例でいちばん多かったのは「考え方の土台を渡したあと、使い方の手前」【実例・未確認】（→ 5-6）
- `paid/02-draft.md`（下書き）にも同じ1行を置く。題の案・記事の説明・告知文には書かない

## 5. 有料部分に置くもの（サイトにないものだけ）

`paid/plan.md` で、少なくとも一つを選ぶ。選んだものが、サイトの記事（いまの記事・アーカイブ）と公開した note に書いていないことを、部長が確かめてから書く。サイトの記事に同じ中身があるなら、有料にする理由にならない（→ 5-5・5-6）。

| 置けるもの | 中身 | 書く人 | 理由 |
|---|---|---|---|
| **ムートンの記録**（柱） | 僕がいつ、何を、どのくらい試したか。続かなかった日を含めて、起きたことだけ | オーナー（手順0の答え `paid/00-owner.md`、または `【本人が書く：〇〇】`） | 本人にしか書けない一次情報で、本ではなくこの記事を買う理由になる（`docs/product-first-strategy-20261015.md`）。長く読まれる記事の特徴は書き手の経験や専門性に基づく「一次情報」だった、という note 社の調査【報道・未確認】。`docs/content-quality.md` 1-8 は、ムートン自身の迷いと試したことを一か所以上求める（→ 2-8・5-6） |
| **原典を読む** | 哲学者の原典の一節（短く）を、照らした本文から訳すか、保護期間の切れた古い訳で読む。前後の文脈 → 僕の読み方 → 別の読み方 | AI（照合の表で「照らした・合う」のものだけ） | いまのサイトの記事（判定表の型）は研究の確かめが中心【決まり】docs/site-renewal-20261021.md。ただしアーカイブの哲学の記事（`src/articles/kierkegaard.html` など）には原典の言葉があるので、同じ一節・同じ読み方になっていないかを確かめる。**別の読み方には、確かめた注釈や解説（書誌つき）を1つ以上つける。確かめられないなら、別の読み方を節にしない**。引用と訳の決まりは `style.md` の 4（→ 5-6・2-9） |
| **当てはまらない場面・反対の根拠** | この考えで動かないほうがいいとき、反対の読み方・反対の研究（出典つき） | AI | 言い切らない決まりと同じ向き【決まり】content-quality 1-4・1-5（→ 5-6「根拠の細かい検討」） |
| **読む順番の案内** | 原典・入門書・サイトの記事を、どの順で、どの章から読むか | AI（書誌を確かめたものだけ） | 本の題・章・版を確かめてから書く。確かめられない本は挙げない（→ 5-6） |

- **有料部分に、本人の言葉が一か所以上**：オーナーが書いた・話した言葉（手順0の答えか、`【本人が書く】` にオーナーが書いたもの）。入るまでは「本人の言葉待ち」で公開しない（`checklist.md` の 8）。AI の読みだけで有料にしない
- **哲学以外のテーマ**（食・身体・お金など）：サイトの記事が、研究を原典まで遡って確かめる仕事を全部している【決まり】docs/site-renewal-20261021.md。だからサイトにないものは、たいてい「ムートンの記録」か、サイトの記事に書いていない一本の研究の読み込み（方法・対象・限界の細部）になる。どちらもなければ有料にしない（`SKILL.md` の手順0）
- 実例でいちばん多かった「方法・手順・実践のしかたを有料にする」形【実例・未確認：記録で裏づくのは3件】は、そのまま使わない。手順を渡すと、読者は「従う人」になる【決まり】BRAND.md「安易に与えない」。実践は、ムートン自身の記録として書く（読者への手順に見えない書き方）（→ 5-4・5-5・11-2）
- 終わり方：**最後に問いを一つ**（答えを書かない）→ 参考文献（有料部分）。【決まり】content-quality 1-7
- 有料部分の最後で、ほかの有料記事・マガジン・メンバーシップに誘わない。【決まり】BRAND.md「取り入れないこと」（購入直後のアップセル）。サイトの無料の記事への案内はよい。次の記事は、無料部分と記事の一覧で知らせる（→ 7-6・11-2）
- 見出しは、読者への決まりに読めない形にする（「〜しない」より、場面の形「〜になるとき」）。【決まり】BRAND.md「安易に与えない」

## 6. 置かないもの（無料部分・有料部分とも）

根拠は `analysis.md` の 11-2（使わないものと、代わりのやり方）と 2-6（「買われています」）。

| 置かないもの | 理由 |
|---|---|
| 値段 | note が購入の場所に値段を出す【公式・未確認】。本文に書くと、オーナーが値段を変えたときに食い違う（ログアウトして値段がどこに見えるかは、オーナーが確かめる：`SKILL.md`「オーナーに確かめること」の 7・9） |
| サイトの記事の言い換え・要約だけの有料部分 | サイトは無料の決定版【決まり】。買った人が損をする |
| 有料部分の結論・読み方を、無料部分や告知に出すこと | 買う前に中身を渡すと、買った人に新しいものが残らない。無料部分に出すのは、目次の見出しと、何を考える材料かの一文まで |
| 手順・ステップ・ワーク・穴埋め（＿＿）・「今日やること」 | 【決まり】BRAND.md「安易に与えない」、content-quality 1-7 |
| 「ここからが本番」「この先で人生が変わる」などの線の前の煽り | 約束しない・あおらない【決まり】BRAND.md |
| 答えを伏せる題・1行目（「〜の理由」「〜の正体」）で引いて、答えを有料部分にだけ置くこと | 題で気を引いて払わせる形になる。使うなら、答えの入口を無料部分に置くときだけ（`titles.md` の 2 の 7） |
| 限定・期限・値上げ予告・割引・「残り○部」・人数 | 嘘の緊急性を使わない【決まり】。偽りの限定・水増しの元値は不当表示になる、という note の説明【公式・未確認】 |
| 買った人の声・「買われています」を根拠にした文 | 実際に聞いた声しか載せない【決まり】docs/product-first-strategy-20261015.md 2.7。「買われています」は「過去24時間に売れた」という意味だという個人の説明がある【個人・未確認】 |
| 作ったムートンの体験 | 本人が書いていないことは `【本人が書く：〇〇】` と空ける【決まり】note-writer |
| URL だけの行 | 長い utm つきの URL が並ぶと、記事が終わったように見える。題の文字にリンクを付ける（note のエディタで変換されるかは、オーナーが一度確かめる） |

## 7. 見本の骨組み（paid/article.md の形）

`analysis.md` 5-6 の構成の案を、ムートンの決まりに合わせて形にしたもの。テーマは見本のための仮のもの（セネカ『人生の短さについて』× 予定は埋まっているのに何も進まない夜）。〔〕は中身が入るところ、（役割：…）は説明で本文に残さない。引用・章・数字は、どれも照らしてから入れる（ここには一つも書いていない）。

```markdown
# 〔題：止まる言葉と主題の言葉。titles.md〕

広告を含みます（リンク先のサイトのページには、広告が出ることがあります）。

〔1行目：いちばん強い一文〕

〔誰の、どんな夜か。場面から。2〜3段落。この記事で何を読むかを一文で〕

**〔問い：太字の一文〕**

## 〔見出しは文で。考え方の土台〕

〔概念・背景・例。僕の文が主〕

> 〔照らした本文から訳した1〜2文〕
> ——セネカ『人生の短さについて』〔章〕（〔訳の出どころ：style.md の 4〕）[1]

〔引用の読み方の入口。答えまでは書かない〕
```
