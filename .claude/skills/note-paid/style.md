# 文体

ムートンの声は、サイト・note・X のどれでも同じ。土台は `docs/content-quality.md` と `BRAND.md`。ここには、それを有料記事に当てたときの決まりと、引用と訳の書き方と、売り手の文体からまねしないことを書く。

強さの印は `structure.md` の冒頭と同じ。根拠の全体は `analysis.md`。末尾の「→ 6-1」などは `analysis.md` の節の番号。

---

## 1. 先に知っておくこと

- 売れている哲学の有料記事の**本文の文体**は、調査で見られなかった。note のページ本体を開けず、見えたのは題・価格・冒頭の数文・説明の抜粋だけ【未調査】。だから文体はムートンの決まりを先にし、実例からは「冒頭で何が読めるかを一文で言う」「限界を書く」の2つだけを借りる（→ 6-1）
- 参加人数が大きく見えた哲学のメンバーシップ（2件）は、生活や仕事に哲学を当てる考え方の文章を続けて出していたが、どちらも本・X など note の外に読者がいる【実例・未確認】。文体をまねても、同じ結果になるとは限らない（→ 3-4・4-1）

## 2. ムートンの声（変えないこと）

どれもリポジトリの決まりで、外の証拠ではない（→ 6-2）。

1. **一人称は「僕」、常体（だ・である）**。1本の中で統一する。【決まり】CLAUDE.md「文章のルール」、content-quality 2
2. **1行目は、いちばん強い一文**。いちばん強い一文が後ろにあれば前に出す。【決まり】content-quality 0-1
3. **一人に語りかける**。「人は〜」より「〜していないだろうか」。ただし「あなた」を毎文に入れない。読者の気持ちを決めつけない。【決まり】BRAND.md「一人に語りかける」
4. **命令・断定・結果の約束・あおり・見下しを使わない**。「〜しなさい」「〜しましょう」「必ず」「〜できるようになる」「人生が変わる」「今すぐ」「損」を書かない。経験と提案で書く（「僕はこうした」「〜かもしれない」「〜という見方を手元に置ける」）。【決まり】content-quality 1-5、BRAND.md「ブランドメッセージ」
5. **具体**：場面・数字・固有名詞・本の章・ムートンがしたこと。「見え方が変わる」のような抽象だけで段落を終えない。【決まり】content-quality 0-2
6. **短く**：一文は短く。段落は2〜4文。雰囲気のための一文・詩的な言い回し・余韻のための改行は削る。【決まり】content-quality 0-3、note-writer
7. **見出しは `##` と `###` だけ、文で書く**（「不安を『めまい』と呼んだ人」）。note のエディタにそのまま移せる。読者への決まりに読める見出し（「〜しない」「〜するな」）より、場面の形（「〜になるとき」）。【決まり】note-writer、content-quality 2、BRAND.md「安易に与えない」
8. **最後に問いを一つ**。答えも、手順も、「今日やること」も置かない。【決まり】BRAND.md「安易に与えない」
9. **表記**：数字は半角、年は西暦、鉤括弧の入れ子は『』、固有名詞はサイトの記事にそろえる。【決まり】content-quality 2。区切りのダッシュは「——」（U+2014 を2つ）にそろえる（引用の出典の行・題の区切り・見出しの区切りとも。リポジトリの記事と同じ）。罫線の「──」（U+2500）は使わない（このスキルの決まり）
10. **読みと事実を分ける**：哲学者の言葉の言い換えか、僕の読みかが分かるように書く（「と彼は言う」「と僕は読む」）。解釈を、哲学者が言ったことのように言い切らない（このスキルの決まり。content-quality 1-5 と同じ向き）

## 3. 有料記事で足すこと

1. **冒頭で、何が読めるかを一文で言う**。実例：冒頭の一文で、記事が何をまとめたものかを言っていた【実例・未確認：1件】（その一文は「〇分で読める」という結果の約束を含んでいたので、形だけを借りる）。ムートンでは約束にならない形で書く（例の形：「この記事では、〔哲学者〕の〔本〕から一章ずつを、〔悩み〕の夜に当てて読む。」）（→ 6-1・6-3）
2. **限界を書く**：「僕の読み方で、唯一の読み方ではない」「答えは書いていない」。実例でも「唯一絶対の正しい方法ではない」「あくまで概略」と書いていた【実例・未確認：1人・2本】。約束しない決まりと同じ向き【決まり】（→ 6-1・11-3）
3. **有料ラインの前後で声を変えない**。線の前で煽らない（「ここからが本番」「この先で人生が変わる」と書かない）。有料部分へ渡す一文は事実だけ（「ここから先に、次の3つを書いた（有料部分は約〇字。読む時間は〇分ほど）。」）。note は線の位置に区切りを自分で出す【公式・未確認】（→ 2-4）
4. **有料部分も同じ密度で**。「買ってくれたあなただけに」のような特別扱いの言葉を重ねない。中身で示す
5. **ムートンの記録は、過去形で、起きたことだけ**：いつ・何を・どのくらい・どうなったか。続かなかった日も書く。読者への手順に見えない書き方にする（「だから僕は〜している」はよい。「〜してみてほしい」を重ねない）。【決まり】BRAND.md「安易に与えない」
6. **本人の体験を作らない**。使ってよいのは、オーナーが会話・Issue・自分の原稿で伝えた経験（手順0の答え `paid/00-owner.md` など）だけ。どこで聞いたかを `paid/02-notes.md` に書く。ないところは `【本人が書く：〇〇】` と空ける（何を何文で書くかの手がかりを添える）。【決まり】note-writer
7. **原典を読む節の順番**：引用（短く・出典つき）→ 前後の文脈 → 僕の読み方 → 別の読み方（確かめた注釈・解説があるときだけ）→ 当てはまらない場面。引用より、僕の文のほうが長い（下の 4 の「主従」）
8. **健康・医療**の話では「治る」「効く」と言い切らない。【決まり】CLAUDE.md「文章のルール」
9. **サイトのトップの見出しなど、note の読者が知らないものを前提にしない**。使うなら、本人の経験として書くか、何のことか分かるように書く

## 4. 引用と訳の書き方（著作権の「引用」の決まりに合わせ、出どころを正直に書く）

下の表の【一般的な決まり】は、日本の著作権法の「引用」で一般に言われる条件（区別・主従・必要な範囲・出典）。条文と判例は、この調査では確かめていない（→ 2-9「古典の翻訳」・10-7）。

**訳の出どころで書き分ける**（いちばん大事。照らしていない訳に「原典から」と書かない）

| 訳の作り方 | 引用の下の行（例の形） | 参考文献に書くこと |
|---|---|---|
| 原典の版と1文ずつ照らして訳した | `——〔著者〕『〔書名〕』〔章・節〕（要約・僕の訳）[n]` | 原典：〔版（編者・出版社・年）〕。照らした日 |
| 保護期間の切れた訳（英訳など）から日本語にした（重訳） | 同上 | 〔訳者〕の英訳（〔書名〕、〔年〕）から訳した。ギリシャ語などの原文とは照らしていない |
| 保護期間の切れた古い日本語訳をそのまま使った | `——〔著者〕『〔書名〕』〔章〕（〔訳者〕訳、〔出版社〕、〔年〕）[n]` | 訳者・出版社・年・保護期間が切れていること（訳者の没年） |
| 現代の訳で意味を確かめた（文は写していない） | 上のどれか | あわせて「意味は〔訳者〕訳『〔書名〕』（〔出版社〕、〔年〕）で確かめた」 |
| AI が記憶から作った訳（どの本文とも照らしていない） | **使わない**（照合待ち。`SKILL.md` の手順2） | — |

- 「僕の訳」は、照らした本文があり、オーナーが訳を読んで確かめたものに使う（確かめた日は `paid/04-review.md`）。AI の訳を「僕の訳」としてよいかは、オーナーに確かめている（`SKILL.md`「オーナーに確かめること」の 12）。決まるまでは、参考文献に訳の出どころ（上の表の右の列）を必ず書く
- 無料部分の「書かないこと」にも、訳の出どころを一文で書く（例の形：「引用は、〔訳者〕の英訳（〔年〕）から僕が訳した。」）。照らしていないなら、その文は書けない（＝まだ公開できない）
- **弟子の筆記で言葉が残った人**（エピクテトス・ソクラテスなど）について「〇〇が書いた」と書かない。「〇〇は語った」「弟子の〔名前〕が書き留めた『〔書名〕』に、こうある」と書く（本が「書いてある」はよい）

形：

```markdown
> 〔引用文（短く）〕
> ——〔著者〕『〔書名〕』〔章・節・日付〕（〔訳者〕訳、〔出版社〕、〔年〕）[n]
```

照らした本文から自分で訳したとき：

```markdown
> 〔訳した文〕
> ——〔著者〕『〔書名〕』〔章・節〕（要約・僕の訳）[n]
```

（参考文献の [n] に、上の表の右の列を書く。`note/cannot-decide/article.md` の「要約・僕の訳」の書き方と同じ形）

| 決まり | 中身 | 理由 |
|---|---|---|
| 区別 | 引用は `>` のブロックか「」で、本文と分かれて見える | 引用の条件（はっきり区別できること）【一般的な決まり】 |
| 主従 | 僕の文が主、引用は従。引用だけの段落・節をつくらない。引用より、それを読む僕の文が長い | 引用の条件（主従関係）【一般的な決まり】 |
| 必要な範囲 | 1か所は数行まで。長い箇所は要約して「（要約・僕の訳）」 | 必要な範囲を超えた写しは引用にならない【一般的な決まり】 |
| 出典 | 著者・書名・章（節・日付）・訳者・出版社・年。自分の訳なら、照らした本文（上の表） | 出所を明らかにする【一般的な決まり】。【決まり】content-quality 1-3 |
| 訳 | 照らした原典から自分で訳すか、保護期間の切れた古い訳を使うほうが安全。現代の翻訳には、原典が古くても訳者の権利がある。保護期間が切れているかは、訳者の没年と著作権法で確かめる。分からなければ、自分で訳すか、使わない | 翻訳は原典とは別の著作物【一般的な注意・法令は未確認】 |
| 変えない | 他人の訳を言い換えて「僕の訳」としない。現代の訳は、意味を確かめるのに使っても、文を写さない | 出典の正直さ |
| 書名 | いま手に入る邦訳の題も一度は並べる（例：『提要』は、岩波文庫の國方栄二訳では『要録』の題で入っている：`src/articles/stoicism.html` の参考文献 1） | 買う人が本屋や検索で見る名前と合うように |
| 名言 | 出典を確かめられない名言（「ニーチェはこう言った」）は書かない | 【決まり】content-quality 1-3 |
| 画像 | 翻訳書の文を見出し画像に載せない。照らしていない引用も載せない（`thumbnail.md`） | 画像の中の文は、主従を保ちにくい【推測】 |

青空文庫には、保護期間の切れた作品のほか、権利者が公開を認めた作品もある。使うときは、訳者と「底本」の記載を確かめる。法的な判断が要るときは、オーナー（必要なら専門家）が決める。

## 5. 売り手の文体から、まねしないこと

note の哲学の有料記事・会員記事で見えたもの（どれも売れた数は見えていない【実例・未確認】）のうち、ムートンでは使わないもの（→ 6-1・11-2）。書き手の良し悪しの話ではなく、ムートンの決まりに合わないから使わない。

| 見えたもの | 使わない理由 |
|---|---|
| 「挫折なしに」「未来が変わる！」「〇分で読める（〇分で分かる・身につく）」 | 結果の約束。根拠のない効果の保証は不当表示になりうる、という note の説明【公式・未確認】。【決まり】約束しない。**測った分量と読む時間（「有料部分は約1,900字」「読む時間は4分ほど」）は、事実として書いてよい**（BRAND.md「PDF・約15分」と同じ。`structure.md` の 1）。禁じるのは、理解や結果を約束する言い方 |
| 「5つの手順」「7つのステップ」で中身を売る | 【決まり】安易に与えない |
| 「！」「✨」「超シンプル」 | 飾りで、伝える役に立たない【決まり】コピー第一 |
| 「発狂」「邪悪」「炎上」などの強い語 | あおらない【決まり】。X では強い反発（ミュート・通報）が届き方を下げる、という解説もある【個人・未確認】 |
| 経歴・部数・参加人数で信頼をつくる | 先生ではない（`site.js` の bio）。確かめられない数を書かない |
| 「〇年分の学びを凝縮した」のような、有料にした理由の大きな言い方（実例は検索の要約で見ただけ） | 理由は事実だけ（何に時間を使ったか、何がここにしかないか） |
| 「コーヒー1杯」のような値段のたとえ | 値段は数字で言い切る【決まり】BRAND.md「コピーライティング第一」の「変わらないこと」。そもそも値段は本文に書かない（`structure.md` の 6）。`analysis.md` 11-3 は、押しつけ・あおりではないが月額の誘い方の言葉だ、と読んでいる。このスキルは月額を使わない |

まねしてよいもの：冒頭で何が読めるかを一文で言う（3 の 1）、限界を書く（3 の 2）、有料部分の目次を見せる（`structure.md` の 3 の ⑩）。
