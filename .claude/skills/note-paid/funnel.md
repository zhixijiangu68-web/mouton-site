# 導線と価格（正直なやり方だけ）

流れ：**X（止まる一行）→ note の有料記事の無料部分（買うかどうかを決める）→ 有料部分**。サイトの記事（全文・無料・出典つきの決定版）は、無料部分からいつでも行けるところに置く。隠さない。X の告知の材料は、無料部分（有料ラインより上）だけ。

強さの印は `structure.md` の冒頭と同じ。根拠の全体は `analysis.md`。末尾の「→ 7-5」などは `analysis.md` の節の番号。

---

## 1. 先に知っておくこと

- **売れた書き手の売上・購入率・PV と購入の比は、調査で1件も得られなかった**。哲学の単品の有料記事の購入数・スキ数も、1件も見えていない【未調査】。「この型にすれば売れる」と言える材料はない。だから下の決まりは「正直で、仕様が多少違っても壊れない」ことを先にしている。数字は自分の記事で測ってから変える（8）。穴を埋める手順は `analysis.md` 12-8（→ 1-2・3-5）
- 参加人数が大きく見えた哲学のメンバーシップは2件だけで、どちらも本・X など **note の外に読者がいる人**だった（参加人数の表示。時点は分からない）【実例・未確認】。記事の本数（「〇記事が読み放題」）は書き手が出した量で、読者の数ではない。外の読者が少ないうちは、X とサイトの読者に届けることが先（→ 3-4・4-1・4-7）
- note の仕様・手数料・返金の決まりは、どれも help-note.com の本文を開いて確かめていない【公式・未確認】。値段を決める前と公開の前に、オーナーが一度 note の画面とヘルプで確かめる（`paid/04-review.md` の「公開の設定」に項目を並べる）（→ 1-1・12-5）

## 2. 売り方の形

| 形 | このスキルで | 理由 |
|---|---|---|
| 有料記事（単品） | **使う。最初はこれだけ** | 1本から売れる。買った人の手元に残る（→ 2-1） |
| 有料マガジン（買い切り） | 同じテーマの有料記事が3本以上たまったら、`paid/plan.md` で案を出す（決めるのはオーナー） | あとから足した記事も追加料金なしで読める、という説明【公式・未確認】。先に買った人が損をしない。まとめの値段は、中の記事の合計より安くする。「〇円のところ〇円」の元値は書かない（下の 7）（→ 2-1・7-3） |
| メンバーシップ・定期購読マガジン | **使わない** | 【決まり】BRAND.md「信者をつくらない」：会員制・定期購読・休むと失う仕組みをつくらない。メンバーシップは解約すると読めなくなる、定期購読マガジンは利用料20%で月1回以上の更新が要る、という説明【公式・未確認】（→ 2-1・7-4・7-6） |
| チップ | 設定はオーナーが決める。本文で頼まない | 頼むと押しつけになる（押しつけない：【決まり】BRAND.md） |

## 3. 無料部分で、正直に伝えること

`structure.md` の 3 の ⑤〜⑦ と ⑩。

- サイトで無料で読めるもの（記事の題にリンク）と、この記事にしかないもの
- 書いていないもの（答え・手順・約束）と、僕の読み方が唯一ではないこと、訳の出どころ
- 書いている人（先生ではない）
- 有料部分に何があるか（見出しの一覧と、それぞれ何を考える材料かの一文）と、分量・読む時間

理由：買う前に見えるのは無料部分だけ【公式・未確認】。中身を先に見せる【決まり】BRAND.md「信者をつくらない」（「目次と冒頭（無料）で中身を先に見せる」）。サイトに無料であるものを黙って売ると、買った人があとで知って損をする【決まり】CLAUDE.md（サイトは決定版）。売り込みに見せない。でも、隠さない【決まり】BRAND.md「目立ち方」（→ 5-6・11-2）。ただし、有料部分の結論・読み方は無料部分に出さない（出すと、買った人に新しいものが残らない）。

## 4. 価格（AI は案まで。決めるのはオーナー）

`paid/plan.md` に、案を2〜3つ、理由と手取りの計算つきで出し、推す案を一つ選ぶ。

**材料**

| 材料 | 強さ |
|---|---|
| note の哲学の単品で価格が見えた12件は ¥100〜¥980（¥100〜200 が5件、¥500 が4件、¥980 が3件）。¥1,000 以上は0件。12件のうち6件は検索ツールの要約で見た値で、いつの値かも分からない。売れた数はどれも分からない | 【実例・未確認】 |
| note 社の約30万件の分析：分類ごとの売上上位20%で、平均価格は実用ノウハウ系 1,842円、読み物系 983円。哲学の読み物に近いのは読み物系 | 【報道・未確認】（note の原典は見ていない） |
| 有料部分の文字数と売上の相関はほぼゼロ（同じ分析） | 【報道・未確認】 |
| サイトの哲学の3本は各 2,980円（PDF・21ページ）。2026-10-21 からアーカイブで、販売の仕組みは止めたまま | 【決まり】docs/philosophy-sales-20261016.md（3行の価格、47〜51行の表の「ページ」の列）、promo/status.md 20行、docs/site-renewal-20261021.md 11行 |
| 最初の重要な成果は、知人・関係者ではない第三者による実際の購入1件 | 【決まり】docs/product-first-strategy-20261015.md「3」、CLAUDE.md「最新の事業方針」 |

**このスキルの既定**（推す案の決め方。どれも【推測】で、売れた数で見直す）

| 条件 | 推す案 | 理由 |
|---|---|---|
| 第三者の購入が、どの note の有料記事でもまだ0件（`note/*/results.md` で確かめる） | **¥300** | 最初の成果（第三者の実際の購入1件）を確かめやすくする。値段の受け入れられ方は、1件売れてから上げて確かめる |
| 本人の記録が有料部分にない、または有料部分が2,000字未満 | **¥300** | 本ではなくこの記事を買う理由と、払った人が受け取る分量が小さい |
| 上のどちらでもない（第三者の購入が1件以上・本人の記録あり・有料部分 2,000字以上） | **¥500** | 見えた12件でいちばん多かった値（4件）で、哲学の読み物に近い分類の平均（983円）より下 |
| さらに、照らした原典を読む節もあり、どちらもサイトにない | ¥980 も案に入れる | 見えた単品の上の端（3件）で、読み物系の平均とほぼ同じ |

- 案は、推す案を中心に2〜3つ並べる（例：¥300・¥500・¥980）
- `analysis.md` 7-5 には ¥1,500〜¥2,000（実用ノウハウ系の平均の近く。哲学の単品の実例は0件）と ¥2,980（サイトの3本と同じ）の案もある。本文 4,000字までの記事ではサイトの PDF と釣り合わないので、既定には入れない。オーナーが望めば `paid/plan.md` に並べる【推測】
- 長さで値段を付けない。値段は「この記事にしかないもの」で説明できる額にする（→ 5-2）

**手取りの計算**（`paid/plan.md` に書く）

- 手取り（振込手数料の前）＝ 価格 ×（1 − 事務手数料）×（1 − プラットフォーム利用料）。カード払いなら事務手数料5%・利用料10%で、価格の 85.5%【公式・未確認＋計算】
  - ¥300 → 256.5円、¥500 → 427.5円、¥980 → 837.9円（カード払い）
  - 事務手数料は読者の払い方で変わる（携帯キャリア決済は15%で 76.5%）【公式・未確認＋計算】
- 振込手数料は振込1回ごとに 270円（何件分でも1回ごと）【公式・未確認】
- 率は値段を決める前に help-note.com で確かめる。確かめた日を `paid/plan.md` に書く。開けなかったら「未確認（開けなかった）」と書く（→ 2-3・12-5）

**値段の書き方**

- 本文に値段を書かない（note が購入の場所に出す【公式・未確認】。値段を変えたときに本文と食い違う）。ただし BRAND.md は「価格はいつも明示する」「値段は先に、はっきり」なので、ログアウトして値段がどこに見えるかをオーナーが確かめる。無料部分の前に見えないなら、本文の最初に値段の1行を置くかをオーナーが決める（`SKILL.md`「オーナーに確かめること」の 7・9）
- X の告知に値段を書くのは、オーナーが値段を決めたあとだけ。決めた数字と同じにする（`{価格}` と空けておく）
- 値段を何度も変えない。値上げの前に買った人の扱い（差額・読める版）は、ヘルプの答えを確かめていない【未調査】

## 5. 設定（オーナーが note の画面で決める）

`paid/plan.md` に案を書き、`paid/04-review.md` の「公開の設定」に一覧で出す。AI は設定しない。

| 設定 | 調べて分かったこと | このスキルの案 |
|---|---|---|
| 価格 | 上の 4 | 上の 4 の表で決まる案（→ 7-5） |
| 有料エリアの位置 | 段落と段落の間にだけ置ける【公式・未確認】 | `paid/article.md` の `【有料ライン】` の行の位置（→ 2-4） |
| 返金 | 記事ごとに「受け付ける／受け付けない」を選べる。受け付けると題の横に「返金可」、受け付けないと購入ボタンの下に「返金不可」。申請は購入から24時間以内で、note が審査【公式・未確認】 | 両方を並べて、オーナーが決める。受け付ける理由：買う前に有料部分を見せられないので、買う人の危険を小さくする【推測】。受け付けない理由：有料部分は数分で読み終えられるので、読んだあとに返金を申請されうる【推測】（濫用には note が対応する、という説明はある【公式・未確認】）。サイトの PDF は「返品は基本なし（重複購入は返金）」（docs/philosophy-sales-20261016.md）（→ 2-5） |
| AI 学習対価還元プログラム | 有料記事のテキストも、初めの設定では対象。記事ごとに外せる【公式・未確認】 | 案は出さない。事実だけを伝える（→ 2-7） |
| ゲスト購入 | 作者が許可すると、会員登録なしで買える【公式・未確認】 | 許可する：X から来た人が買いやすい。決めるのはオーナー（→ 2-4・7-1） |
| SNS プロモーション（指定の投稿をリポストした人に割引） | 2023-05 に始まった機能【公式・未確認】 | 使わない：リポストと値引きを引き換えにすることと、ステルスマーケティングの決まりとの関係を調べていない【未調査】。BRAND.md「広告であることを隠さない」（→ 2-6） |
| タイムセール・数量限定販売 | 公式の機能。タイムセールは前回から2週間あける決まり（景品表示法への配慮）【公式・未確認】 | 使わない（7）（→ 2-6） |
| 特定商取引法の表示 | 販売業者に当たるときは表示が要る。「請求があれば遅滞なく開示する」と書けば一部を省ける、開示の請求は note 宛てに来る、という note の説明【公式・未確認】。くり返し売るなら販売業者に当たる前提で準備する、というのが一般的な理解【一般的な理解・未確認】 | **公開の前提**（`SKILL.md`「変えない決まり」14）：最初の有料記事を公開する前に、オーナーが note の設定を済ませる（「請求があれば遅滞なく開示する」旨を含む）。当たらないと判断するなら、その理由をオーナーが `paid/04-review.md` に書く。省けるのは表示の一部で、請求があれば開示する義務は売り手に残る。中身はオーナーの情報なので、AI は書き込まない。サイトの Stripe の表記とは別もの（→ 2-9） |

公開の前に、オーナーがログアウトした状態かシークレットモードで記事を開き、買う人に見える範囲を確かめる（ログインしたままだと全文が見える）【公式・未確認】。あわせて、値段がどこに見えるか（無料部分の前か、有料ラインの位置だけか）と、Markdown から貼った見出し・引用・太字・リンクが崩れていないかを見る。仕様が違っていても害のない手順なので、毎回入れる。

## 6. つなぐ場所

| どこから → どこへ | 書き方 | 理由 |
|---|---|---|
| X → note の有料記事 | `05-sns.md`。本文は止まる一行と、無料部分の中身だけ（有料部分の引用・読み方・結論は書かない）。リンクの行で「note の有料記事（冒頭は無料で読める）」と書く。note の URL には utm を付けない | 売り込みに見せない。でも、隠さない【決まり】BRAND.md。告知が有料部分を出すと、告知から来た人に新しいものが残らない。note.com は GA4 の外（`note/good-habits/05-sns.md` と同じ扱い）（→ 7-1） |
| note の無料部分 → サイト | 記事の題にリンク：`[〔題〕](https://moutonarchive.com/<記事>.html?utm_source=note&utm_medium=referral&utm_campaign=<slug>)` | 【決まり】CLAUDE.md「note」。URL だけの行を並べない（`structure.md` の 6） |
| サイト → この有料記事 | **決まるまで案内しない**（`SKILL.md`「オーナーに確かめること」の 11） | いちばん読者がいるのはサイトだが、サイトは決定版・全文無料。そこから有料の note へ案内してよいかは、オーナーが決める |
| note の無料記事（note スキル）→ この有料記事 | 悩みの続きとして1か所だけ | 【決まり】content-quality 1-9。ただし今の note スキルは「販売が始まるまで値段・購入の案内は書かない」なので、オーナーに確かめてから（→ 7-6・12-1） |
| 有料部分の終わり → ほかの有料記事・マガジン | 誘わない。サイトの無料の記事への案内はよい | 【決まり】BRAND.md「取り入れないこと」（購入直後のアップセル）（→ 7-6） |
| 連載 | 題に番号を付け、無料部分で前の回にリンクする | 連番・前後編の題は実例で8件【実例・未確認】。続けて読む理由を、番号と目次で見せる（→ 3-4・7-2） |

- X は最初の読者を連れてくる役。1年以上たった記事への流入は検索64%・SNS 3%、という note 社の調査がある【報道・未確認。読まれ方の数字で、購入の数字ではない】。題と本文には、何年たっても検索される言葉（哲学者名・書名・悩みの言葉）を入れる（`titles.md`）（→ 2-8・7-7）

## 7. 売り手から、まねしないこと

note の哲学の有料記事・会員記事、note のヘルプで見えたもののうち、ムートンでは使わないもの。どれも「よく見えた」だけで、売れた証拠ではない。書き手の表示が偽り・違法だという意味ではなく、ムートンの決まりに合わないから使わない（→ 11-2・7-4）。

| 見えたもの | 使わない理由 |
|---|---|
| 結果の約束（「挫折なしに」「未来が変わる！」「〇分で読める」） | 【決まり】約束しない。根拠のない効果の保証は不当表示になりうる【公式・未確認】。測った分量・読む時間を事実として書くのはよい（`style.md` の 5） |
| 手順・ステップを有料部分の中身にする（「5つの手順」「7つのステップ」） | 【決まり】BRAND.md「安易に与えない」 |
| 人数の限定（「あと10人募集中」「5名限定」） | 嘘の緊急性を使わない【決まり】。偽りの限定は不当表示、という note の一般的な説明もある【公式・未確認】（実例の上限が本当かは分からない）。本当の上限でも、ムートンは限定で急がせない |
| 元値と並べる値引き（「〇本で〇円のところ、まとめて〇円」の形）、タイムセール、値上げ予告、「今だけ」 | 時間であおらない【決まり】product-first 2.7。値段は数字だけで言い切る。元値が本当でも、並べると割引に目を向けさせる言い方になる【推測】。水増しの元値は不当表示【公式・未確認】 |
| 初月無料・値段の据え置きの約束で会員に誘う | メンバーシップを使わない（2） |
| 「有料記事がすべて読み放題」で単品の読者を会員へ | 同上。休むと失う仕組みをつくらない【決まり】 |
| 経歴・部数・参加人数を信頼の材料にする | 確かめられない本人申告。ムートンは先生ではない【決まり】site.js の bio |
| 「買われています」を売れている証拠に見せる | 「過去24時間に売れた」という意味だという個人の説明【個人・未確認】。売れ筋の証拠にしない |
| 「No.1」「最高」「業界最高水準」「独自」 | 根拠のない最上級は不当表示になりうる【公式・未確認】 |
| 気持ちを上げてから落とす（落差）、恐れ・不足感で動かす | 【決まり】product-first 2.7、BRAND.md |
| AI で作った「読者の声」 | 実際に聞いた声だけ【決まり】product-first 2.7 |
| リポストと引き換えの割引（SNS プロモーション） | 5 |

**まねしてよいこと**（どれも効果は確かめられていない。ムートンの決まりに合うので使う）：有料部分の目次を無料で見せる（2件）、限界を書く（1人・2本）、冒頭で何が読めるかを一文で言う（1件）、概念・背景・例は無料に置く（3〜5件）、無料版 → 有料版・前編無料 → 後編有料の形（各1件）、連載の番号（8件）、過去の有料記事をまとめて売る（2件＋参考1件）【実例・未確認】。「単品からはじめて、たまったらまとめる」という順番は、実例から読んだ推測【推測】（→ 11-3・3-4・7-7）。

## 8. 測って直す

- 最初の成果は、知人・関係者ではない人の**実際の購入1件**。PV・スキ・クリック・フォロワーと混ぜない【決まり】docs/product-first-strategy-20261015.md「3」（→ 7-7・12-3）
- 公開後、オーナーから数字をもらったら `note/<slug>/results.md` に書く：公開日・URL・価格・PV・スキ・購入数・売上・返金・どこから来たか（note の画面で見えれば）・X の表示回数とリンクのクリック。note の画面で何が見えるかは確かめていない【未調査】
- results.md は1行1回の記録にする（数字は、オーナーが note・X の画面で見たものだけ。見えないものは「不明」）。コミットしてよいファイルなので、有料部分の中身は書かない：

```markdown
公開日：〔YYYY-MM-DD〕／URL：〔https://note.com/…〕

| 日付 | 何日目 | 価格 | PV | スキ | 購入 | 第三者の購入 | 売上 | 返金 | どこから来たか | X の表示・クリック | 変えたこと |
```
