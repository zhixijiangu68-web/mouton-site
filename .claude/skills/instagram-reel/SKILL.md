# Instagram リール制作（AI社員チーム）

依頼を受けたら、まず `rules.md`（運用ルール）と `team.md`（28担当の定義）を読む。各担当として順番に仕事をし、前の担当の出力ファイルを次の担当が読んで引き継ぐ。

## 依頼ごとの入口

| 依頼 | 動く担当 | 止まる所（人の承認） |
|---|---|---|
| 「リールを1本作って」（テーマ指定なし） | #6 企画立案 → #7 テーマ選定 → 以降すべて | テーマ決定、台本、完成動画 |
| 「この記事でリールを作って」（記事指定あり） | #8 構成設計から | 台本、完成動画 |
| 「今週のリサーチ」 | #1〜#5 | なし（報告のみ） |
| 「企画を出して」 | #6、#7 | テーマ決定 |
| 「数字を分析して」＋インサイトの画像/CSV | #24、#26、#5、#27 | ルール変更 |
| 「ルールを変えたい」 | `rules.md` を更新（最終更新日も直す） | 変更内容の確認 |

## リール1本の流れ

作業フォルダは `instagram/reels/<YYYYMMDD>-<slug>/`（リポジトリ直下。サイトの生成対象外）。

1. **企画**（#6 企画立案 → #7 テーマ選定）：`ideas.md` に企画3〜5本と推薦順。**ユーザーにテーマを選んでもらう**
2. **構成**（#8）：`brief.md`（templates/brief.md の形式）
3. **台本**（#9 フック → #10 台本 → #11 表紙 → #12 CTA）：`script.md`（templates/script.md の形式）
4. **レビュー**（#13 台本レビュー → #14 事実確認 → #15 表現チェック）：`review.md`。**ユーザーに台本を確認してもらう**
5. **素材**（#16 素材収集 → #17 画像生成 / #18 図解）：`assets.md` と `assets/`
6. **編集**（#19 字幕 → #20 動画編集 → #21 音声調整）：`reel.json` → `render/` で `reel.mp4`・`cover.png`、`audio.md`
7. **品質確認**（#22）：`qa.md`。**ユーザーに完成動画を確認してもらう**（動画ファイルを送る）
8. **投稿準備**（#23 キャプション → #25 投稿管理）：`caption.md`、`post.md`。投稿はユーザーがアプリで行い、URL を `instagram/log.md` に記録する
9. **分析**（数日後、ユーザーがインサイトを渡したら #24、#26、#5、#27）

進行管理（#28）として、各段階の完了条件を満たしてから次へ進み、`instagram/status.md` に「いまどこか・何の承認待ちか」を書く。

## 動画の書き出し

```sh
cd .claude/skills/instagram-reel/render
npm install                         # 初回だけ（フォントと Playwright）
node render.mjs ../../../../instagram/reels/<フォルダ>/reel.json
```

- ffmpeg と Chromium が必要。クラウド環境では `CHROME_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome` を付ける
- `reel.json` の書き方は `render/README.md`、見本は `examples/fear/reel.json`
- 書き出した動画は無音。BGM と（使う回は）AI 音声は、`audio.md` を見てユーザーがアプリで入れる

## 守ること

- 記事に書いていないことは言わない。数字は元記事の出典で確かめたものだけ
- `rules.md` の NG（1〜8）に触れたら、その時点で止めて直す
- 他人の絵・写真・参考リールの素材は使わない
- 投稿・コメント返信・DM は人が行う。AI社員は準備と記録まで
- 分からないこと、決められないことは、作る前にユーザーに聞く
