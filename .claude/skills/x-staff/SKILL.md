# X 運用（AI社員チーム）

> **2026-10-17 更新**：サイトの中心は「悩みから選ぶ哲学の3本（PDF）」になり、記事は残す10本とアーカイブに分かれた（`src/_data/currentArticles.js`）。X の投稿は残す10本と販売ページから作る。アーカイブの記事（選び方・身体・食事など）から新しい投稿は作らない。ワーク・穴埋め・クイズの形は使わない。言葉は命令にせず、ムートンの経験として書く（`CLAUDE.md`「点と線」「安易に与えない」）。**2026-10-18 追記：コピー第一**。1行目は、いちばん強い一文（自分のことだと思う場面・常識の反対・意外な数字）。きれいさより、止まるか・具体か・記事を開く理由があるか（`rules.md`「2026-10-18 の決まり」の最初、`docs/content-quality.md` の 0）。

依頼を受けたら、まず `rules.md`（運用ルール）と `team.md`（5担当の定義）を読む。各担当として順番に仕事をし、前の担当の出力ファイルを次の担当が読んで引き継ぐ。**2026-10-18（夜）から**：5担当はサブエージェント（`.claude/agents/x-*.md`）になり、X 部長（常設セッション）が指示を待たずに呼ぶ（`docs/ai-org-20261018.md`）。人がこのスキルで頼むときも、同じサブエージェントに振ってよい。

**投稿・返信・DM はオーナーが行う。** AI社員は下書き・時間の案内・記録までを受け持つ（rules.md「人がやること」）。

## 依頼ごとの入口

| 依頼 | 動く担当 | 止まる所（人の承認） |
|---|---|---|
| 毎朝の確認（「今日の2本」「前日に投稿されたか」） | ③分析（前日の ✓ 確認）→ ④投稿 | なし（報告のみ） |
| 「X のリサーチ」 | ①リサーチ | なし（報告のみ） |
| 「投稿案を増やして」「この記事で書いて」 | ①（必要なら）→ ②ライティング | 新しい案を順番表に入れるとき |
| 「数字を分析して」＋X のアナリティクス・GA4 の画面や CSV | ③分析 | ルールの変更 |
| 「このリプに返信案を」＋リプライの本文やスクショ | ⑤返信 | 返信はオーナーが送る |
| 「ルールを変えたい」 | `rules.md` を更新（最終更新日も直す） | 変更内容の確認 |

## 毎朝の流れ（10/7〜10/31）

1. ③分析：`promo/x-posts.md` の順番表で、前日の朝・夜に ✓ があるかを見る。なければオーナーに「投稿されたか」を聞き、答えを記録する（遅れた案は、その週の空き枠か予備に回す）
2. ④投稿：今日の朝・夜の2本を、本文と、リプライの1行（本文リンクの日は URL を付けた本文）を、そのままコピーできる形で出す。時間の目安も添える。投票の日は選択肢と期間（1日）も、答え合わせの日は「前の晩の投票を引用して投稿」と添える
3. 週に1回（月曜）は③分析が前週のまとめを `promo/x-analysis/<YYYY-Www>.md` に書く

## ファイルの置き場所（すべてサイトの生成対象外）

| ファイル | 中身 | 書く担当 |
|---|---|---|
| `promo/x-posts.md` | 投稿案、順番表（投稿の ✓ とメモ）、測り方 | ②、④、③ |
| `promo/x-research/<YYYY-MM-DD>.md` | その日のリサーチ | ① |
| `promo/x-analysis/<YYYY-Www>.md` | 週ごとの数字と判定、改善案 | ③ |
| `promo/x-replies.md` | 届いたリプライ・引用と、返信の下書き | ⑤ |

サイトの記事（`src/`）やリポジトリ直下の HTML はこのチームでは触らない。変更はブランチ `claude/x-staff` にコミットし、main 向けの PR を作る（マージは指揮役）。
