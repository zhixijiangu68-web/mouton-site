# X 運用（AI社員チーム）

依頼を受けたら、まず `rules.md`（運用ルール）と `team.md`（5担当の定義）を読む。各担当として順番に仕事をし、前の担当の出力ファイルを次の担当が読んで引き継ぐ。

**投稿・返信・DM はオーナーが行う。** AI社員は下書き・時間の案内・記録までを受け持つ（rules.md「人がやること」）。

## 依頼ごとの入口

| 依頼 | 動く担当 | 止まる所（人の承認） |
|---|---|---|
| 毎朝の確認（「今日の2本」「前日に投稿されたか」） | ③分析（前日の ✓ 確認）→ ④投稿 | なし（報告のみ） |
| 「X のリサーチ」 | ①リサーチ | なし（報告のみ） |
| 「投稿案を増やして」「この記事で書いて」 | ①（必要なら）→ ②ライティング | 新しい案を順番表に入れるとき |
| 「数字を分析して」＋X のアナリティクス・GA4 の画面や CSV | ③分析 | ルールの変更 |
| 「このリプに返信案を」＋リプライの本文やスクショ | ⑤返信 | 返信はオーナーが送る |
| 「ルールを変えたい」 | `rules.md` を更新（最終更新日も直す） | 変更内容の確認 |

## 毎朝の流れ（10/7〜10/31）

1. ③分析：`promo/x-posts.md` の順番表で、前日の朝・夜に ✓ があるかを見る。なければオーナーに「投稿されたか」を聞き、答えを記録する（遅れた案は、その週の空き枠か予備に回す）
2. ④投稿：今日の朝・夜の2本を、本文と、リプライの1行（本文リンクの日は URL を付けた本文）を、そのままコピーできる形で出す。時間の目安も添える
3. 週に1回（月曜）は③分析が前週のまとめを `promo/x-analysis/<YYYY-Www>.md` に書く

## ファイルの置き場所（すべてサイトの生成対象外）

| ファイル | 中身 | 書く担当 |
|---|---|---|
| `promo/x-posts.md` | 投稿案、順番表（投稿の ✓ とメモ）、測り方 | ②、④、③ |
| `promo/x-research/<YYYY-MM-DD>.md` | その日のリサーチ | ① |
| `promo/x-analysis/<YYYY-Www>.md` | 週ごとの数字と判定、改善案 | ③ |
| `promo/x-replies.md` | 届いたリプライ・引用と、返信の下書き | ⑤ |

サイトの記事（`src/`）やリポジトリ直下の HTML はこのチームでは触らない。変更はブランチ `claude/x-staff` にコミットし、main 向けの PR を作る（マージは指揮役）。
