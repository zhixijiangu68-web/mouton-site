# X とサイトの運用（AI社員チーム）

依頼を受けたら、まず `rules.md`（運用ルール）と `team.md`（担当の定義）を読み、`promo/status.md` で「いまどこか」を確かめる。

期間は **2026-10-06〜11-05**（10月の勝負＋11月の計画づくり）。どの仕事も「X → 選び方の記事 → Amazon・楽天 の流れを太くするか」で優先度を決める。Instagram は休止中（`instagram/README.md`）。

## 依頼ごとの入口

| 依頼 | 動く担当 | 止まる所（人の承認） |
|---|---|---|
| 「今日の仕事」「いまどうなってる？」 | S1 編集長 | 承認待ちの一覧を見せる |
| 「今日の2本」「Xの投稿を作って」「Xの数字を分析して」「返信案」 | **x-staff**（`.claude/skills/x-staff/`）→ S3 チェック | 投稿・返信はオーナー |
| ツイートを貼られた／「アレンジして」 | x-staff #2 ライティング（`promo/tweet-stock.md` に集める） | なし |
| 「選び方の記事を書いて」「この商品を紹介したい」 | S2 記事担当 → S3 チェック → S4 サイト担当 | テーマ、公開前の本文 |
| 「記事を直して」「導線を良くして」 | S2 記事担当 or S4 サイト担当 → S3 チェック | 公開前の差分 |
| 「週の振り返り」「10月の振り返り」 | x-staff #3 分析 → S1 編集長 | 翌週・11月の計画 |
| 「ルールを変えたい」 | `rules.md` を更新（最終更新日も直す） | 変更内容の確認 |

## 毎日の流れ（オーナーが「今日の仕事」と言ったとき）

1. **S1 編集長**：`promo/status.md` を開き、承認待ち・止まっている所を伝える
2. **x-staff**：その日の2本（#4 投稿）と、前日分が投稿されたかの確認（#3 分析）
3. その週の計画（status.md の「今週」）にある記事・サイトの仕事を1つ進める
4. 終わったら status.md を更新してコミットする

毎日・毎週の予定（何時に・どこで・何をするか）は `promo/calendar.html` で見られる。`promo/x-posts.md` から `npm run calendar` で作る生成物なので、直接は編集しない

## 守ること

- サイトのページは `src/` を直して `npm run build` → `npm test`。生成物も一緒にコミットする（CLAUDE.md）
- 公開前に必ず S3 チェックを通す。健康の言い切り・出典のない数字・PR 表示の抜けは、その場で止めて直す
- X への投稿・返信・DM、ASP の登録や ID の取得は人が行う。AI社員は下書き・設定の反映・記録まで
- 分からないこと、決められないことは、作る前にオーナーに聞く
