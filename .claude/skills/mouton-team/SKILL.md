# X とサイトの運用（AI社員チーム）

依頼を受けたら、まず `rules.md`（運用ルール）と `team.md`（6担当の定義）を読み、`promo/status.md` で「いまどこか」を確かめる。

期間は **2026-10-06〜11-05**（10月の勝負＋11月の計画づくり）。どの仕事も「X → 選び方の記事 → Amazon・楽天 の流れを太くするか」で優先度を決める。Instagram は休止中（`instagram/README.md`）。

## 依頼ごとの入口

| 依頼 | 動く担当 | 止まる所（人の承認） |
|---|---|---|
| 「今日の仕事」「いまどうなってる？」 | #1 編集長 | 承認待ちの一覧を見せる |
| 「Xの投稿を作って」「順番表を直して」 | #2 X担当 → #4 チェック | 投稿はオーナー |
| ツイートを貼られた／「アレンジして」 | #2 X担当（`promo/tweet-stock.md`） | なし |
| 「選び方の記事を書いて」「この商品を紹介したい」 | #3 記事担当 → #4 チェック → #5 サイト担当 | テーマ、公開前の本文 |
| 「記事を直して」「導線を良くして」 | #3 記事担当 or #5 サイト担当 → #4 チェック | 公開前の差分 |
| 「数字を見て」＋スクショ・CSV | #6 計測担当 → #1 編集長 | 打ち手の変更 |
| 「週の振り返り」「10月の振り返り」 | #6 計測担当 → #1 編集長 | 翌週・11月の計画 |
| 「ルールを変えたい」 | `rules.md` を更新（最終更新日も直す） | 変更内容の確認 |

## 毎日の流れ（オーナーが「今日の仕事」と言ったとき）

1. **#1 編集長**：`promo/status.md` を開き、今日の X の2枠（`promo/x-posts.md` の順番表）と、承認待ち・止まっている所を伝える
2. **#2 X担当**：前日分の「投稿」✓ とメモを確認。抜けていたら次の空き枠に回す案を出す
3. その週の計画（status.md の「今週」）にある記事・サイトの仕事を1つ進める
4. 終わったら status.md を更新してコミットする

## 守ること

- サイトのページは `src/` を直して `npm run build` → `npm test`。生成物も一緒にコミットする（CLAUDE.md）
- 公開前に必ず #4 チェックを通す。健康の言い切り・出典のない数字・PR 表示の抜けは、その場で止めて直す
- X への投稿・返信・DM、ASP の登録や ID の取得は人が行う。AI社員は下書き・設定の反映・記録まで
- 分からないこと、決められないことは、作る前にオーナーに聞く
