IDS 4/4：選ぶとき・運用するときに見るところと、学び方

約7分更新日 2026年11月4日

IDS の製品を比べ始めると、カタログの数字と機能の一覧に目が行く。調べ終えてみると、先に決めておくことのほうが多かった。どこを見るのか、止めたいのか、警告を誰が読むのか。

この4本目では、選ぶときと、置いたあとに見るところを書く。最後に、自分の手元で学ぶ入口を置いた。

IDS について、4本に分けて書いている。1 IDS とは何か、なぜ大事か／2 無料の道具／3 商用とクラウドの製品／4 選ぶとき・運用するとき。

よく言われることの判定

確かさは、資料の確かさの目安。ここに置いた2つは、メーカーの数字や、別の分野の手引書がもとなので、「低」にしている。

よく言われること判定確かさ主な根拠
カタログの最大の処理能力は、機能を全部使っても出る× 否定低Corelight の発表では、ある機器は通信の分析だけなら最大10Gbpsで、Zeek・Suricata・パケットの保存を全部使うと最大5Gbpsだった（メーカーの数字） [1]
IDS は、置いたらすぐに止める設定で本番に入れてよい× 否定低IPA の制御システム向けの手引書は、導入を「導入検討 → 構築 → 試験運用 → 本格運用」に分けている。制御システム向けの文書で、ほかの環境にそのまま当てはまるかは確かめていない [2]

選ぶときに見るのは、置き場所・止めるか・暗号化・処理能力・ルール・連携・人手だった

調べたことから、選ぶときの問いを7つに絞った。製品のカタログを開く前に、紙に書いて答えておくと迷いにくい。

  1. どこを見たいか：境目を通る通信か、内側どうしの通信か、機械の中か
  2. 止めたいのか、知らせてほしいのか：止めるなら通り道に入る置き方になる。誤って止めたときの影響も背負う
  3. 暗号化された通信をどうするか：復号するか、特徴だけで見るか、端末の記録で埋めるか[3]
  4. どれだけの量を流すか：カタログの処理能力は、機能を全部有効にすると下がることがある
  5. ルールや脅威の情報は、どこから、どれくらいの遅れで届くか：無料のルールには遅れがあるものもある[4]
  6. 警告をどこに集めるか：EVE JSON のような形で、SIEM（ログを集めて分析する仕組み）に流せるか
  7. 誰が、いつ、警告を読むか：これに答えられないなら、製品を選ぶ前に決めることがある

誰が読むかは、名前と時間まで決める

7つ目の問いは、いちばん後回しにされやすいと僕は思う。「担当の部署」ではなく、誰が、どの時間に、1日に何件まで読めるかまで決めておく。読める件数より多く知らせる設定なら、知らせは読まれずに積もる。読んだあと、誰に知らせ、何を止めるかも、置く前に決めておきたい。

通信の取り出し方は、タップか、ミラーポートか

1つ目の問いには、通信をどこから取り出すかも入る。Security Onion の文書は、2つの取り出し口を挙げている。スイッチのミラーポート（通信のコピーを出す口）と、専用のタップ（回線から通信のコピーを取り出す機器）だ。できればタップを勧めている[5]。

NAT（社内のアドレスを外向けの一つのアドレスに置き換える仕組み）がある環境では、内側で取るとしている。本当の社内のアドレスが見えるようにするためだ[5]。

処理能力は、使う機能を全部入れた数字で見る

4つ目の問いの例として、Corelight の発表を見る。AP 620 という機器は、通信の分析だけなら最大10Gbpsだ。Zeek・Suricata・パケットの保存を全部使うと、最大5Gbpsになる[1]。カタログの一番大きな数字ではなく、自分が使う機能を全部入れたときの数字を見る。

費用は、代金と人の時間の両方で見る

無料の道具は、ソフトの代金はかからない。その代わり、機器を用意し、更新を当て、ルールを調整し、警告を読む人の時間がかかる。商用の製品は、機器やサブスクリプションの代金がかかる。その代わり、ルールや脅威の情報の更新は、メーカーが用意する。どちらが安いかは、環境と、使える人手で変わる。

試してから決める

管理者として許可を得た範囲で、自分の環境の通信を保存しておく。それを候補の道具に読ませると、どれだけ知らせてくるかが分かる。そのうちどれだけが、本当に気にすべきものかも分かる。Security Onion の Import という構成は、保存した通信を読み込むためのもので、この試し方に使える[6]。

運用で見るのは、取りこぼし・誤検知の調整・警告を読む人だった

置いたあとにも、見るところが3つある。

一つ目は取りこぼしだ。Security Onion は、Zeek が報告する取りこぼしの割合を画面に出す。値が高いほど、見えていない通信が多い。Zeek に取りこぼしがあるのにパケットの欠落がないときは、手前のタップやミラーポートで落ちている可能性が高いとしている[7]。

二つ目は、いきなり止めない段取りだ。IPA の制御システム向けの手引書は、導入を4段階に分けている。「導入検討 → 構築 → 試験運用 → 本格運用」だ[2]。制御システム向けの文書だが、試験運用で誤検知（攻撃ではないものを攻撃として知らせること）を見てから本番に移る考え方は、ほかの環境でも使えると僕は思う。

三つ目は、警告を読む人だ。NIST の CSF 2.0 は、見張ること（DE.CM）と、見つけたものを分析して判断すること（DE.AE）を、別の項目として並べている[8]。警告が多すぎて読まれなければ、IDS はないのに近くなると僕は思う。ルールの調整は、置いたあとにずっと続く仕事だ。

学ぶなら、自分の PC の仮想環境と公開された PCAP から始められる

手を動かして学ぶ入口もある。試すのは、自分の機械と、許可された演習の環境の中だけにしてほしい。人のネットワークを許可なく監視したり、調べたりすることはしない。

僕が調べた中でいちばん軽そうだったのは、自分の PC の仮想環境に Security Onion を入れる始め方だ。Import は、保存した通信（PCAP）を読み込むだけの構成だ。2コア・メモリ4GB・ディスク100GB・NIC（ネットワークにつなぐ部品）1枚が最低限とされている[6]。Suricata や Zeek が通信を実際に見るところまで試す Eval という構成は、4コア・メモリ8GB・ディスク200GB・NIC 2枚とされている[6]。

読み込む通信は、公開された練習用の PCAP が使える。Brad Duncan が運営する malware-traffic-analysis.net には、分析の練習問題と PCAP がある。ただし本人が書いているとおり、PCAP の中に本物のマルウェアが入っていることがある。取り出して動かすと感染しうる。本人は、Linux や macOS などで見ることを勧めている[9]。僕は、ネットにつながない仮想環境で、ファイルを取り出さずに読むことにしている。

決まった道筋で学ぶなら、TryHackMe の Snort の部屋がある。IDS/IPS の概要からルールの書き方までを扱う[10]。Hack The Box Academy の Working with IDS/IPS は、Suricata・Snort・Zeek を扱う[11]。

学ぶうちに、製品や公開されているサービスの弱点に気づくことがあるかもしれない。そのときは公開せず、作った会社か、IPA の届け出の窓口に知らせる。

IDS は、どこを見るかと、誰が読むかを決めて初めて働く

まとめると、選ぶ前に7つの問いに答えておく。どこを見るか、止めるか、暗号化をどうするか、量、ルール、集め先、そして読む人だ。置いたあとは、取りこぼしを見て、試験運用で誤検知を減らし、警告を読む人と時間を回し続ける。

4本を通して、IDS は置けば守ってくれる箱ではなかった。選ぶのは、自分の環境を知っている人だ。
