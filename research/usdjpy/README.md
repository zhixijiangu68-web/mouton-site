# USD/JPY Fib検証 — 第1段階

Issue #1: https://github.com/zhixijiangu68-web/mouton-site/issues/1

1分足CSV → JST正規化 → 完成足生成 → 確定スイング → Fib初回到達イベント。
到達は反発・注文・約定ではありません。実相場の収益性評価はまだしていません。
既存のEleventy入力 `src/` と独立したPython CLIです。

## 実行

Python 3.10以上。追加のPythonパッケージは不要です。IANA時刻データのない環境
（Windows等）で `source_timezone` を使う場合は `python -m pip install tzdata`。
リポジトリ直下で実行します（Windowsでは `python` を `py` に置き換え可）。

```sh
python -m unittest discover -s research/usdjpy/tests -v
python -m research.usdjpy.run --input research/usdjpy/tests/fixtures/minute_sample.csv
```

出力先は `research/usdjpy/output/`。`--output` で変更可能。同名出力は上書きします。

- `bars.csv`: 対象区間の完成足。start/endはJST、endで初めて利用可能。
- `swings.csv`: ピボットの発生時刻と確定時刻（同種連続を含む検出監査記録）。
- `fib_events.csv`: 波ID、売買方向、確定時刻、Fib比率・価格、到達足・判明時刻、時間帯。
- `report.json`: 入力SHA256、実行設定、品質、件数、年×時間帯の値幅統計。

添付データは架空の300本の1分足（20本の15分足）。買い波104→120に対し
38.2%=113.888、50%=112の2到達を期待します。61.8%は未到達。
実データ、取引履歴、成績ではありません。

## 実データ入力

```csv
timestamp,open,high,low,close
2025-01-06T00:00:00Z,157.200,157.230,157.190,157.220
```

- USDJPYのみ。価格は円。timestampは**完成した1分足の開始時刻**。
- タイムゾーン付きISO8601推奨。タイムゾーンなしは設定 `source_timezone`
  （例 `Asia/Tokyo`）必須。DST曖昧時刻・存在しない時刻は拒否し、オフセットを要求。
- 価格種別bid/ask/midと取得元をconfigに明記。異なる業者・種別を混ぜない。
- 並べ替え、完全一致重複を除去。競合重複、不正OHLC、NaN、非正価格、秒ずれは停止。
- 欠損補間なし。必要本数が欠けた集計足は不採用。未観測の全区間はgapに残る。
- weekend_candidateは週末を含む長い欠損の便宜的な分類。休場の確定判定ではない。
- メモリ内処理。まず小さなファイルで確認。多数年の大規模処理の性能は未測定。
- 生データは `research/usdjpy/data/`、生成物は `output/` に置く。gitignore対象。
  公開リポジトリへの生データ追加・再配布は行わない。

## 設定

追加依存を避けるため、計画のYAMLから標準ライブラリで読める `config.json` に変更。
`--config` で任意のJSONを指定可能。

- timeframe_minutes: 5 / 15 / 30 / 60（初期15）。JSTの00分基準、左閉右開。
- pivot_width: 左右の本数（初期2）。設定変更は開発区間でのみ比較する。
- Fib比率: 0.382 / 0.500 / 0.618固定。
- symbol、source、source_timezone、price_type: データの仕様。
- splits: start < development_end < validation_end < end のタイムゾーン付き日時。

## スイングと到達

左右2本の全高値より厳密に高ければ高値ピボット、全安値より厳密に低ければ安値。
同値、同一足で高値/安値の両方に該当、窓内欠損は不採用。
後ろ2本目の終値確定で認識する。同種が続いた場合はより極端な値に以後の状態を更新。
監査記録や既に出力した到達を書き換えない。

直近2高値・2安値がともに上昇なら買い、ともに下降なら売り。
買いは最新L→H、売りは最新H→Lの終点確定時に監視開始。
買い水準=H-(H-L)r、売り水準=L+(H-L)r。
確定待ち中に既に水準まで到達/通過した比率は除外。
確定後の足でlow≤水準≤highとなる最初の足だけ記録。許容幅なし。
同一足で複数水準に触れた場合は各水準を記録するが、足内の順序は主張しない。
波の高安範囲外への逸脱は到達判定より優先して監視終了。
新しい採用ピボットで前の監視を終了し、条件を満たす新しい波だけ開始。
欠損では波・トレンド状態をリセット。ピボット窓も連続足のみ。

全時間帯でスイングを作り、到達を10–11時、16–18時、22–翌1時、outsideに分類。
開始を含み終了を含まない。時間帯はJST固定で、海外DSTによる時刻移動はしない。
現段階は比較用にoutsideも出力。売買段階では対象時間帯のエントリーに限定する。

## データ分割・未使用区間

実データ期間の古い60%を開発、次20%を選定、最新20%を最終未使用にする計画。
**実データを受け取ってから暦期間を基準に境界日を決め、設定を固定する。**
添付configの日時は人工データ実行用であり、実データの60/20/20境界ではない。
追加入力のたびに境界が動く自動割合分割はしない。

通常実行はdevelopmentのみ。validationは `--partition validation`。
holdoutはルール固定後に限り `--partition holdout --unlock-holdout`。
このフラグは誤実行防止でありアクセス制御ではない。最終区間を開いたら実行設定と
結果を保存し、それを見て再調整した場合は新たな未使用期間を用意する。

入力全体の形式検査とハッシュ算出は行うが、要求区間より後の価格を使って足・
スイング・イベント・値幅統計は作らない。選定区間以降は過去の足を準備に使う。
境界をまたぐ足・範囲外のイベントは評価対象外。後続の売買処理では境界を
またぐポジションも除外する。区間ごとの成績を合算して最終評価としない。

outsideとの比較が可能。高ボラ時間帯としての有効性は実データ未検証。
