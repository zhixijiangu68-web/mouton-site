# 最小売買バックテスト v1

対象: Issue #1 / PR #137。2026-10-14に合意した基準仕様の実装。
実注文は出さない。開発区間での計算検証用であり、推奨売買ルールではない。

## 固定ルール

- USDJPY、Bidの1分足、完全15分足、左右2本の確定ピボット。
- 既存のトレンド・初回到達・欠損リセットの定義は変更しない。
- 38.2/50/61.8%の到達記録を維持し、売買は50%だけ。
- 買い: 到達足の終値 > Fib価格、かつ終値 > 始値。
- 売り: 到達足の終値 < Fib価格、かつ終値 < 始値。
- 同値は不成立。到達足だけで判定し、不成立後に反発を待ち直さない。
- `available_at`（到達足の終了）で初めて判断し、その時刻に始まる次の15分足の
  最初の1分足始値で成行約定。次の15分足の完成・高安・欠損有無は参照しない。
- エントリー時刻がJST [10:00,11:00)、[16:00,18:00)、[22:00,翌01:00)のいずれか。
  到達足に付く既存の時間帯ラベルとは別に `entry_session` を保存する。
- 買いSL = 到達足Bid安値 − 1pip。売りSL = 到達足Ask高値 + 1pip。
- SLはエントリー時に固定し、追従・建値移動・裁量変更しない。
- エントリー約定価格EからSLまでの距離をRとし、買いTP=E+2R、売りTP=E−2R。
  単一TP、分割決済なし。ギャップや滑りによって実現損失は1Rを超え得る。
- エントリーから60分後の1分足始値で時間決済。セッション終了による決済はしない。
- 同時1ポジション、同一波最大1約定。保有中の候補は破棄する。
  当該時刻の始値で既存取引が決済されても、その時刻の新規候補は見送る。
- 同時刻の候補はsignal ID順で処理し、後続を待ち行列に入れない。
- 初期資金100万円、数量1,000 USD固定、複利なし。資金管理・証拠金強制決済は未実装。
  長期評価や数量拡張の前に資金管理を別途定義する。

## 約定とコスト

`Decimal`で計算。1pip=0.01円。初期仮定はスプレッド1.0pip、
成行/ストップの滑り片道0.1pip、手数料片道0円。
HISTDATAのBidに固定スプレッドを加えてAskを構成する。実測Askではない。

| 操作 | 約定 |
|---|---|
| 買いエントリー | Bid始値 + spread + slip |
| 売りエントリー | Bid始値 − slip |
| 買い成行決済 | Bid − slip |
| 売り成行決済 | Ask + slip |
| TP指値 | TP価格。有利な価格改善なし、指値の滑り0 |

SL/TPの監視価格は買いBid・売りAsk。SLを越えた始値は、その不利な始値に
滑りを加えて約定。TPを越えた始値でもTP価格で約定。
時間決済の時刻は始値でSL→TP→時間決済の順に判定し、その後の高安を使わない。

同一1分足で両方に触れたらSL優先。`ambiguous_intrabar=true`。
到達順序や約定秒は推測しない。足内約定は `exit_at` を空欄とし、
`exit_bar_start/end` に左閉右開の区間を記録する。
保有時間も下限・上限を出す。始値約定なら下限=上限。
エントリーした最初の1分足からSL/TPを監視する。

純損益 = 方向符号 × (決済約定価格−新規約定価格) × 数量 − 往復手数料。
スプレッドと滑りは価格に含まれるので再控除しない。
同一の売買・決済条件でBid基準価格の損益を記録し、
`gross_bid_pnl_jpy − total_cost_jpy = net_pnl_jpy` を照合できる。
これは別途実行したコストゼロ戦略との比較ではない。
スワップは未モデル化。仮定コストを実測コストと呼ばない。

## 欠損と境界

- 確認足は完全な15分足のみ。新規注文時刻に1分足がなければ取消。
- 将来の欠損を事前に確認してエントリーを取り消さない。
- 保有中（時間決済予定の1分足を含む）に1分でも欠ければ、未解決取引として
  残し、最初の欠損時刻で売買処理を停止する。最後の既知価格で決済しない。
- CLIはその場合も台帳・レポートを保存し終了コード2を返す。
  `metrics=null`、`partial_metrics`には停止前の決済済み損益と観測済み資産曲線の
  部分集計を置く。欠損取引を除いた正式成績として扱わない。
- フラット時の欠損は取引を創作せず通過。資産曲線は観測1分足にだけ出力する。
- 既知の区間末尾までに時間決済用の1分足を観測できない注文は見送る。
  条件は `entry_at + 60分 + 1分 <= development_end`。価格データの事前走査ではない。
- 初版CLIはdevelopmentだけを許可する。区間末尾で強制決済せず、
  validation/holdoutの価格を使わない。生CSVは入力形式検査・全体ハッシュの対象だが、
  集計・売買・指標に渡す価格はdevelopment内だけ。
- 診断用の到達件数は開発区間全体を表す。売買が欠損停止した場合、
  `signals_processed`以降を取引として処理していない点を区別する。

## 出力と指標

| 出力 | 内容 |
|---|---|
| signals.csv | 波・比率・到達・利用可能時刻、反発判定、予定時刻、見送り理由、trade ID |
| trades.csv | 入出値、数量、固定SL/TP/R/期限、決済区間・理由、コスト内訳、純損益・pips・R、未解決状態 |
| equity.csv | 観測1分足終了時の確定損益、仮清算損益、資産額、ピーク、DD |
| backtest_report.json | 設定・コード・入力のハッシュ、区間、品質、件数推移、指標、制約 |

CSV/JSON時刻はJSTのオフセット付きISO8601。Decimalは文字列。
資産曲線では入場時に手数料を支払い、保有中は買いBid／売りAskで仮清算し、
決済滑りと決済手数料も織り込む。決済時に入場手数料を二重計上しない。
最大DDは初期資金を最初のピークとする観測1分終値基準。ティック内最大DDではない。

純損益を使う勝率・PF・平均円/pips/R・最大連敗・最大DD（円/%）、
SL/TP/時間決済別件数、足内曖昧件数、平均保有時間範囲、コスト合計を出す。
損益0は勝率分母に含み、連敗を区切る。0取引の平均・勝率・PFはnull。
損失0のPFもnullとし `pf_undefined_reason` を残す。Infinity/NaNはJSONに書かない。

## 実装境界

`signals.py` → `execution.py` / `backtest.py` → `ledger.py` / `metrics.py`。
設定型は `trade_model.py`、接続CLIは `run_backtest.py`。
既存 `run.py`、`fib_events.py`、到達CSVは変更しない。
出力フォルダは新規作成だけを許可し、既存実行結果を上書きしない。
Python追加パッケージなし。既存Build checkのunittest discoveryで新規テストも実行される。

## 検証ゲートと次段階

1. 手計算の反発・買い/売り約定・2R・スプレッド/滑り・手数料に一致。
2. 次足始値、時間帯境界、二重建玉防止、同一波制約、足内SL優先、ギャップを検証。
3. 保有中欠損で停止し、既に約定した事実を取り消さない。区間境界を越えない。
4. 未来追加で過去の確定結果不変、未使用価格変更で売買出力不変、既存19テスト成功。
5. 同じ2012開発区間で取引台帳と1分足を照合し、件数推移と制約を残す。

全期間の分割設計、他TP/保有時間の開発内比較、固定後の選定・未使用検証を残す。
