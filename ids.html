守る

侵入に自分で気づけた組織は52%だった。IDSは、選ぶ前に「どこを見るか」を決める道具だった。

IDS と IPS の違い、なぜ大事か、無料・商用・クラウドの製品の比べ方、選ぶときと運用するときに見るところ

約21分更新日 2026年11月4日

侵入されたことに、自分で最初に気づけた組織は52%だった。Mandiant が2025年に対応した事案のまとめ（M-Trends 2026）の数字だ。残りは、外から知らされて初めて気づいている。侵入から見つかるまでの日数の中央値は14日で、前の年の11日より延びた[1]。

中から気づくための道具の一つが、IDS（侵入検知システム。通信やログを見て、攻撃らしいものを知らせる仕組み）だ。僕は専門家ではなく、セキュリティを勉強している一人として、IDS を調べ直した。何を見て、何を見られないのか。無料の道具と商用の製品は何が違うのか。選ぶときと、置いたあとに、どこを見ればいいのか。

先に言うと、IDS は置けば守ってくれる箱ではなかった。どこに置き、何を見せ、警告を誰が読むかを決めて、初めて働く道具だった。製品の比較はそのあとに来る。

IDS は見つけて知らせる仕組みで、止めるのは IPS の役目だった

IDS の基本の文書は、米国の NIST（国立標準技術研究所）の SP 800-94 だ。いま有効なのは2007年2月の版で、IDS と IPS（侵入防止システム。通信の通り道に入って、攻撃らしいものを止める仕組み）をまとめて IDPS と呼んでいる[2]。2012年に改訂の案が出たが、最終版にならず、2022年7月に取り下げられた[12]。IPA が日本語訳を出している[13]。

この文書は、IDPS を見る場所で4つに分けている。ネットワークの通信を見るネットワーク型、無線、ネットワークの振る舞いの分析、1台の機械の中を見るホスト型だ。検知の方式は3つに分けている[2]。シグネチャ型（知られた攻撃の型と照らす）、アノマリー型（ふだんからのずれを見る）、ステートフルプロトコル解析（通信の決まりに合っているかを見る）だ。

IPA の制御システム向けの手引書は、方式を5つに分けている。シグネチャ型・ルールベース・ステートフルプロトコル解析・振る舞い検知型・サンドボックス型（怪しいファイルを隔離した環境で動かして確かめる）だ[14]。分け方は文書によって違う。それぞれの方式が何を得意とし、何を見逃しやすいかは、SP 800-94 の本文で確かめてから書き足す。

大事なのは、IDS と IPS の違いが、製品の名前ではなく置き方で決まることだ。通信のコピーを受け取って見るなら、知らせることしかできない。通信の通り道に入るなら、止められる。Google Cloud IDS は、通信のコピーを作って調べる仕組みで、検知と警告だけを行い、止めるには別の製品を使うと説明している[3]。

近い道具との違いを、言い切れる範囲で並べると次のようになる。

IDS と近い道具（この記事での使い分け）
道具見るもの止めるか
ファイアウォール決めた規則（宛先・ポートなど）規則で通す・通さないを決める
IDS（ネットワーク型）通信の中身や手順の怪しさ止めない。知らせる
IPSIDS と同じ通り道にいて止める
IDS（ホスト型）1台の機械のログ・ファイル・設定製品によって、その機械で対処する

SIEMIDS を含む色々なログ止めない。集めて突き合わせる

NDR（ネットワークの検知と対応）や SIEM（ログを集めて分析する仕組み）の定義は、メーカーによって少しずつ違う。この表は、この記事を読むための目安だ。

侵入に自分で気づけた組織は52%で、気づくまでの中央値は14日だった

冒頭の数字をもう少し見る。M-Trends 2026 では、自分で最初に気づけた割合は52%で、前の年の43%から増えた。それでも、半分近くは外からの知らせで気づいている。気づくまでの日数の中央値は14日で、中央値なので、半分はそれより長い[1]。

IBM の Cost of a Data Breach の2026年版では、侵害を特定して封じ込めるまでの平均は247日だったと報じられている[15]。14日と247日は、矛盾ではない。M-Trends は Mandiant が対応した事案の中央値で、IBM は調査した組織のデータ侵害の平均だ。数え方も対象も違うので、「調べ方によって、数週間から8か月」と幅で受け取るのが正確だと思う。

日本の数字も見ておく。IPA の「情報セキュリティ10大脅威 2026」の組織編の1位は、ランサム攻撃による被害だった[16]。警察庁によると、2025年上半期のランサムウェアの被害の報告は116件だった。感染経路が分かったもののうち、VPN（外から社内のネットワークに安全につなぐ仕組み）の機器が62.2%だった。リモートデスクトップと合わせると8割を超える[17]。入口の多くは、VPN の機器やリモートデスクトップのような、外とつながる境目だった。境目を通る通信を見ることと、入られたあと中で広がる動きを見ることの両方に、IDS の出番がある。ただし、これは感染経路の統計で、IDS があれば防げたと言える数字ではない。

基準の中での位置も確かめた。CIS Controls v8.1 の Control 13 は、ネットワークの監視と防御の項目だ。侵入検知はホスト型（13.2）とネットワーク型（13.3）、侵入防止は 13.7 と 13.8 と、別々に置いている。13.3 は、最低限の対策の次の段階（実装グループ2）に入っている[11]。NIST の Cybersecurity Framework 2.0 では、検知（DE）が2つに分かれている。継続的な監視（DE.CM）と、見つけたものの分析（DE.AE）だ[18]。見張ることと、見つけたものを分析して判断することが、別の項目として並んでいる。

無料で使える IDS は、Suricata・Snort 3・Zeek と、ホスト型の Wazuh・OSSEC だった

ここからは製品を見る。版や日付は、2026年11月4日時点で、公式の発表を検索で確かめたものだ。古くなりやすいので、使う前に公式のページを見てほしい。

無料で使える主な IDS（2026年11月4日時点）
名前見る場所と方式止めるか向いている使い方
Suricata 8ネットワーク。シグネチャとプロトコル解析IPS モードで止められる検知も遮断も一つで。記録を SIEM に流したいとき
Snort 3ネットワーク。シグネチャが中心IPS として使えるTalos のルールに合わせたいとき。Snort 2 からの移行

表の「止めるか」は、置き方と設定によって変わる。ネットワーク型の道具でも、通信のコピーを受け取る置き方なら知らせることしかできない。

Suricata：検知も遮断も一つでできる

Suricata は、OISF（Open Information Security Foundation）が作るネットワーク型の IDS/IPS で、ライセンスは GPL v2 だ。8系の最初の版 8.0.0 は2025年7月に出た[19]。シグネチャ（ルール）での検知に加えて、通信のプロトコルを解析し、その結果を EVE JSON という1行1件の JSON で記録する。SIEM に流しやすい形だ。

遮断もできる。Linux では、NFQUEUE（通信を Suricata に回す仕組み）を使う。または、2枚の NIC（ネットワークにつなぐ部品）を橋渡しする AF_PACKET の IPS モードを使う。IPS モードのときだけ、drop のルールで実際に通信が落ちる[20]。2026年9月の 8.0.7 は、AI を使った解析によるものとして、これまでで最も多い脆弱性の報告を直した版だった[21]。守る道具そのものも、更新し続けるものだ。

ルールは、何を見つけたら、どう扱うかを1行で書いたものだ。考え方を見るために、演習用の例を一つ置く。自分の環境で、example.com という名前を DNS で引いたら知らせる、というだけのルールだ。

alert dns any any -> any any (msg:"演習: example.com の名前を引いた"; dns.query; content:"example.com"; nocase; sid:1000001; rev:1;)

先頭の alert が扱い方（知らせる）、dns が見るプロトコル、any any -> any any が送り元と宛先（どこでも）、かっこの中が条件と記録の文言だ。sid はルールの番号で、自分で作るルールには、配布されるルールとぶつからない番号を使う。IPS モードでは、先頭を drop にすると止める扱いになる。この1行は書き方の例で、僕はまだ自分の環境で動かして確かめていない。書き方の細部は、使う版の Suricata の文書で確かめてほしい。

暗号化された通信では、中身の代わりに、JA3・JA4 と呼ばれる「話し方の指紋」（TLS ＝ 通信を暗号化する決まりの、始めのあいさつの特徴）を記録できる[22]。

Snort 3：Snort 2 は終わった

Snort は、Cisco の Talos が作る IDS/IPS で、エンジンは GPL v2 だ。2026年10月21日、オープンソースの Snort 2 は、すべての版のサポートが終わった。Talos も Snort 2 向けのルールを出さなくなり、設定を Snort 3 の書き方に変える snort2lua という道具を案内している[6]。古い解説記事の多くは Snort 2 が前提なので、これから学ぶなら Snort 3 から始めるのがよさそうだ。

Snort 3 は、1つのプロセスでいくつものスレッドを動かせ、設定は Lua というプログラムの言葉で書く。Snort 2 の設定はそのままでは動かない[23]。ルールは、無料で登録も要らない Community、無料の登録で使える Registered、有料の Subscriber の3つがある。Registered の新しいルールは、Subscriber より30日遅れて届くと説明されている。2014年の説明で、いまも同じかは確かめていない[24]。Suricata と Snort には、Proofpoint の ET Open（無料）と ET Pro（有料）のルールもある。ET Pro は ET Open を丸ごと含むので、同時には入れない[25]。

Zeek：記録して、あとから調べる

Zeek（旧名 Bro）は、通信をプロトコルごとのログ（接続・DNS・HTTP・TLS など）に書き出し、専用のスクリプトで監視の方針を書く道具だ。公式の説明は、よくある IDS とはまったく違い、特定の検知の方式に縛られないとしている。ライセンスは BSD だ[26]。2026年9月に 9.0.0（長期サポートの版）が出て[27]、10月には 8.0.11 と 9.0.1 が「これまでで最大のセキュリティリリース」として出た[28]。

TLS のやりとりは ssl.log に、証明書は x509.log に残る。ただし TLS 1.3 では証明書が暗号化されるので、x509.log は出ない[5]。何が起きたかを細かく残すのが得意だ。Security Onion や Corelight は、Zeek と Suricata を組み合わせている[29][30]。

Security Onion：まとめて試せる配布

Security Onion は、Suricata・Zeek・Elastic（検索と可視化）をまとめて入れられる配布だ。2026年3月に 3.0.0 が出て、パケットの保存も Suricata が担うようになった。対応する OS は Oracle Linux 9 だけだ[29]。2.4 系は2026年10月1日でサポートが終わった[31]。これも、古い手順書に注意が要る。

Wazuh と OSSEC：機械の中を見る

ホスト型の代表が Wazuh と OSSEC だ。どちらも、サーバーや PC のログを分析し、ファイルの改ざんを見つける。変化を見つけたときに、その機械でスクリプトを動かして対処する active response の仕組みもある[32][33]。ネットワーク型と、見る場所が違う。どちらか一つではなく、組み合わせるものだ。

商用の多くは次世代ファイアウォールの機能で、NDR は内側の通信の振る舞いを見る

商用の製品は、大きく3つに分かれた。次世代ファイアウォール（NGFW）の中の IPS、専用の IPS、NDR だ。ここに書く性能の数字は、すべてメーカーの発表で、第三者が確かめたものではない。

次世代ファイアウォールの IPS は、境目に置く機器の機能の一つだ。Cisco Secure Firewall は Snort 3 のエンジンを使う。復号せずに通信の特徴から脅威を見分ける、Encrypted Visibility Engine も持つ[34]。Palo Alto Networks の Advanced Threat Prevention は、シグネチャに、通り道での深層学習を足した追加のサブスクリプションだ。メーカーの発表では、従来の IPS より、ゼロデイ（直し方がまだ出ていない弱点）を狙うインジェクション攻撃を60%多く防ぐ[35]。インジェクション攻撃は、入力に命令を混ぜて相手に実行させる攻撃だ。Fortinet の FortiGate は、通信を復号するディープインスペクションで中身を IPS に見せる。証明書だけを見る方式では、中身が要る IPS は働かないと説明している[36][37]。Check Point は、HTTPS Inspection で復号してから検査する[38]。

専用の IPS では、Trend Micro の TippingPoint がある。Digital Vaccine と呼ぶフィルターを配り、脆弱性を狙う通信を止める「仮想パッチ」が中心だ[39]。

NDR は、ミラーポート（スイッチが通信のコピーを出す口）やタップ（回線から通信のコピーを取り出す機器）から通信のコピーを受け取り、内側の通信の振る舞いを見る。Darktrace は、組織ごとの「ふだん」を学び、そこからのずれを見つけると説明している[40]。Vectra AI は、通信のメタデータ（宛先・時刻・量など、中身以外の情報）と、Active Directory などの ID の動きから攻撃者の振る舞いを見る[41]。ExtraHop の RevealX は、TLS 1.3 を含めて通信を復号できる、とメーカーは説明している[42]。Corelight は、オープンソースの Zeek と Suricata を土台にした NDR だ[30]。

暗号化された通信の扱いは、3通りに分かれた。復号して中身を見る（NGFW の検査、ExtraHop）。復号せずに通信の特徴で見る（Cisco の Encrypted Visibility Engine、Corelight、Vectra、Darktrace）。中身は見えない（Google Cloud IDS）[4]。復号するには、検査する機器の証明書を端末に信頼させる手間と、処理の重さがついてくる[36][43]。

クラウドでは、止められるものと、知らせるだけのものがあった

クラウドの主な3つは、置き方が違った。

クラウドの IDS/IPS（2026年11月4日時点。公式の資料を検索で確認）
サービス止めるか検知のもと暗号化料金の形
AWS Network Firewall止められる（警告だけにもできる）Suricata 互換のルールと、AWS が管理するルールTLS インスペクションで復号できる時間＋処理した量

AWS Network Firewall は、Suricata 互換のルールで止められる。TLS インスペクションでは、証明書を AWS Certificate Manager で用意する[44]。公式の料金のページでは、米国東部で、1時間あたり0.395ドルと、処理した1GBあたり0.065ドルだった。TLS インスペクションを使うと、時間あたりの料金が加わる[45]。Google Cloud IDS は、通信のコピーを調べて知らせるだけで、料金のページでは1時間あたり1.50ドルと、検査した1GBあたり0.07ドルだった[46]。Azure Firewall Premium は、シグネチャごとに「無効」「警告」「警告して拒否」を選べる[43]。値段は変わりやすく、地域でも違うので、使う前に料金のページで確かめてほしい。

第三者の評価は版によって変わり、Gartner の Leader は性能の試験ではなかった

製品を比べるとき、第三者の評価は役に立つ。ただ、読み方には注意が要る。

CyberRatings.org の2025年のエンタープライズ・ファイアウォールの比較試験では、7製品のうち3つが「Recommended」だった[7]。Fortinet と Palo Alto Networks の2製品は、IP や TCP の回避の手口で抜けられて「Caution」だった。そのあと、直した版で再試験し、「Recommended」に上がった[8]。試験の結果は、試した版に結びついている。そして、回避の手口に弱いと、シグネチャがあっても抜けられる。

Gartner の Magic Quadrant は、ベンダーを「実行能力」と「ビジョンの完全性」の2軸に置くもので、検知率を測る試験ではない。2025年の Hybrid Mesh Firewall の Leaders は、Check Point・Fortinet・Palo Alto Networks だった[9]。初めての NDR の Leaders は、Vectra AI・Darktrace・ExtraHop・Corelight だった[47]。どちらも、名前が挙がったことを、そのまま検知の強さと読まないほうがいい。

選ぶときに見るのは、置き場所・止めるか・暗号化・処理能力・ルール・連携・人手だった

調べたことから、選ぶときの問いを7つに絞った。製品のカタログを開く前に、紙に書いて答えておくと迷いにくい。

  1. どこを見たいか：境目を通る通信か、内側どうしの通信か、機械の中か。Security Onion の文書は、通信を取り出すのにスイッチのミラーポートか専用のタップ（TAP）を使い、できればタップを勧めている。NAT（社内のアドレスを外向けの一つのアドレスに置き換える仕組み）がある環境では、本当の社内のアドレスが見えるように内側で取るとしている[48]
  2. 止めたいのか、知らせてほしいのか：止めるなら通り道に入る置き方になり、誤って止めたときの影響も背負う
  3. 暗号化された通信をどうするか：復号するか、特徴だけで見るか、端末の記録で埋めるか[10]
  4. どれだけの量を流すか：カタログの処理能力は、機能を全部有効にすると下がることがある。Corelight の発表では、AP 620 という機器は、通信の分析だけなら最大10Gbps、Zeek・Suricata・パケットの保存を全部使うと最大5Gbpsだ[49]
  5. ルールや脅威の情報は、どこから、どれくらいの遅れで届くか：無料のルールは遅れがあるものもある[24]
  6. 警告をどこに集めるか：EVE JSON のような形で SIEM に流せるか
  7. 誰が、いつ、警告を読むか：これに答えられないなら、製品を選ぶ前に決めることがある

費用の見方にも、気をつけるところがある。無料の道具は、ソフトの代金はかからない。その代わり、機器を用意し、更新を当て、ルールを調整し、警告を読む人の時間がかかる。商用の製品は、機器やサブスクリプションの代金がかかる。その代わり、ルールや脅威の情報の更新は、メーカーが用意する。どちらが安いかは、環境と、使える人手で変わる。カタログの値段だけで比べると、置いたあとの手間を見落とす。

もう一つは、試してから決めることだ。管理者として許可を得た範囲で、自分の環境の通信を保存しておく。それを候補の道具に読ませると、どれだけ知らせてきて、そのうちどれだけが本当に気にすべきものかが分かる。後で書く Security Onion の Import の構成は、この試し方に使える[50]。

運用で見るのは、取りこぼし・誤検知の調整・警告を読む人だった

置いたあとにも、見るところがある。一つ目は取りこぼしだ。Security Onion は、Zeek が報告する取りこぼしの割合を画面に出す。値が高いほど、見えていない通信が多い。Zeek に取りこぼしがあるのにパケットの欠落がないときは、手前のタップやミラーポートで落ちている可能性が高いとしている[51]。

二つ目は、いきなり止めない段取りだ。IPA の制御システム向けの手引書は、導入を「導入検討 → 構築 → 試験運用 → 本格運用」の4段階に分けている[14]。制御システム向けの文書だが、試験運用で誤検知を見てから本番に移る考え方は、ほかの環境でも使える。

三つ目は、警告を読む人だ。NIST の CSF 2.0 は、見張ること（DE.CM）と、見つけたものを分析して判断すること（DE.AE）を、別の項目として並べていた[18]。警告が多すぎて読まれなければ、IDS はないのに近くなると僕は思う。ルールの調整は、置いたあとにずっと続く仕事だ。

学ぶなら、自分の PC の仮想環境と公開された PCAP から始められる

手を動かして学ぶ入口もある。試すのは、自分の機械と、許可された演習の環境の中だけにしてほしい。人のネットワークを許可なく監視したり、調べたりすることはしない。

僕が調べた中でいちばん軽そうだったのは、自分の PC の仮想環境に Security Onion を入れる始め方だ。保存した通信（PCAP）を読み込むだけの Import という構成は、2コア・メモリ4GB・ディスク100GB・NIC 1枚が最低限とされている[50]。

読み込む通信は、公開された練習用の PCAP が使える。Brad Duncan が運営する malware-traffic-analysis.net には、分析の練習問題と PCAP がある。ただし本人が書いているとおり、PCAP の中に本物のマルウェアが入っていることがあり、取り出して動かすと感染しうる。本人は、Linux や macOS などで見ることを勧めている[52]。僕は、ネットにつながない仮想環境で、ファイルを取り出さずに読むことにしている。

決まった道筋で学ぶなら、TryHackMe の Snort の部屋がある。IDS/IPS の概要からルールの書き方までを扱う[53]。Hack The Box Academy の Working with IDS/IPS は、Suricata・Snort・Zeek を扱う[54]。

学ぶうちに、製品や公開されているサービスの弱点に気づくことがあるかもしれない。そのときは公開せず、作った会社か、IPA の届け出の窓口に知らせる。

IDS は、どこを見るかと、誰が読むかを決めて初めて働く道具だった

調べて分かったことをまとめる。IDS は見つけて知らせる仕組みで、止めるのは IPS だ。その違いは、製品の名前より置き方で決まる。侵入に自分で気づけた組織は52%で、外から知らされて気づく組織もまだ多い。無料の道具では Suricata・Snort 3・Zeek が中心で、Snort 2 と Security Onion 2.4 は2026年にサポートが終わった。商用は次世代ファイアウォールの IPS と NDR に分かれ、暗号化された通信の扱いが製品ごとに大きく違った。第三者の評価は版に結びつき、Gartner の Leader は性能の試験ではなかった。

分かっていないこともある。この記事の事実は、公式の資料を検索で確かめたもので、原典のページを一つずつ開いて確かめ直している途中だ。版・料金・提供の状況は変わりやすく、日本で使えるかどうか（地域や販売）は、ほとんどの製品で確かめられていない。製品の検知の強さを、同じ条件で比べた公開の試験も、ここではファイアウォールの試験しか見つけられなかった。

この記事の下書きと資料の照らし合わせには AI を使った。公開の前に、ムートンが全文を読む決まりにしている。特定の製品を勧めるものではない。選ぶのは、自分の環境を知っている人だ。

自分の環境で、IDS の警告を最初に読むのは誰で、それはいつだろうか。
